# graft-ops — map
One line per public item. Update when a public item changes.

`graft-ops`: operations, the undo journal, Mistake Radar detection and Ghost Preview planning. Depends on `graft-git` and `graft-core` only (plus `serde`/`serde_json` for the journal file); `graft-fixtures` as a dev-dependency. **Seam rule:** `ops` decides, `app` wires — `app` never builds a `GitInvocation` for a write, never touches the journal file, never chooses a snapshot.

## operation
- `Operation` (enum) — one write, four properties (`kind`, `describe`, `check`, `plan`, `touches`; the inverse is `undo::inverse` from the journal entry): `Stage(Target)`, `Unstage(Target)`, `Discard(Target)`, `Commit(CommitParams)`, `Amend(CommitParams)`, `StashPush(StashParams)`, `StashApply { index, commit }`, `StashPop { index, commit }`, `StashDrop { index, commit }` (m3/02), `Fetch(FetchParams)`, `Pull(PullParams)`, `Push(PushParams)` (m4/04), `Merge(MergeParams)`, `Rebase(RebaseParams)`, `CherryPick(PickParams)`, `Revert(RevertParams)`, `Reset(ResetParams)`, `Checkout(CheckoutParams)`, `BranchCreate(BranchCreateParams)`, `BranchDelete(RefDeleteParams)`, `TagCreate(TagCreateParams)`, `TagDelete(RefDeleteParams)`, `BranchFromStash(BranchFromStashParams)` (m5/07), `ResolveWholeFile(ResolveWholeParams)`, `RestartConflict(RestartParams)` (m6-conflicts/03), `FinishMerge(FinishMergeParams)` (m6-conflicts/20), `AbortMerge(AbortMergeParams)` (m6-conflicts/57), `DropPutBack { stash: Oid, why: PutBackWhy }` (m6-conflicts/72; `why` m7/24-0), `Rewrite(RewriteParams)` (m7/02b: `rewrite <branch>` / `put staged changes into <short>`; `check` = `HEAD` on his branch at the planned tip, every line tip unmoved, `validate`; `plan` = `git rebase -i … <onto> [<top>]`; `touches` = the line's refs, index, worktree; sets edits aside like `Rebase`). `Rebase`'s plan is `git rebase -i [--no-update-refs --no-autostash --empty=drop] <onto> [<top>]` (the three flags on git ≥ 2.38; `<top>` when its line has 2+ branches, m7/05b), run by `apply::engine`.
- `Operation::DropPutBack { stash, why }` (m6-conflicts/72, ADR-0045 §3; `why` m7/24-0, the clash's `PutBackWhy`, built by graft's `resolver::close_after_last`) — finishing a pop or set-aside clash: `stash drop stash@{n}`, `n` looked up by commit in `facts.stashes` (`stash::position_of`), never assumed; `check` refuses `NoSuchStash` when it is gone (no longer listed, or past `read`'s 50-entry cap). Kind `StashDrop`, `pins: [stash]`, touches `{[refs/stash]}` — so the existing `StashStore` inverse brings it back on `u`. `describe` `drop stash <short id>` (`SetAside`: `drop the set-aside copy (<short id>)`). Plan fallback if the facts somehow lack it: `stash drop <commit hex>`, which git refuses loudly (never a guessed position).
- `Side` (enum) — `Ours` (stage 2) / `Theirs` (stage 3); `word()` (m6-conflicts/03).
- `ResolveWholeParams` (struct) — `path`, `side`, `how: UnmergedHow`: one conflicted path resolved whole. `check` refuses `NotUnmerged` when the status does not call the path unmerged **or** when `how` is not the shape it reads now — the side chosen may not exist in the shape it became. **The table, verified against git 2.54.0 (Apple Git-157), 2026-09-22, one path per shape in a throwaway stopped merge; every row exits 0 and empties `ls-files -u` for that path:** `BothModified`/`BothAdded`, either side → `checkout --ours|--theirs` then `add` (index and working tree both become that stage's blob); `DeletedByThem`+`Ours`, `DeletedByUs`+`Theirs`, `AddedByUs`+`Ours`, `AddedByThem`+`Theirs` → `add` alone, because the side's bytes are already on disk — **`DeletedByUs` confirmed: git leaves theirs' bytes in the working tree**, so `add` stages stage 3; the other side of each of those four → `rm --quiet`; `BothDeleted`, either side → `rm --quiet`, which **exits 0 although no file is on disk** — the index entry is what it removes. `rm` needs no `-f`: an unmerged entry is not "staged content" to its safety check. Every path `--literal-pathspecs` (m6-conflicts/03).
- `RestartParams` (struct) — `path`, `kind: RestartKind` (m6-conflicts/58: the gate's answer, sent back by the app). `plan_restart` runs `checkout <kind.checkout_flag()> -- <path>`: `--merge` for `Markers` (the conflict back from stages 1–3), `--ours`/`--theirs` for `WholeFile` (the surviving side written back after `run_restart_prep` restored the stages). Every path — the folded step (`apply::fold::inside_live_operation`, `op.plan(facts)`) and the entry of its own (`apply.rs`, `op.plan(&facts)`) — reads this one plan. `checkout --merge` itself only merges `UU`/`AA` (measured, git 2.54.0: `UD`, `DU`, `AU`, `UA`, `DD` exit 1 `does not have all necessary versions`). The gate is asked in **two places**, because `check` is pure over `RepoFacts`: `check_restart` decides for a path the status calls unmerged (`has_markers` or `NotMarkerShape` — a still-unmerged one-sided file has nothing chosen to start over), and **admits** one it does not, leaving `apply::prepare_restart` to ask `restart_source` of the stages it finds.
- `RestartKind` (enum) / `OneSided` (enum) — m6-conflicts/58. `RestartKind::{Markers, WholeFile { shape: OneSided }}`, `checkout_flag() -> &'static str` (`--merge`; `--ours` for `UD`/`AU`, stage 2 survives; `--theirs` for `DU`/`UA`, stage 3): the one source the plan and the app's box both read. `OneSided::{DeletedByThem, DeletedByUs, AddedByUs, AddedByThem}` — exactly the four one-sided shapes, so `DD` cannot be written; `from_how(UnmergedHow) -> Option<Self>` (`None` for `UU`, `AA`, `DD`), `how()`.
- `FinishMergeParams` (struct) — `merge_head: Oid` (what `MERGE_HEAD` named when the user asked), `message: Option<Vec<u8>>` (`None` = git's `MERGE_MSG`): finishing a merge **begun in the shell** as its own entry (m6-conflicts/20). `check`: git merging, else `NotInProgress` (unmerged paths are refused first, `Unmerged`); the rest of its check needs reads and is `apply`'s. `plan`: `merge --continue`, or `commit --cleanup=whitespace -F -` with the message on the `Invocation`'s stdin (which already existed; `GIT_EDITOR=true` from the plan runner). `touches` `{[branch | HEAD], index, worktree}`. `describe` `finish merge of <short id>`, overridden by `apply` with `finish::merged_from`'s name. Never folds, `opens_in_progress` → `None`.
- `shape_of_stages` (fn, crate-private) — the `UnmergedHow` a set of `snapshot::StageEntry`s spells, the inverse of git's `XY` pair: 1+2+3 `UU`, 2+3 `AA`, 1+2 `UD`, 1+3 `DU`, 2 `AU`, 3 `UA`, 1 `DD`, none `None`. The only way to apply the marker gate to stages read out of a recorded tree (m6-conflicts/08).
- `FetchParams` (struct) — `remote: Option<String>` (`None` = `--all`), `prune` (m4/04).
- `PullParams` (struct) — `branch`, `upstream: TrackedUpstream` (the app's copy; `check` refuses `UpstreamChanged` when the facts disagree) (m4/04).
- `PushParams` (struct) — `branch`, `remote`, `remote_branch` (full `refs/heads/x`), `set_upstream` (`-u`), `lease: Option<Lease>` (m4/04), `source_commit: Option<Oid>` — a guided re-push: the refspec's source is that commit rather than the branch, `describe` names it, `check` refuses `RepushNeedsLease` without a lease, and `preview::plan` refuses `NotOnBranch` unless it is an ancestor of the branch (m5/07, ADR-0038 §4).
- `Lease` (struct) — `expected: Oid`: `--force-with-lease=<remote_branch>:<expected>`. No force without a lease exists (m4/04). `check` refuses `LeaseStale` unless `expected` is the fetched tracking tip; `--force-if-includes` dropped — git makes it a no-op beside an explicit expect (m4/04 review M1).
- `RemoteNames` (struct) — `local` (`main`), `remote_side` (`origin/main`), `remote` (`origin`): the names a remote failure line uses, taken from the params, never parsed back out of the description (m4/04 review M4).
- `Operation::remote_names` (fn) — `Some(RemoteNames)` for fetch/pull/push, `None` for a local operation (m4/04 review M4).
- `Operation::is_remote` (fn) — fetch, pull or push; the executor streams their stderr and refreshes `Everything` (m4/04).
- `Operation::preview` (fn) — a remote operation's command lines before any facts are read, equal to `plan`'s; `None` for a local one (m4/04).
- `Target` (enum) — `Paths(Vec<PathBuf>)` or `Patch { path, patch, side }` (one hunk or selected lines from `diff::hunk_patch`; its `PatchDirection` and `plan`'s `-R` are one choice — `Forward` for stage, `Reverse` for unstage/discard) (m3/02, side added in the review fix).
- `PatchSide` (enum) — which diff a hunk was cut from: `Worktree` (unstaged diff; stage takes it, discard reverses it in the working tree) or `Index` (staged diff; unstage takes it, discard reverses it in the working tree then the index) (m3/02 review fix, M4).
- `CommitParams` (struct) — `message`, `sign_off`, `no_verify`, `allow_empty` (m3/02).
- `StashParams` (struct) — `message`, `scope: StashScope`; `Default` (m3/02).
- `StashScope` (enum) — `All { include_untracked }` (`-u` when true; the default) or `StagedOnly` (`--staged`); git refuses `--staged` with `-u`, so the pair is unrepresentable (m3/02 review fix, M6).
- `Invocation` (struct) — `args: Vec<GitArg>`, `stdin: Option<Vec<u8>>`, `remote: bool` (talks to a remote: progress + askpass; a pull's `merge --ff-only` is `false`, m4/04); `command_line` (fn) via `graft_git::run::command_line` (m3/02).
- `Tip` (struct) — `name` (full ref) + `oid`: what a history operation was aimed at. `check` refuses `Moved { name }` when the repository disagrees, which is how a preview and the operation it drew stay the same act (m5/07, design note hard choice 3).
- `Operation::tips` (fn) — every `Tip` an operation is pinned to, for the caller that re-checks a drawn preview before confirming (m5/07).
- `Operation::is_history` (fn) — true for the eleven m5/07 kinds, a fixed list: the ones whose refresh is always `Everything` (m5/07).
- `SetAside` (struct, m6-conflicts/73) — `files`: the changed tracked files a rebase or checkout will set aside and put back (ADR-0045 §4); `staged` removed in m7-power-tools/30c (it was always 0 since 30): every put-back keeps the index (ADR-0045 amendment 2026-09-26 b); when git cannot reinstate it the after-state says so (`AfterState::StagingNotKept`), which the preview does not forecast. `Operation::sets_aside(facts)` (fn) → `Some` for `Rebase`/`Rewrite`/`CherryPick` (the pick: m7-power-tools/11a, any changed tracked file, not only the paths it touches), a `Checkout` with `OnEdits::SetAside`, and a switching `BranchCreate` with `SetAside` away from `HEAD`'s commit (m7-power-tools/10b), over changed tracked files, and a `Pull` (m7-power-tools/03b) only when `RepoFacts::incoming` says fast-forward and its paths meet a changed tracked file (a rename's original path counts; then all changed tracked files are set aside); `None` otherwise (untracked files are never set aside). When `Some`, `touches` also names `refs/stash` (Pull included).
- `Operation::starts_in_progress` (fn) — `Some(InProgress)` for merge, rebase, cherry-pick and revert: what git's state would say if this one stopped on a conflict (m5/07). One table, the crate-private `operation::opens_in_progress(kind)`, asked two ways: here for an operation about to run, and by `apply::resume::live_entry` for a journal entry already written (m5/07 review fix, M11).
- `FactsScope` (struct) — `remotes: bool` + `refs: Vec<String>`: what `read_facts` must answer for this operation. What `check` reads, and since m5/07 what `preview::plan` needs too — a branch-from-stash names `HEAD` because the preview reaches the stash commit by asking for what is on it and not on `HEAD`; a push names its branch so a re-push can prove its commit is on it (m5/07).
- `Source` (enum) — `Branch(String)` or `Commit(Oid)`: what a merge or rebase names on the command line (m5/07).
- `FastForward` (enum) — `Default`, `Only` (`--ff-only`), `Never` (`--no-ff`) (m5/07).
- `MergeParams` (struct) — `source: Source`, `into: Tip`, `source_tip: Oid` (what `source` resolved to when the preview was drawn), `ff` (m5/07).
- `RebaseParams` (struct) — `branch: Tip`, `onto: Source`, `onto_tip: Oid` (m5/07); `line: BranchLine` (his branch first, bottom up: every branch `y` moves) and `drops: Vec<Oid>` (rows the todo marks `drop`) (m7/05b), filled once by `preview::plan_as_run`. `RebaseParams::new(branch, onto, onto_tip)` — line = his branch alone, no drops; every graft site builds with it. `check` pins every branch of the line; `plan` names the top (`… <onto> <top>`) when the line has 2+.
- `PickParams` (struct) — `commits: Vec<Oid>` (in apply order), `subject` (the first one's, for the description), `head: Tip` (m5/07). `PickParams::check_commit(commit, on_head, parents) -> Result<(), Refusal>` (m7-power-tools/11a): `AlreadyOnBranch { commit, branch }` (`<sha7> is already on <branch>`) when `on_head` (HEAD or an ancestor), else `PickMerge { commit }` (`<sha7> is a merge · taking a merge isn't in Graft yet`) at 2+ parents; the caller holds the reads (`check` reads no object): `preview::plan` of a pick and `apply` (`guard_pick`, before the set-aside) both ask it from one `rev-list <commit> ^<head> -n1`.
- `RevertParams` (struct) — `commit`, `subject`, `mainline: Option<u8>` (`-m` for a merge), `parents` (how many the commit has), `parent: Option<Oid>` (its first parent — what the forecast diffs against, since the commit itself is already on `HEAD`), `head: Tip` (m5/07).
- `ResetParams` (struct) — `target: ResetTarget`, `to: Oid` (m5/07).
- `ResetTarget` (enum) — `Head { branch: Tip, mode: ResetMode }` (`git reset`, the working tree's business) or `Branch(Tip)` (`git branch -f`, a ref move that leaves the tree alone) (m5/07).
- `ResetMode` (enum) — `Soft`, `Mixed`, `Hard` (m5/07).
- `CheckoutParams` (struct) — `to: CheckoutTarget`, `head_before: HeadRef`, `on_edits: OnEdits` (m7-power-tools/10b). `touches` names **no** ref: `HEAD` is recorded by the entry's `head_before`/`head_after` and put back by `SetHead`, because an `UpdateRef` on a symbolic `HEAD` moves the branch under it (m5/07).
- `CheckoutTarget` (enum) — `Branch(String)` or `Detached(Oid)` (m5/07), or `Track { remote: Tip, local: String }` (m7-power-tools/10b): a remote-only branch checked out as a new local one. Plan, measured on git 2.54 with `branch.autoSetupMerge=false`: `git switch --create <local> --track <refs/remotes/…>` — the explicit `--track` sets `branch.<local>.remote`/`.merge` whatever the config says. `check`: `RefExists` when `local` exists, `NoSuchRef` when the remote ref is gone, `Moved` when it moved since the list. `touches` = `refs/heads/<local>` (so `u` deletes it; `branch.<local>.*` config stays). `describe` = `checkout <local> (new, tracks origin/x)`.
- `OnEdits` (enum, m7-power-tools/10b) — `Refuse` or `SetAside`: what a switch (`Checkout`, a switching `BranchCreate`) does over changed tracked files. `Refuse` → `check` refuses `DirtyTree` (the app's instant switch, which answers that refusal with the preview); `SetAside` → `sets_aside` is `Some` (the previewed switch, ADR-0045 §4).
- `BranchCreateParams` (struct) — `name` (short), `at`, `checkout` (m5/07), `on_edits: OnEdits` (m7-power-tools/10b; read only when `checkout`). A switching create at `HEAD`'s own commit never sets aside and never refuses dirty (`switch -c` leaves index and files as they are; the preview's `WorktreeEffect::EditsStay`); elsewhere `SetAside` sets aside and puts back, `Refuse` refuses `DirtyTree`.
- `RefDeleteParams` (struct) — `name` (full ref), `expected`: `check` refuses a ref that moved since, so it is not lost (m5/07). A tag's delete is `update-ref -d <name> <expected>` (compare-and-swap); a branch's is `branch -D <b>`, which takes its `branch.<b>.*` config with it, recorded before and after so `u` writes it back (review m7-09..21c Minor 13).
- `TagCreateParams` (struct) — `name` (short), `at`, `message: Option<String>` (`Some` = annotated, `-F -`) (m5/07).
- `BranchFromStashParams` (struct) — `name` (short), `index` (`stash@{n}`), `commit`: `git stash branch` starts the branch at the stash's base, which is why it cannot conflict (m5/07).
- `RepoFacts` (struct) — `bare`, `head: HeadRef`, `in_progress`, `status: WorkingTreeStatus`, `stashes: Vec<StashEntry>`, `git: GitVersion`, `remotes: Vec<Remote>`, `upstream: Option<TrackedUpstream>` (of `HEAD`'s branch; `None` detached/unborn/none set, m4/04; both read only for a remote operation, empty/`None` otherwise, review M2); read once before `check`/`plan`/`touches` (m3/02). `incoming: Option<Incoming>` (m7-power-tools/03b): `None` from `read_facts`; `apply` fills it for a pull after its fetch, only over changed tracked files. `edit_stop: Option<EditStop>` (m7-power-tools/07a): `read_facts` fills it mid-rebase only (`rewrite::edit_stop`); `None` outside a rebase and at a conflict stop.
- `Incoming` (struct, m7-power-tools/03b) — `tip: Oid` (the tracking ref after the fetch), `fast_forward: bool` (`HEAD` an ancestor of `tip`), `paths: Vec<PathBuf>` (`diff --name-only --no-renames HEAD tip`; empty when not a fast-forward).
- `Refusal` (enum), m6-conflicts/03 additions — `NotUnmerged { path }` (`<path> is not conflicted`), `ConflictsOpen { path, open }` (`<n> conflicts still open in <path>`, `1 conflict …` at one, m6-conflicts/46), `NotMarkerShape { path, how }` (`<path>: <how> — no markers to take from`), `NoStagesKept { path }` (`<path>: the conflict's sides were not kept`, m6-conflicts/08: `d` on a path no longer unmerged whose sides no recorded stage tree holds — bare `checkout --merge` there exits 0 and silently does nothing). `RestartChanged { path }` (`<path> changed since it was opened · open it again`, m6-conflicts/58): the `RestartParams.kind` sent is not what the recovered stages spell now — the stale-gate backstop, refused before anything is written. Their words are in `explain()` with every other refusal's; the group spec called the method `words()`, which does not exist on `Refusal`. `MessageNotHere { kind }` (m6-conflicts/09): `Resume::ContinueWith` on a rebase, cherry-pick or revert. `OctopusMerge { heads, end: MergeEnd }` (m6-conflicts/38; `end` m6-conflicts/57): `c` or `a` on an octopus merge begun in the shell — `this merges <n> branches at once (an octopus merge); <end.in_the_shell()>`. `AutostashWaits { end: MergeEnd }` (m6-conflicts/57): `c` or `a` while `MERGE_AUTOSTASH` exists (was `NotInProgress` for `c`) — `git set your changes aside for this merge (autostash); <end.in_the_shell()>`.
- `MergeEnd` (enum, m6-conflicts/57) — `Finish`, `Abort`: which end of a shell-begun merge a refusal is about; `in_the_shell()` → `finish it in the shell: git commit` / `abort it in the shell: git merge --abort`.
- `AbortMergeParams` (struct, m6-conflicts/57) — `merge_head: Oid`. `Operation::AbortMerge`: aborting a merge **begun in the shell** as its own entry, `git merge --abort` with a `Full` backup, so `u` puts the merge back (stages, hand edits, `MERGE_HEAD`/`MSG`/`MODE`; not `MERGE_RR` or `AUTO_MERGE`). `check` as `FinishMerge`'s but exempt from `Unmerged`; `touches` `{[branch | HEAD], index, worktree}`; `describe` `abort merge of <short id>`, overridden by `apply` with the branch name. Never folds. Kind `OperationKind::AbortMerge` (graft-core, `abort_merge` in the journal; `kind_name` `abort merge`).
- `Refusal` (enum) — `Bare`, `InProgress(InProgress)`, `Unmerged { paths }` (words since m6-conflicts/72: `<path> still has conflicts · resolve it first`, `<path> +N …` when more; no shell, no milestone), `PathNotInState { path }`, `PatchPathMismatch`, `PatchSideMismatch`, `NothingStaged`, `EmptySubject`, `UnbornHead` (amend or stash push before the first commit), `NothingToStash`, `NeedsGit { feature, minimum }`, `NoSuchStash`, `StashListChanged`, `TouchesChangedFiles { paths }`, `DetachedHead`, `NoRemote`, `NoSuchRemote { name }`, `NoUpstream { branch }`, `UpstreamChanged`, `BranchChanged` (m4/04), `HeadUnborn` (30n: `head_is` on an orphan branch — `HEAD has no commit yet · c makes the first one`; was `BranchChanged`, which was false), `LeaseStale { remote_side }` (m4/04 review M1), `Moved { name }` (a pinned tip moved since the preview), `DirtyTree { count }` (a new branch switched to, or a branch from a stash, over changed tracked files — never `--autostash`; since m6-conflicts/73 a rebase or checkout sets the edits aside instead of refusing), `MarkersRemain { path }` (staging a file that still has `<<<<<<< ` in it), `BadRefName { name, rule }`, `RefExists { name }`, `NotInProgress`, `NotOnBranch { commit, branch }`, `NotPreviewable(OperationKind)`, `CannotRevertTo(String)`, `RepushNeedsLease`, `MainlineOnNonMerge`, `NotFastForward { branch }` (m5/07), `StashInTheWay { unsaved, staged, untracked, ignored }` (m6-conflicts/86; sets apart since 87: `your unsaved edits to <a>` for tracked edits, `your staged edits to <b>` beside them, `<path> is in the way` for an untracked file, clauses joined by `and`; since m7/28c an ignored file reads `<path> (ignored)[ +N more] is|are in the way · move it|them aside first`, as `InTheWay` does), `StashIndexNoLongerApplies { index }` (87: the stash's staged part no longer applies to the index — git's `--index` refusal — `the staged part of stash@{n} no longer applies`); `explain` matches every variant itself, no re-entry (review Minor 7); `explain` (fn) is one actionable sentence, naming `continue_command`/`abort_command` for `InProgress` (m3/02).
- `Operation::check` (fn) — bare → unmerged → in-progress (stage/unstage allowed; **P14's exception**, m7-power-tools/07a: `Amend` allowed mid-rebase iff `facts.edit_stop` is `Some` with `head_on_it`; a commit on top, a conflict stop, merge/cherry-pick/revert still `InProgress`; the rest wait) → the kind's rules: paths must be in the state the op applies to (a patch needs a tracked file changed on its `side`, ADR-0034; stage takes a `Worktree` hunk and unstage an `Index` one, else `PatchSideMismatch`), patch headers must name the path, commit needs something staged (unless `allow_empty`) and a subject, amend needs a born `HEAD` and a subject (nothing staged = reword), stash push needs a born `HEAD`, something in its scope (`StagedOnly`: something staged) and git ≥ 2.35 for `--staged`, apply/pop/drop need the list unchanged (`index` still holds `commit`), apply/pop refuse when a stashed path is dirty now (m3/02). Fetch is allowed bare and mid-operation (unknown remote → `NoSuchRemote`, none → `NoRemote`); pull needs a branch, an upstream equal to its params'; push needs a branch equal to its params' and a known remote, and a lease's `expected` equal to `HEAD`'s upstream's `tracking_tip` for the pushed remote branch (else `LeaseStale`: fetched since, never fetched, or not the upstream; review M1). Nothing about ahead/behind — git decides (m4/04).
- `Operation::plan` (fn) — exact args, verified in a throwaway repo. Every command with paths is `git --literal-pathspecs …`: `*`, `?`, `[` and a leading `:` are pathspec magic even after `--` (a file named `a*b` would take `ab` with it). `add -- <paths>` / `apply --cached -` (stdin); `restore --staged -- <paths>` (`rm --cached --quiet` on an unborn head) / `apply --cached -R -`; discard one invocation per class: `restore --staged --worktree --source=HEAD -- <staged>` (also removes a staged new file, restores a rename), `restore --worktree -- <unstaged-only>`, `clean -f -- <untracked>` (unborn: `rm --cached --quiet` then `clean -f`); a `Worktree` hunk `apply -R -`, an `Index` hunk `apply -R -` then `apply --cached -R -` (working tree first: the step that can fail leaves nothing changed); `commit -F -` (+ `--amend`/`--signoff`/`--no-verify`/`--allow-empty`, message on stdin, never `-m`); `stash push [-u | --staged] [-m <msg>]`, `stash apply|pop --index stash@{n}`, `stash drop stash@{n}`; `fetch --progress [--prune] (--all | <remote>)`; pull = `fetch --progress <remote>` then `merge --ff-only --no-overwrite-ignore --no-edit <tracking ref>` (the flag since m7/28a, ADR-0049 §4: the fetch runs between Graft's read of files in the way and git's write); `push --progress [-u] [--force-with-lease=<rb>:<oid>] <remote> refs/heads/<b>:<rb>` (m4/04). A renamed entry's `original_path` joins the pathspec (m3/02).
- `Operation::plan`, the m5/07 history kinds — `merge --no-edit (--ff|--ff-only|--no-ff) -m <subject> <source>` (the fast-forward flag is **always** written, `--ff` included: `merge.ff=false` in the reader's config would otherwise turn the drawn fast-forward into a merge commit, m5/07 review fix M1); `rebase --no-update-refs --no-autostash <onto>` when git ≥ `GitVersion::MINIMUM` (`rebase.updateRefs=true` moves branches the entry never recorded, so undo could not put them back, review fix M2); `cherry-pick --no-edit <commit>`; `revert --no-edit [-m <n>] <commit>`; `reset --soft|--mixed|--hard <to>`; `update-ref <branch> <to> <expected>` (moving a branch that is not `HEAD`, and every delete); `switch [--detach] <target>`; `branch <name> <at>`; `tag [-a -F -] <name> <at>`; `stash branch <name> stash@{n}`. **The rule behind the flags**: a plan says what it means, so no config the reader happens to have set can make the preview a lie (m5/07, review fix).
- `Operation::moves_head` (fn, m7/03) — true when finishing the write moves `HEAD` (its ref or its commit): Commit, Amend, Merge, Rebase, Rewrite, CherryPick, Revert, Pull, Checkout, BranchFromStash, FinishMerge, `Reset` with `ResetTarget::Head`, `BranchCreate { checkout: true }`; false for every other kind, `Recover` included. Exhaustive match, no `_` arm. The app lands the graph cursor on the new `HEAD` after a `Done` for these.
- `Operation::touches` (fn) — stage/unstage `{[], index}`, discard `{[], index, worktree}`, commit/amend `{[branch full name | "HEAD"], index}`, stash push/apply/pop `{["refs/stash"], index, worktree}`, stash drop `{["refs/stash"]}` (m3/02); fetch `{}` (tracking refs never recorded), pull `{[branch], index, worktree}` (**not** the tracking ref: undo never moves one), push `{[upstream tracking ref if known]}` for the browser, never for undo (m4/04); rebase/checkout (and cherry-pick, m7-power-tools/11a) add `refs/stash` when `sets_aside` is `Some` (m6-conflicts/73).
- `Operation::describe_in` (fn, m6-conflicts/82 m6) — `(&self, &RepoFacts) -> String`: `DropPutBack` as `drop stash@{n}` (`SetAside`: `drop the set-aside copy (stash@{n})`, m7/24-0), `n` from the facts' stash list by commit; every other kind, or a stash not listed, `describe()`. `apply` records an entry's description through it.
- `Operation::describe` (fn) — `stage src/a.rs`, `stage 3 files`, `stage a hunk of src/a.rs`, `commit "<subject>"`, `amend "<subject>"`, `stash "<msg>"` / `stash the working tree`, `apply|pop|drop stash@{n}` (m3/02); `fetch all remotes`/`fetch origin`, `pull origin/main`, `push main → origin/main[ (set upstream)]`, `force-push main → origin/main (with lease)` (m4/04).
- `RecoverTarget` (enum, m7/22) — what `⏎` on a journal-list row puts back: `MoveRef { name, to, expected }` (a branch back to `to`, only if still at `expected`), `Recreate { name, at }` (a gone branch), `Files { entry, backup_tree, paths }` (a lost edit from an undo's backup). `RecoverParams` (struct) — `target`, `because` (the event's words, for the entry's description). `Operation::Recover` runs it (m7/23).
- `Operation::Recover(RecoverParams)` (m7/23) — kind `Recover`. `check`: `MoveRef` refuses `NoSuchRef` (gone), `HeldAgain` (already at `to`), `MovedOnSince` (not at `expected`); `Recreate` refuses `HeldAgain` (name at `at`), else `new_ref`'s `BadRefName`/`RefExists`; `Files` refuses only an empty path list (since m7/30o R1 it writes over his changes at its paths: the entry's before-snapshot keeps them, `u` brings them back; an **ignored** file at a path is refused `InTheWay` (`putting back your edit`) by `in_the_way`); a checked-out `MoveRef` over a file on disk (untracked or **ignored**) at a path `to` writes and the index does not track is refused `InTheWay` (`putting <b> back to <sha7>`) by the preview and by `apply` (since m7/28a; one read, `in_the_way::blocking`; review m7-22 C1). `plan`: `update-ref refs/heads/<b> <to> <expected>`, or `reset --hard <to>` when `HEAD` is on it (set aside around, ADR-0045 §4; `sets_aside` says so); `branch <name> <at>`; `--literal-pathspecs restore --source=<tree> --worktree -- <paths>`. `touches`: the branch (+ index, worktree, `refs/stash` when checked out and set aside); `Files` = worktree only. Pins `MoveRef.expected`. `describe`: `put <b> back to <sha7> (<because>)`, `made <b> again at <sha7> (<because>)`, `put back your edit to <path>[ +N more]`. `u` = the generic inverse, no code of its own.
- `FilesEffect` (enum, m7/23) — the preview's `your files:` line: `Unchanged { not_checked_out }` (`main isn't checked out`), `Changes { come_back, go, set_aside, replaced, still_staged }`; `replaced` (m7/30o) = a file put-back's paths changed against `HEAD` (staged, unstaged or untracked), written over and kept by the entry's snapshot (`what's in p now is replaced`); `still_staged` (m7/30p R2) = those of `replaced` whose index differs from `HEAD`, left staged because the put-back writes the worktree only (`p stays staged as you had it`); both empty for every other put-back.
- `Refusal::InTheWay { doing, ignored, untracked }` (m7/28a, ADR-0049) — files git doesn't keep where the write puts its own: `<path> (ignored) is in the way of <doing> · move it aside first`, `<path> (ignored) +N more are in the way of <doing> · move them aside first`; only untracked: `<path> is in the way of <doing> · S stashes it first` / `<path> +N more are … · S stashes them first`. `<path>` is the first ignored, else the first untracked; `+N` counts the rest of both. `<doing>` from `in_the_way::doing`.
- `NoPutBack` (enum, m7/22) — why a row has nothing for `⏎`: `Graft` (use revert-to), `Switch { back_to }`, `Created { name }`, `Nothing`.
- `Refusal`, m7/22 additions — `MovedOnSince { name, now }` (`<name> moved on since (now <sha7>)`), `HeldAgain { commit, by }` (`<sha7> is on <by> again · nothing to put back`), `NoPutBack(NoPutBack)` (its own words per variant).

## conflict
The resolver's job-side half (m6-conflicts/03): no `Operation`, no journal line. A block take is an fs write with no `git` command in it — a step inside the live `Pending` span, like a hand edit (design note hard choice 2). The whole-file shapes, which *are* `git` writes, go through `Operation::ResolveWholeFile`.
- `Opened` (struct) — `file: Option<ConflictFile>` (`None` for a whole-file shape and for a binary `UU`/`AA`), `how: UnmergedHow`, `binary`.
- `OpenError` (enum) — `Refused(Refusal)` (`NotUnmerged`), `Read(io::Error)`, `TooLarge { bytes }`, `Markers(ParseError)`.
- `open_conflict` (fn) — `(repo, status, path)`: refuses `NotUnmerged`; `how.has_markers()` and not binary → the parsed file; binary or a whole-file shape → `file: None`. Malformed markers surface as `Markers` **with their line**, never as "no conflicts here" — including `ParseErrorKind::MarkerSize` (a marker run of eight or more `<`), so an oversized-marker file never reaches the resolver as "nothing to resolve". Runs *shorter* than seven still parse clean and are missed here and by `MarkersRemain` (broken gap, M7).
- `TakeError` (enum) — `Changed { now: Oid }`, `NoSuchBlock(usize)`, `Write(WriteError)`.
- `DoneFile` (enum, child `done`) / `open_done` (fn) — m6-conflicts/25: reads a path that is **no longer** unmerged, read-only, for the resolver's done card. `open_done(repo, status, path) -> Result<DoneFile, OpenError>`: an unmerged path → `Refused(Unmerged)`; else `graft_git::conflict::read` of the working tree → `Text { file, unstaged }` (`unstaged` = the status shows edits since the stage), `Binary { unstaged }`, or `Removed` (not on disk). Too large / parse / io map as `open_conflict` does.
- `apply_take` (fn) — `(repo, path, file: &ConflictFile, block, take)` → the document as it now stands. Takes the side on a clone of `file` and hands `file.fingerprint` to `write_back`, which refuses `Changed` when the bytes on disk are not the ones the user is looking at and leaves them untouched. **Takes the document, not an `Oid`** (the spec's `expected: Oid` with a re-read from disk): a taken block renders as its taken lines alone, so re-reading the path would drop every `Resolved` region and re-index the rest under the cursor — measured, `three.txt` goes 3 blocks → 2. Passing the document in keeps `blocks()` stable for the session and is what makes a re-take *replace* rather than land on a different block.
- `apply_take_all` (fn) — `(repo, path, file: &ConflictFile, take)`: `apply_take` for every open block, one `write_back` against `file.fingerprint`; `Changed` leaves the bytes untouched. Takes the document for the same reason as `apply_take` (m6-conflicts/16 D1).
- `BaseError` (enum) — `NoBase` (a stage missing: a whole-file shape, or `AA`), `Mismatch(BaseMismatch)`, `Diff3(Diff3Error)`.
- `base_for` (fn) — `(repo, path, file)` → `diff3_file` + `attach_base`; how many blocks got a base.
- `mark_resolved_refusal` (fn) — `(path, file)` → `Some(ConflictsOpen { path, open })` while `file.open() > 0`. The app calls it before `Stage`, so the refusal is in words before a `git` process runs; `MarkersRemain` stays as the second line of defence.
- `ConflictSet` (struct) — `paths` (unmerged now in status order, then git's `Conflicts:` list in `MERGE_MSG` order, then paths at stage ≥ 1 in any unmerged state on the live entry's backup chain **since the current step stopped** — the walk ends at the first `LinkKind::Resume` link, left out (m6-conflicts/22); each once) and `recorded` (git's list found, or the chain named any) (m6-conflicts/09, `conflict/set.rs`).
- `ConflictSetError` (enum) — `Io`, `Run` as the spec gave them, plus `Facts` (the live entry could not be settled), `Journal` (the journal did not parse), `Snapshot` (the chain could not be walked) (m6-conflicts/09).
- `operation_conflicts` (fn) — `(repo, facts)` → `ConflictSet`. Git and the chain only, no app state, so a relaunch and a shell-begun operation list the same files. `MERGE_MSG` and the chain are read only while `facts.in_progress` is `Some`. Reads the journal file with `journal::parse`, never `Journal::open` (which writes). **Which kinds write `Conflicts:`, measured git 2.54.0:** merge, pull, rebase (merge backend), cherry-pick, revert — yes, path unquoted; stash pop — no `MERGE_MSG` at all (m6-conflicts/09).
- `conflict/merge_msg.rs` (crate-private) — `MERGE_MSG` read-only helpers: `read`, `comment_prefix` (`core.commentChar`, `#` unset or `auto`), `conflicts`, `without_comments`, `merged_from` (m6-conflicts/09).

## finish
What a merge will commit, for the finish summary (m6-conflicts/09). Reads only.
- `FinishSummary` (struct) — `into` (branch short name, or `HEAD`'s short id detached), `from` (`MERGE_MSG`'s first line: `Merge branch 'x'` → `x`, ` of <url>` kept, ` into y` dropped; else `MERGE_HEAD`'s short id), `by_you`, `by_git`, `message` (`MERGE_MSG` minus comment lines and trailing blank lines), `recorded`.
- `ByYou` (struct) / `ResultIs` (enum) — a conflicted path and its staged blob against `HEAD:path` (`Yours`, checked first) and `MERGE_HEAD:path` (`Theirs`); absent in the index `Deleted`; else `Combined`.
- `ByGit` (struct) / `Change` (enum) — every other `DiffSpec::Staged` change: `Added` (a detected copy too), `Modified`, `Deleted`, `Renamed { from }`, `TypeChanged`; `added`/`removed` 0 for binary.
- `SummaryError` (enum) — `NotMerging`, `StillUnmerged { count }`, `Facts`, `Run`, `Io`, plus `Conflicts(ConflictSetError)` and `Diff(DiffError)`.
- `finish_summary` (fn) — `(repo)`: merge only, nothing unmerged. When `recorded` is false, `by_you` is empty and every staged change is in `by_git`.
- `merged_from` (fn, crate-private) — `(repo, merge_msg: Option<&[u8]>)`: the rule behind `FinishSummary::from`, shared with `apply`'s `finish merge of <from>` description (m6-conflicts/20).

## journal
- `Line` (enum) — one JSONL record: `Pending(PendingLine)` (the before-fields, `at_unix_ms`, `kind`, `description`, `touches`, `backup_ref`, `pins`, `reverses`) or `Outcome(OutcomeLine)` (`status` Committed/Aborted, the after-fields, `commands`); two lines per entry, append-only; `id` (fn) (m3/02).
- `Parsed` (struct) — `entries` (in pending-line order) and `torn_tail` (1-based line number of a truncated last line, a crash mid-append; nothing is lost by it) (m3/02).
- `parse` (fn) — pure; merges pending + outcome by id, a pending with no outcome stays `Pending`; errors for a malformed line, a torn line that is not last, an outcome without a pending, or a duplicate of either (m3/02).
- `render_pending` / `render_outcome` (fn) — the bytes to append, newline included; `render_outcome` refuses a `Pending` entry (m3/02).
- `PendingLine.put_back` (m6-conflicts/72) — the entry's `put_back` on its opening line, same serde rule; absent when `None`.
- `PendingLine.merge_before` / `OutcomeLine.merge_after` — git's merge state (m6-conflicts/20), `serde(default, skip_serializing_if = None)`: an old line parses as `None`, a line with no merge renders as before. `Journal::mark_interrupted` records the merge state it reads as `merge_after`.
- `JournalError` (enum) — `Json { line, what }`, `TornTail { line }`, `DuplicatePending`, `OutcomeWithoutPending`, `DuplicateOutcome`, `StillPending`, `Io` (for the execution group's file handle) (m3/02).
- `in_force` (fn) — the entry took effect and no later in-force entry has `reverses == Some(id)`. `Committed` always took effect; `Aborted` only with a backup (`worktree_before`) **and** a recorded after-field that differs from before, or a touched field never recorded after (unknown ≠ unchanged). A failure that changed nothing — hook-rejected commit, an undo whose CAS refused — is not in force, so it never shadows `next_undo` and never marks its target reversed (m3/02 review fix, C1).
- `in_force` (m5/07) — a `Pending` entry is **not** in force: a conflicted operation is one entry, `Pending` from the stop until it finishes or aborts, and while it is open it never shadows `next_undo` (design note hard choice 2).
- `in_force_all` (fn) — one flag per entry, in journal order: what `in_force` answers for every entry in one walk, for the journal browser's row marks (m3-working-tree-undo-and-stash/06).
- `undoable_kind` (fn) — false for `Fetch`, `Push` (and `Undo`/`Redo`): kinds `u` passes over (m4/04, design note choice 1).
- `undoable` (fn) — `undoable_kind` **and** not a `Committed` pull whose after equals its before on every field (git's "Already up to date."): such a pull stays journaled (its fetch ran) but is transparent to `u`/`U`, like a fetch (m4/04 review M3).
- `next_undo` (fn) — newest in-force entry that is `undoable` (m3/02; fetch/push skipped m4/04; no-op pull skipped, review M3).
- `next_redo` (fn) — newest in-force `Undo` with no in-force **undoable** operation newer than it (a new operation after an undo empties redo, §6.5; a fetch, push or no-op pull does not) (m3/02, m4/04, review M3).
- `root_operation` (fn) — follows an `Undo`/`Redo` entry's `reverses` chain to the operation at its root; what `undo::inverse` takes as `original` (m3/02).
- `PointInTime` (struct) — `head`, `refs` (every ref any entry touched), `index`, `worktree` (m3/02).
- `state_at` (fn) — ADR-0031's query: per tracked thing, the after-value of the newest entry at or before `at`, else the before-value of the oldest entry after; `None` when no entry is at or before `at`. Nothing calls it in M3 (m3/02).

## undo
- `Step` (enum) — `UpdateRef { name, expect, to }` (compare-and-swap; `None` = absent), `SetHead(HeadRef)`, `RestoreIndex { index: IndexState, paths: IndexPaths }`, `RestoreWorktree { tree, paths }`, `StashStore { commit }` (`stash store -m <the commit's subject>`; idempotent because the **executor** scans the reflog first — git's own `stash store` of a commit already at `stash@{1}` adds a duplicate), `StashDrop { commit }` (reflog entry for that commit removed, no-op if absent). `refs/stash` is never an `UpdateRef`: its reflog is the stash list (m3/02).
- `Step::SetMergeState(Option<MergeState>)` (m6-conflicts/20) — `Some` writes `MERGE_MSG`, `MERGE_MODE`, then `MERGE_HEAD` back (temp + rename, at `rev-parse --git-path`); `None` removes them, `MERGE_HEAD` first. Checked after with `rev-parse -q --verify MERGE_HEAD`. `inverse` emits `SetMergeState(entry.merge_before)` **last**, whenever `merge_before != merge_after`; so `u` of a finish puts the merge back and its redo removes it. Touches nothing (`touches_of`).
- `Step::SetBranchConfig { key, to: Vec<String> }` (review m7-16b..21b, Major 1) — one `branch.<name>.*` key of the local config made to hold exactly `to` (empty: unset). `inverse` emits one per key whose `config_before` and `config_after` differ, after the `UpdateRef`s, `to` = the before-values: `u` of a Track removes the upstream it wrote and puts back one that was there before; the redo writes it again. `touches_of` names the key's branch ref, so the undo entry records the section too. `check_ref_names` checks the key's branch. Roll-back: `SetBranchConfig` to the restore's own `config_before`. An entry closed by `mark_interrupted` has no `config_after` (not read there): its undo puts back before-keys only.
- `PathScope` (enum) — the **working-tree** scope: `ChangedBetween { from, to }` (only what the operation changed) or `Everything` (after-tree never recorded: an operation that died before it could be read; `drift` reports it as `unknown` so the user is asked first) (m3/02).
- `IndexPaths` (enum) — the same for the index, over `IndexState`s: `ChangedBetween { from, to }`, `Exactly(Vec<PathBuf>)` (one file started over), `Everything` (no after-state recorded; an unmerged index has no tree to diff, so it is the union of what the backup holds and what the index tracks now) (m6-conflicts/08).
- `InversePlan` (struct) — `reverses`, `kind` (`Undo`/`Redo`), `description` (`undo: …`/`redo: …`, `redo: … (after a failed undo)` for an aborted undo), `touches` (union of the steps), `steps` in order: refs, `HEAD`, index, worktree, stash reflog, `pins` (every `StashDrop`'s commit: the new entry's pins, so the backup ref keeps them alive past `gc.pruneExpire`) (m3/02, pins added in the review fix, M2).
- `NotInvertible` (enum) — `Pending`, `NoBackup` (**never** for an unmerged before-index any more: that has an `IndexState` of its own, m6-conflicts/08), `NotUndoable(kind)` (`Fetch`/`Push`, or a pull that moved nothing per `journal::undoable`; returned by `inverse` before any generic step, m4/04), `NothingToUndo`, `NothingToRedo`, `Incomplete { field }` (m3/02), `OperationLive { kind: InProgress }` (m6-conflicts/57: the executor's undo gate; `finish or abort the <kind> first`; the planner never returns it).
- `undo::operation_live_words` (fn) — `(InProgress) -> String`: `OperationLive`'s one wording, called by `UndoError::explain` and the preview's `CannotRevertTo` refusal (m6-conflicts/64; `preview::tests::operation_live_has_one_wording_in_ops`).
- `inverse` (fn) — `(entry, original)`: generic steps from the entry's own before/after (`UpdateRef` where before ≠ after, `SetHead` when `HEAD` changed, restores where `touches` says so) plus the root operation's stash step: undo of push → `StashDrop(refs_after["refs/stash"])` **only when `refs/stash` moved** (a push with nothing to save exits 0 and leaves the user's own stash there; both sides must be recorded, else `Incomplete`), undo of pop/drop → `StashStore(pins[0])`; an `Undo` entry's inverse is a `Redo` with the forward stash step; a `Redo` entry's inverse is an `Undo` of the original (m3/02, review fix C2). The forward step of a pop/drop/branch-from-stash is `StashDrop(pins[0])` **only when the `Undo` entry's own `refs/stash` moved to that commit** — i.e. its `StashStore` put it back; a pop git refused on a conflict kept its stash, its undo stored nothing, and its redo drops nothing (both sides must be recorded, else `Incomplete`). The root's `refs/stash` cannot tell: popping `stash@{1}` leaves it unmoved either way (m6-conflicts/07, F2). A set-aside root (`put_back: SetAside(S)`, m6-conflicts/73): undo → `StashDrop(S)` only when the root's `refs/stash` ended at S (a clashed put-back kept it); redo → `StashStore(S)` only when that undo's own `refs/stash` moved (`stash_ref_moved`).
- `plan_undo` / `plan_redo` (fn) — `inverse` of `next_undo`/`next_redo` with its root operation (m3/02).
- `plan_revert_to` (fn) — the time machine (§6.6): the in-force **operations** from the newest back to `target` inclusive, newest first, each as its own `InversePlan`. Anything `undoable` passes over (a fetch, a push, a no-op pull) is skipped rather than refused; an entry that cannot be inverted stops the whole plan before a single step runs (m5/07). `Undo` and `Redo` entries are **stepped over**, not inverted: inverting an `Undo` re-does the very work the user undid, so going back in time used to re-create what they had just thrown away (m5/07 review fix, C2 — `journal::is_operation` is the shared filter, and `in_force` already settles which side of an undo/redo pair stands).
- `touches_of` (m5/07) — a `SetHead` step contributes **no** touched ref. A touched ref is snapshotted into `refs_before`/`refs_after`, and inverting that snapshot emits `update-ref HEAD <old> <new>`, which moves the branch `HEAD` points at (found by `tests/it/history_ops.rs::checkout_applies_undoes_redoes`).
- `RepoStateNow` (struct) — `merge: Option<MergeState>` (m6-conflicts/20); `head`, `refs`, `index: IndexState` (never optional and never an error: an unmerged index is the stage tree), `worktree_tree`, read fresh by the executor (m3/02; `IndexState` m6-conflicts/08).
- `Drift` (struct) — `refs: Vec<(name, recorded, now)>`, `head`, `index: Option<(IndexState, IndexState)>`, `worktree`, `unknown: Vec<&str>` (`"HEAD"`, `"the index"`, `"the working tree"`: touched, never recorded after, restored whole); `is_clean` is false when anything moved **or** anything is unknown; `explain` (`refs/heads/main moved; the index changed`, `the working tree's state after the operation was never recorded; undo restores all of it`); the index reads `the index is unmerged now` / `the index is merged now` when the shape changed, `the index changed` otherwise (m3/02, unknown added in the review fix, M1; shapes m6-conflicts/08).
- `Drift::replaced` / `Replaced` (struct) — m6-conflicts/77: what running the inverse anyway would replace: `paths` (sorted, unique; the inverse writes them, the user changed them since the entry's after-state, and what is there now is not already what the inverse writes — working tree or index) `whole_tree` (a `PathScope::Everything` step) and `whole_index` (an `IndexPaths::Everything` step; apart since m6-conflicts/80, so an index-only restore is not worded as the working tree). `drift` leaves it empty; `run_plan` fills it only when the drift is not clean (private `undo::replaced`: at most two `diff-tree -r -z --no-renames` spawns for the working tree and three `snapshot::index_paths_changed` for the index, each one `diff-tree` or two `ls-tree -r` — worst case 8, all logged to the entry's Command Log, m6-conflicts/80). The no-cost promise rests on the gate in `run_plan` and on the early returns in `in_worktree`/`in_index` (`after == now || after == before`). Not part of `is_clean`. `is_empty`; `extend` unions (the time machine's steps).
- `Drift::merge` / `MergeDrift` (enum) — m6-conflicts/20: git's merge state now against the entry's `merge_after`, `Begun` / `Ended` / `Changed`; words `a merge is in progress now`, `the merge is no longer in progress`, `the merge in progress changed`. An enum, not the two states: they are the entry's and the repository's, and boxing them pushed `UndoError` over clippy's large-error bound.
- `drift` (fn) — §6.7's three comparisons against the entry's after-state, plus `unknown` for every touched field with no after-value: unknown is not clean, so the confirm rail fires exactly where the restore is widest (m3/02 review fix, replaces "a field never recorded cannot drift").

## journal (file handle)
- `Journal` (struct) — the open journal file and the entries read from it; `open` (creates `<git-path graft>/` and the file, parses, and **cuts off a torn last line** so the next append is not spliced onto it), `path`, `entries`, `torn_tail` (the cut line's number, nothing lost by it), `append_pending`/`append_outcome` (one `O_APPEND` write plus `fsync`; file first, held copy second), `unresolved`, `mark_interrupted(id, after)` (m3/03). Note `open` **writes** (the torn-tail cut), so it is not a read-only call; two Graft processes on one worktree are not supported.
- `Journal::hold_commands` (fn) — keep a stopped operation's command lines on the held entry. Only the outcome line records `commands`, and a conflicted operation has not written one yet, so the lines live in memory until it finishes; a relaunch loses them and the entry is closed by `recover_interrupted` with none (m5/07).
- `journal_path` (fn) — `git rev-parse --git-path graft/undo-journal.jsonl`: per-worktree by git's own layout (ADR-0010) (m3/03).

## snapshot
`snapshot.rs` takes the snapshot; `snapshot/stage_tree.rs` is the stage-tree codec, `snapshot/chain.rs` the backup chain, `snapshot/index_paths.rs` the path diffing, `snapshot/raw.rs` the bytes git would not give back (ADR-0052), `snapshot/plumbing.rs` the temporary index and the `git` they share. Every public item is re-exported from `snapshot`, so no path below moved (m6 g04/g08 review, M3: 976 lines split).
- `SnapshotScope` (enum) — `None` or `Full`; hard choice 3's one knob (m3/03).
- `scope` (fn) — `Full` whenever the operation touches the index or the working tree, `None` otherwise (ADR-0009: unconditional) (m3/03).
- `Snapshot` (struct) — `index: IndexState`, `worktree_tree`, `commit` (m3/03; `IndexState` m6-conflicts/08).
- `index_state` (fn) — the staged state as a tree, from a **copy** of `.git/index`: `Merged(write-tree)`, or, when git refuses the copy as unmerged, the **stage tree** — `ls-files --stage` on the copy, every path rewritten to `<stage>/<path>` at stage 0 on a second temp index, then `write-tree`. No blob is written; every stage's blob is already an object. Never `write-tree` on the real index (m3/03; the stage tree m6-conflicts/08).
- The backup commit's layout — `{ index/, worktree/ }` for a merged index (**unchanged**, so every ref written since M3 reads as before) and `{ unmerged/, worktree/ }` for a stage tree. Never both (m6-conflicts/08).
- `LinkKind` (enum) — `Step` (before a folded resolver write, `apply/fold.rs`) or `Resume` (before `resume` hands the operation back to git): why a chain link was written, as the backup commit's last message line `Graft-Link: step|resume`. No such line (the pre-operation snapshot, links written before m6-conflicts/22) reads as `Step` (m6-conflicts/22).
- `chain_backup` (fn) — trailing `link: LinkKind` since m6-conflicts/22. Decision 2 of m6-conflicts/08: the repository **now**, committed onto a live entry's backup ref (parent = the ref's current target), then `move_backup_ref`. `Ok(None)` when the entry names no backup ref. **No journal line, no entry** — a step inside a stopped operation is still one entry (M5 hard choice 2), but the step's own `add` drops stages 1-3 and a whole-file take overwrites the working tree, so what it is about to lose is kept here.
- `StageEntry` (struct) / `stage_entries` (fn) — the `(mode, oid, stage)` triples one path has in an `IndexState`, **in stage order** (the derived `Ord` is mode-then-oid, which orders three stages of one path at random); empty when the state does not hold the path (m6-conflicts/08).
- `recorded_index_state` (fn) — the `IndexState` a backup commit records, from the **name** of its index subtree (`index/` merged, `unmerged/` the stage tree); `None` when the commit has neither, which is how a chain walk knows it has run into the user's own history (m6-conflicts/08).
- `backup_chain` (fn) — a backup ref's recorded index states, each paired with its `LinkKind` (m6-conflicts/22), **newest first**: the ref's commit, then first parents, stopping at the first non-backup commit. An absent ref is an empty chain. Whole chain, every kind; readers asking about the current step use `current_step_chain`.
- `current_step_chain` (fn) — `backup_chain`'s states cut at the first `LinkKind::Resume` link (left out), newest first: the current step's links only. The one bound both `ConflictSet` and `apply::stage_source` read through (review m6-amend-10-22 M1).
- `index_paths_changed` (fn) — `(repo, from, to, stop, commands)`: the paths whose index entries differ between two recorded states, each `git` it runs pushed to `commands` (m6-conflicts/80): `diff-tree -r --name-only` with the stage prefix stripped and de-duplicated when both share a shape, one `ls-tree -r` per side and a set comparison when they do not (m6-conflicts/08).
- `worktree_tree` (fn) — the same copy plus `add -A`: tracked working-tree content *and* untracked files, in one tree. The copy carries git's stat cache, so only stat-dirty files re-hash — 15 ms against 236 ms for a fresh `read-tree` on 5,000 files (git 2.54) (m3/03).
- `raw_record` (fn, `snapshot/raw.rs`, m7/30q-a, ADR-0052) — `(repo, scratch, stop, head: Option<Oid>, worktree_tree) -> Result<Option<Oid>, SnapshotError>`: the regular files `worktree_tree` holds apart from `HEAD` (`diff-tree -r -z --no-renames`; unborn: `ls-tree -r -z`, every file), that git would convert (`config --get core.autocrlf`, only a git-false value is off; `check-attr -z --stdin` on `text eol crlf filter ident working-tree-encoding`), and whose disk bytes differ from git's own checkout of the cleaned blob (`update-index -z --index-info` on a fresh `TempIndex`, `checkout-index -a -f --prefix=<scratch dir>/`, streamed compare; the dir is removed on every path), as a tree of their raw bytes at their own paths and modes (`hash-object -w --no-filters`, `update-index`, `write-tree`). `None` when none (and for a bare repo). Not `cat-file --batch --filters`: its header prints the pre-filter size. **Not yet called by `take`** (30q-a stopped at this seam; see the ticket).
- `take` (fn) — both trees from one index copy, `mktree` into `{ index/, worktree/ }`, `commit-tree` with a fixed `graft` identity and `parents` (the pins **and** every commit the entry's before-fields name), `update-ref refs/graft/backup/<worktree>/<ulid>` (m3/03, anchors in the review fix, C1).
- `commit_trees` (fn) — the same join and commit without touching a ref; either tree may be `None`. The after-snapshot uses it with the before-commit and the entry's after-commits as parents (m3/03, `Option<Oid>` worktree side in the review fix, C1).
- `move_backup_ref` (fn) — point a backup ref at another commit (m3/03).
- `backup_ref_name` (fn) — `refs/graft/backup/<worktree>/<ulid>` (ADR-0010 + its Correction) (m3/03).
- `SnapshotError` (enum) — `Run`, `Io`, `NotAnOid { what, printed }`, `UnknownLink { commit, printed }` (a `Graft-Link:` value this build does not know, m6-conflicts/22), `Stopped`. `Unmerged` is **retired**: an unmerged index is a state, not a failure (m3/03; m6-conflicts/08).

## facts
- `read_facts` (fn) — `(repo, git, stop, with_remotes)`: `RepoFacts` in one pass: bare, `HEAD`, in-progress, status, stashes, the git version, and — only when `with_remotes` (`apply` passes `op.is_remote()`) — remotes and `HEAD`'s upstream (m4/04; gated in review M2, so an unreadable remote section never blocks stage, commit or stash). Mid-rebase only, the edit-stop fact (`rewrite::edit_stop`, m7-power-tools/07a). Read once, before anything is written, so `check`/`plan`/`touches` see one picture (m3/03).
- `head_ref` (fn) — `HEAD` as the journal records it (m3/03).
- `read_refs` (fn) — the current value of each named ref, `None` for one that is absent; follows a symbolic ref. One lookup per name, not a pass over the ref store (m3/03, review fix M6).
- `read_state_now` (fn) — §6.7's three comparisons read fresh: `HEAD`, the named refs, the index state (`IndexState::Unmerged` when unmerged: a state of its own, never an absence or an error — m6-conflicts/08), the worktree tree and the merge state (m3/03, review fix M5).
- `FactsError` (enum) — `Status`, `Head`, `Refs`, `Stash`, `State`, `Snapshot`, `NonUtf8Ref` (a ref name the journal cannot record as text; never mangled silently), `Markers { path, source }`, `Ancestry(RunError)` (an ancestry read the re-push guard needed failed — refusing to guess is the point of the guard, m5/07 review fix M5), `Stopped`, `Remote(RemoteError)` (m4/04); `explain` (m3/03).
- `FactsError::MergeState(MergeStateError)` (m6-conflicts/20) — git's merge files could not be read.
- `FactsError::{History(RunError), Branches(BranchError), SavedPlan(io::Error)}` (m7/02) — a rewrite's history read, the default branch, or its saved plan could not be read; `of_history` (crate-private) maps a stopped run to `Stopped`.
- `FactsError::Incoming(RunError)` (m7-power-tools/03b) — what a pull's fetch brought could not be read; `of_incoming` (crate-private) maps a stopped read to `Stopped`. `read_incoming(repo, head, tip, stop)` (crate-private) — `merge-base --is-ancestor`, then (fast-forward only) `diff --name-only -z --no-renames`: two spawns at most.
- `FactsError::Reflog(ReflogError)` (m7/22) — git's reflog could not be read (`reading git's reflog: …`).
- `FactsError::BranchConfig(RunError)` (review m7-16b..21b, Major 1) — a touched branch's `branch.<name>.*` config could not be read (`the branch's config: …`); `begin` refuses on it (a stop stays a stop). `AfterState::BranchConfig(FactsError)` — the same after the operation: `config_after` stays empty, never swallowed.
- `branch_config` (mod, crate-private; review m7-16b..21b, Major 1) — a branch's own config as journal state: `read(repo, refs, stop)` = `git config --local -z --get-regexp ^branch\.` filtered to the `refs/heads/<name>` in `refs` (none: no spawn; exit 1 = no keys; a non-UTF-8 value is `Unparsable`, a valueless key reads `true`); `branch_of(key)` → `refs/heads/<name>` (the name may hold dots); `writes(key, to)` → `--replace-all` + `--add`s, or `--unset-all`; `already_so` = `--unset-all`'s exit 5 (unset already: the state asked). `begin` records `config_before`, `finish` `config_after`, for every branch in `touches.refs`.
- `FactsError::OnDisk { path, source }` (m7/23b) — the in-the-way read (`in_the_way::disk::on_disk`) could not look for a path on disk.

## in_the_way (m7/28a, ADR-0049)
The one read of files git doesn't keep standing where a write puts its own. Callers: `preview::plan` (after `check`) and `apply`'s `guard_in_the_way` (before the set-aside and `begin`). The only worktree `symlink_metadata` in the crate. Split since m7/28c: `in_the_way.rs` (the read and its words), `written.rs` (the one-shot and stash rows), `replay.rs` (the replay rows and git's skip), `reads.rs` (the git reads), `disk.rs` (the stat walk and the untracked/ignored split); every child crate-private.
- `Blocking` (struct) — `ignored`, `untracked`: `Vec<PathBuf>`, each sorted and unique; `is_empty`.
- `blocking` (fn) — `(repo, op, facts, stop) -> Result<Blocking, FactsError>`: `written_paths`, minus the index (`ls-files`), through `on_disk`; ignored = not in `facts.status`'s untracked list (a directory: nothing listed under it). Empty for a kind not covered, and in a bare repo. Spawns: the paths read (1; a stash: parents + one per tree; a replay: `diff-tree` to `onto`, `rev-list`, one `diff-tree --stdin`) and `ls-files` (1), never one per path or commit.
- `refusal` (fn) — `Some(Refusal::InTheWay { doing, .. })` when not empty. `refused` (crate) — the same, but stash apply/pop build `StashInTheWay { untracked, ignored }` (apart since 28c), and a file put-back (Recover `Files`) refuses only its ignored paths: the snapshot holds the untracked (m7/30o R1).
- `doing` (fn) — `<doing>`: `switching to <b|sha7|name>`, `merging <b|sha7>`, `pulling <remote_side>`, `resetting <b> to <sha7>` (hard only), `putting <b> back to <sha7>` (MoveRef), `putting back your edit` (Files, m7/30o), `rebasing onto <b|sha7>`, `rewriting <b>`, `picking <sha7>` / `picking <n> commits`, `reverting <sha7>`; `None` otherwise.
- `written::written_paths` (crate-private) — ADR-0049 §4's table: checkout / branch-create+checkout = `diff-tree HEAD <landed>` (`ls-tree` when unborn); merge, and since 28c pull (`tracking_tip` before the fetch; review 28 M1) = `diff-tree --merge-base HEAD <tip>`, the incoming side; Recover `Files` = its paths (m7/30o); reset `--hard` and checked-out `MoveRef` = `diff-index --cached <to>` (a superset of the table's `HEAD` diff: a `git rm --cached` file is written back too); branch-from-stash = `HEAD`→`stash^1` + the stash's; stash apply/pop = `stash^1`→`stash`, `stash^1`→`stash^2`, `ls-tree stash^3`; replays (m7/28b) = rebase: `diff-tree HEAD <onto_tip>` + each commit of `rev-list --no-merges <onto_tip>..HEAD`; rewrite: git's `skip_unnecessary_picks` first (28c, review 28 m1: leading `pick` rows — the word git is handed, `rewrite::git_words` — whose only parent is the running `onto` move `onto` and are not replayed; `drop` passed over; one `rev-list --no-walk --parents`), then `diff-tree HEAD <onto as skipped>` + each non-`drop` todo row from there (the `made` fixups are rows) + the dependents' commits (`rev-list --no-merges <head>..<top>`); cherry-pick: each commit; revert: the commit against `parent` (else parent `mainline`, via `rev-parse ^@`) — each commit's own change in one `diff-tree --stdin --root`. The engine's `switch <home>` needs no guard of its own: every path it writes is in that union. `Ok(None)` for every other kind.
- `disk::on_disk` (crate-private) — `(repo, paths, tracked)`: a file or link at the path counts; a directory counts when it holds anything the index doesn't track; `ENOTDIR` counts the first ancestor that isn't a directory, unless the index tracks it. Something found under another spelling (a case-insensitive or Unicode-normalising disk: `README.md` finds `Readme.md`) is judged by the spelling the disk keeps — the directory entry with the same inode, per component — and a tracked one is git's, not in the way (28c, review 28 M2). Other I/O errors → `FactsError::OnDisk`.

## merge_state
git's merge in progress, as files (m6-conflicts/20). The one place Graft writes git's merge files, and only to put back bytes git wrote.
- `MergeStateError` (enum) — `Io { file, source }`, `NotAnOid { printed }`, `Run(RunError)`, `NotWritten { expected, git_says }`. `Octopus` removed (m6-conflicts/38): an octopus merge is read, not an error.
- `read_merge_state` (fn, crate-private) — `(repo) -> Result<Option<MergeState>, _>`: three file reads under `git_dir`, no spawn; `MERGE_HEAD` decides (no file, no merge). Every `MERGE_HEAD` line is a head, in order (an octopus's into `other_heads`) — it runs as every entry begins, so refusing a merge shape here refused every `u` during that merge (m6-conflicts/38).
- `write_merge_state` (fn, crate-private) — `(repo, Option<&MergeState>, stop, &mut commands)`: `Step::SetMergeState`'s body; idempotent. Writes `MergeState::merge_head_bytes` (every head); the check after is `rev-parse -q --verify MERGE_HEAD` = the first head, which is what git reads for an octopus (verified, `octopus_merge::set_merge_state_writes_an_octopus_merge_head_back_byte_exact`).
- `autostash_waits` (fn, crate-private) — `MERGE_AUTOSTASH` exists. Verified against git 2.54.0: `merge --continue` and `commit` both apply it.

## clash
- `Clash` (struct, m6-conflicts/72) — `stash`, `why: PutBackWhy`, `paths` (unmerged after): `ApplyError::Clashed`'s payload.
- `StashClash` (struct) — `entry: EntryId`, `stash`, `index: Option<usize>` (always `Some` from `live_clash`: a stash no longer listed is no clash), `why`.
- `ClashCandidate` (struct, m6-conflicts/82) — `{ clash: StashClash, expect: IndexState }`: a clash the journal alone points at, and the index it must still be in to be one.

## apply
`apply.rs` holds `Context`, `apply` and its gates; `apply/record.rs` the protocol's two halves (`begin`, `finish`, after-state, `kind_name`), `apply/run.rs` running a plan, `apply/error.rs` `ApplyError`/`AfterState`, `apply/restart.rs` `d` after `⏎`, `apply/fold.rs` a step inside a stopped operation (`folded_step`), `apply/finish_merge.rs` the shared gate of `FinishMerge` and `AbortMerge` (`ending_a_shell_merge`, m6-conflicts/41, /57), `apply/resume.rs` `resume` and `live_entry`, `apply/resume/shell.rs` the shell-merge route (`Target`, `shell_merge`, `refuse_unmerged`, `refuse_octopus`, m6-conflicts/41), `apply/recover.rs` `recover_interrupted`, `apply/remote.rs` askpass and progress, `apply/set_aside.rs` setting edits aside around a rebase or checkout (m6-conflicts/73; 06d: `set_aside/returned.rs` step 6 apply + drop, `set_aside/answer.rs` the outcome, `set_aside/rebuild.rs` absorb's rebuilt stash, `set_aside/put_back.rs` the apply and its fallback). Every public item is re-exported from `apply`, so no path below moved (m6 g04/g08 review, M3: 1230 lines split).
- `Context` (struct) — one operation's world: `repo`, `git`, `worktree`, `scratch`, `journal`, `now_unix_ms`, `random`, `stop`, `remote: Option<RemoteHooks>` (`open` leaves it `None`: headless, no prompt, no progress, m4/04), `default_branch: Option<RefName>` (the app's `graph.default_branch` override; `open` leaves it `None`; an `r`'s line is found with it, m7/02b); `open`, `next_id`. One context per operation (and per undo, itself an operation) (m3/03).
- `Context::advance` (fn) — mint the next entry id inside one call: the random half incremented as an 80-bit counter, ULID's own rule for entries sharing a millisecond. Only the time machine needs it — every other call journals one entry (m5/07).
- `Resume::ContinueWith { message }` (m6-conflicts/09) — merge only: `git commit --cleanup=whitespace -F -` (message on stdin; `whitespace` since m6-conflicts/22 — git's comment lines are removed once, when `finish_summary` reads `MERGE_MSG`, so a `#` line sent is the user's and is kept) with `GIT_EDITOR=true`, closed like `Continue`; a hook refusing is `ResumeFailed`. Any other kind is `Refusal::MessageNotHere { kind }` (`a <kind> keeps each commit's own message · c continues`) before the entry is looked up or anything runs. `MERGE_MSG` is never written. `Resume` is no longer `Copy`. `Continue` is unchanged (`git merge --continue`).
- `apply::engine` (crate-private, m7/02b, ADR-0047) — `Operation::Rebase` and `Operation::Rewrite` run here: `prepare` (the line — `RebaseParams::line` for `r` (m7/05b: `line_of` read again first; a line whose names differ → `Moved { name: <first that differs> }`; rows `rewrite::rebase_rows`, each `drops` oid marked `drop`, one not among them → `Moved { name: <his branch> }`), the plan's line for a `Rewrite` — the todo, the command; before `touches`, which gains every branch of the line), `Engine::save` (the plan dir, before `begin`), `Engine::run` (`GIT_SEQUENCE_EDITOR`/`GIT_EDITOR` helpers + `CLEANUP`; exit 0 with `rebase-merge/` live is an `edit` stop → `Conflicted { paths: [] }`; otherwise `go_home` — `git switch <his branch>` after a top-of-line run — and the plan removed). `r`'s refusals over dependents (fork, elsewhere, git too old) come from `line_of` in `preview::plan_as_run`, before `y`; `R`/`a`/absorb refuse in `rewrite::plan`.
- `Resume` (enum) — `Continue`, `Skip`, `Abort`: how a stopped operation goes on. For a rewrite (a saved plan exists): `live_entry` also matches `head-name` = the plan's top with `head_before` = its home; `GIT_EDITOR` is the plan's helper + `CLEANUP`, not `true`; exit 0 still rebasing → `Conflicted`; after it ends, `go_home` then the plan removed, failures as `AfterState` (m7/02b). `resume` (fn) finds the one `Pending` entry whose kind git's state still says is live, runs `git <kind> --continue|--skip|--abort` with `GIT_EDITOR=true`, and closes **that same entry** — `Committed` when it finishes, `Aborted { reason }` on `--abort`, or another `Conflicted` when the next commit stops too (m5/07, design note hard choice 2). `live_entry` (crate-private) reads git's state with the caller's stop (`in_progress_detail_with_stop`) and asks the stop again after it, so a stop raised during that read is `Stopped` (m7/01a, gap :640). `live_entry_facts` (crate-private) is the same in `FactsError`, the stop as `FactsError::Stopped`; `conflict::set` uses it, with no catch-all arm (gap :613).
- `apply`, a pull's fetch first (m7-power-tools/03b, `apply/pull.rs` `fetch_first`) — after the guards and `plan`, a `Pull` runs its fetch (the plan's first line) before `touches` and the set-aside, then fills `facts.incoming`; the entry opens after it, the fetch's line first in its commands, the merge alone left to run. A failed or stopped fetch opens and closes the entry as before 03b (both lines, `Aborted`/cancelled, nothing set aside; `open_after` opens it past the stop the fetch already answered). An incoming read that fails or stops returns `Facts`/`Stopped` with no entry (the fetch moved only tracking refs, which a pull never records).
- `apply` set-aside (m6-conflicts/73, ADR-0045 §4–§7) — when `sets_aside` is `Some`: `stash create` → `begin` (`put_back: SetAside(S)`, pins ∋ S) → `stash store` → `reset --hard` → the plan → `stash apply --index S` and read the status (m7-power-tools/30, `apply/set_aside/put_back.rs` `run_put_back`): git failed with nothing unmerged and no tracked file changed → it wrote nothing, so one plain `stash apply S`, read again; clean → drop S by id, `Committed` (after the fallback: `AfterState::StagingNotKept`); unmerged → keep S, `Committed`, `Clashed { SetAside }`; other failure → keep S, `Aborted`, `Git` naming `stash@{n}`; a read failing with no git failure to carry the words (the status after the apply, or the stash list to drop S: "your edits are back; the set-aside copy could not be found to drop") → `AfterState` with `AfterState::SetAsideKept`; the outcome line failing → `Journal` whose `kept` says where the edits are (m6-conflicts/83). A failed store/reset → `Aborted`, words name the stash if listed. A rebase stopping on a conflict keeps S until `resume` ends it, which runs the same put-back. `recover_interrupted` keeps `put_back` on the entry.
- `resume` with no live entry (m6-conflicts/20) — `Continue`/`ContinueWith` while git is merging with one `MERGE_HEAD`: unmerged paths refused first (`Unmerged`, as for a merge Graft began), then `apply(Operation::FinishMerge)`. `Abort` there (m6-conflicts/57) → `apply(Operation::AbortMerge)`, with no `Unmerged` refusal (a stopped merge is what it ends). Either end on an octopus merge → `OctopusMerge { heads, end }` first. `Skip` with no entry, a shell rebase/cherry-pick/revert, nothing in progress → `NotInProgress`, words unchanged.
- `RemoteHooks` (struct) — `progress: Box<dyn Fn(RemoteProgress) + Send + Sync>` (called ≤ every 100 ms from an executor thread, which ends when the invocation's sink is dropped: a blocking loop, no poll, review Minor 3), `askpass: Arc<dyn AskPass>`, `helper: PathBuf` (Graft's binary in askpass mode). Only an `Invocation` with `remote: true` gets them: an `AskPassServer` lives exactly as long as that child; a close failure is `AfterState::AskPass`, never fatal (m4/04).
- `Refresh` (enum) — `WorkingTree` or `Everything` (a ref moved, so the graph too; always for a remote operation) (m3/03, m4/04).
- `Applied` (struct) — the entry as written, and what to re-read (m3/03). **One exception**: a step run while git already has an operation in progress is folded into that operation's entry and writes no line of its own, so its `entry` here is a record of what ran, **not a journal entry** — read `description` and `refresh` from it, never look its `id` up (m5/07 review fix, C1). A working-tree step inside an operation begun in the shell is **not** that exception: it is an ordinary entry (m6 g04/g08 review, M1). `step_backup: Option<Oid>` is the chained commit such a step took **before** it ran, `Some` only for that exception (m6-conflicts/08).
- `Applied::replaced` (field, m6-conflicts/77) — what a forced undo/redo step replaced (`Replaced`), empty for every other write; `update::undo` names it and the key back on the landing.
- `ApplyError` (enum) — `Refused(Refusal)` (nothing written, nothing journaled), `Facts`, `Snapshot`, `Journal { error, after, kept }` (`after` carries git's own failure when the outcome line could not be written over it; `kept` says where a set-aside's edits are when kept or clashed, m6-conflicts/83), `AfterState { applied: Box<Applied>, unread }` (the operation ran and is journaled, but part of its after-state could not be read or kept reachable — `applied` is in it so the caller still refreshes), `Git { entry: Box<JournalEntry>, error, recoverable, edits: Option<EditsAt> }` (`edits`: where a set-aside's edits are when its operation or put-back failed; `explain` appends `EditsAt::words` before the backup clause; `edits_at()` returns it; m6-conflicts/84), `Stopped`, `Remote { entry, failure: RemoteFailure, stderr_tail, names: Box<RemoteNames> }` (a remote operation's non-zero exit or stop: `classify_failure` over all stderr, `Cancelled` on stop; entry `Aborted(<short failure>)`; `stderr_tail` ≤ 8 segments; `explain` is the design note's failure line, m4/04; since m6-conflicts/85 `WouldOverwrite` reads `pull refused: your edits to <paths> would be overwritten` — no keys, the app adds them — and `NotFastForward` `pull stopped: <local> and <remote> diverged — merge or rebase`, no `(M5)`, no shell command); `Conflicted { entry: Box<JournalEntry>, kind: InProgress, paths }` (the operation stopped on a conflict: the entry stays `Pending`, git's state is live, and `resume` is what closes it — not an error the caller can retry), `ResumeFailed { entry, kind, error }` (m5/07); `explain` adds ` · u restores the backup` when recoverable. Both `explain` strings carry git's stderr and the entry's description verbatim: **not sanitised for control bytes**, which the UI must do (m3/03, review fix M1/Minor 1/Minor 9).
- `ApplyError::Clashed { entry, clash: Clash }` (m6-conflicts/72, ADR-0045 §1–2) — a pop or apply git failed that left unmerged paths: entry `Committed` (in force, so `u` is the abort), `index_after` the stage tree `finish` reads (`record::read_after`, `snapshot::index_state`), git kept the stash. Not retryable, like `Conflicted`, but no operation in progress: no `c`, no `a`. Display `<description> left conflicts in N file(s)`. With an after-state field unread it is `AfterState` instead (the clash is then only in the journal).
- `apply`, the put-back failure branch (m6-conflicts/72) — `put_back_for(op)` writes `PutBack` on the `Pending` line for `StashPop`/`StashApply`. When git fails and the entry carries one, `clashed_put_back` reads the status (never stopped — the pop has run): unmerged → `Committed` + `Clashed`; nothing unmerged → `Aborted` + `Git` as before (`apply --index` refusing, an untracked file in the way); status unreadable → `Aborted` with both reasons, `Git`. Not `stopped_on_conflict`, which is unchanged. Only on failure: a plain `stash apply|pop` exits 1 on a clash (ADR-0045 §7).
- `AfterState::StagingNotKept { paths }` (m7-power-tools/30) — a set-aside put-back brought the edits back, but git could not reinstate the index on the landed tree, so it ran without `--index`; `paths` lost their staging (`put_back.rs` `staging_lost`/`lost`: every `M`/`D`/`T` of `diff-tree -r S^1 S^2`, and an `A` only when `diff-tree --name-only S^2 S` names it — its staged content moved on in the tree, `AM`; that second read runs only when an `A` exists; no `C`; sorted, deduped; neither read on the Command Log. 30c). Display `your edits are back · staging not kept: <first>[ +N more] · u undoes it, staging included`. A completed write: the entry is `Committed`, `S` dropped, `u` restores the split. If the drop, or the operation, fails after the fallback, the error's words carry ` · staging not kept: <paths>` too (`error.rs` `staging_clause`, the one formatter; 30c). `tracked_changed` (crate-private) is the put-back's "tree changed" judge, shared with recovery.
- `AfterState` (enum) — a field of an entry's after-state that could not be read or kept reachable: `Head`, `Refs` (also the entry's backup ref when `seal_after` cannot read the tip it chains onto: nothing sealed, after-trees dropped, never a fall-back to the pre-operation commit; m7/01a, gap :601), `Index`, `Worktree`, `Unsealed`, `BackupGone { name }` (m5/07), `AskPass(io::Error)` (the askpass socket could not be cleaned up, m4/04), `SetAsideKept { error, words }` (a set-aside stash kept because a read after the put-back failed; `words` say where the edits are, m6-conflicts/83), `PlanLeft { dir, error }` (a rewrite's plan dir not removed), `NotHome { home, top, error }` (`HEAD` left on the top of the line: the switch home failed) (m7/02b). Never swallowed — an unreadable tree costs a wider `u`, unreadable refs an `u` that refuses (m3/03 review fix, M1).
- `AfterState::MergeState(MergeStateError)` (m6-conflicts/20) — `finish` could not read git's merge state; never swallowed.
- `apply` (fn) — DESIGN.md §6.2: `read_facts` → `check` → `guard_in_the_way` (m7/28a: `in_the_way::blocking`, refused before the set-aside and the `Pending` line; stash apply/pop included) → before-state + backup + `Pending` line → run the plan → after-state (on abort as much as on success) + outcome line. A backup is taken when `scope` says `Full` **or** the operation has pins, since a pin's whole purpose is surviving `gc` (m3/03). Two gates come first (m5/07 review fix): when `facts.in_progress` is `Some`, the operation is a **step inside that span** and takes the folding path instead — no entry, no line — **except** inside an operation begun in the shell (no `Pending` entry of Graft's: nothing to fold into, no backup ref to chain onto), where a step whose `touches` names the working tree (`ResolveWholeFile`, `RestartConflict`) is journaled as its own entry with its own backup, 03's "no live entry → its own entry" rule; an index-only step there still folds into nothing (m6 g04/g08 review, M1: a hand edit overwritten by `t` or `d` was unrecoverable); and a re-push's `source_commit` is re-checked for ancestry before the first write, because a rule only the preview enforces is not enforced (ADR-0038 §4).
- `apply`, `FinishMerge` (m6-conflicts/20) and `AbortMerge` (m6-conflicts/57), one gate `ending_a_shell_merge` — before `begin`, in order: refused `InProgress(Merge)` when an entry of Graft's owns the merge (`live_entry`); `NotInProgress` with no `MERGE_HEAD`; `OctopusMerge { heads, end }` when `MERGE_HEAD` names several commits (also `resume`'s shell-merge route; `resume::shell::refuse_octopus`, m6-conflicts/38); `NotInProgress` unless `MERGE_HEAD` is still `params.merge_head`; `AutostashWaits { end }` while `MERGE_AUTOSTASH` exists (git applies it on finish **and** on abort, which `u` could not give back — both verified, see `merge_state::autostash_waits`). Description `finish merge of <from>` / `abort merge of <from>`. `begin` records `merge_before` and `finish` `merge_after` on **every** entry; the backup's before- and after-commits anchor every `MERGE_HEAD` commit (all of an octopus's, m6-conflicts/38) among their parents (`record::with_anchors`), so a pull-from-URL's `MERGE_HEAD` survives `gc`.
- `StageSource` (enum) / `stage_source` (fn) — where `d` (`RestartConflict`) can get a path's conflict stages from, newest first: `Index` when the status still calls it unmerged; else `Backup { tree }`, the newest `IndexState::Unmerged` holding a stage ≥ 1 for it — the live entry's backup ref chain **for the current step only** (`snapshot::current_step_chain`; a finished step's conflict is refused `NoStagesKept`) when an operation is live, otherwise the journal's in-force entries (`index_after`, then `index_before`); `None` when nobody kept them. **Does not consult git's resolve-undo (REUC)**: REUC is one slot per path, overwritten by the next resolution and gone with a rebuilt index, so it is not what `d` is built on (m6-conflicts/08). Signature deviates from the group spec by taking `&RepoFacts` — `apply` has already read the status, and a second `ls-files -u` could disagree with the `check` that just ran.
- `prepare_restart` / `run_restart_prep` (fns, crate-private) — the two halves of `d` after `⏎`. `prepare_restart` runs **before anything is written** (a refusal leaves no trace): it asks `restart_source` (refusals as there), then refuses `RestartChanged` when the plan's kind differs from `params.kind` (m6-conflicts/58). `run_restart_prep` does the write (`restore_stages`), **after** the before-snapshot or the chained backup, so what `u` puts back is the resolution being started over from, not the stages restored over it. Its command line goes into the entry's Command Log ahead of the plan's (m6-conflicts/08).
- `restart_gate` (fn) / `RestartPlan` (struct) / `RestartReadError` (enum) / `restart_source` (fn, crate-private) — `d`'s gate as a read (m6-conflicts/28). `restart_gate(repo, &RepoFacts, path) -> Result<Result<RestartPlan, Refusal>, RestartReadError>`; `RestartPlan { source: StageSource, kind: RestartKind }` (m6-conflicts/58). It asks exactly what `apply(RestartConflict)` would: `operation::check_restart`, then `restart_source` — the one rule `prepare_restart` also matches on: `None` → `NoStagesKept`; `Index` → `Markers`; `Backup` stages through `shape_of_stages`: both sides → `Markers`, one side (`UD` `DU` `AU` `UA`) → `WholeFile`, `DD` → `NotMarkerShape`. No binary check: a binary `UU` chosen whole answers `Markers`, and `checkout --merge` puts its three stages back. **Read-only**: the journal is read with `journal::parse` from `journal_path`, never `Journal::open` (which cuts a torn tail); no ref, index or file is written. `RestartReadError::{Facts, Run, Journal, Io}` with `explain()` — the gate could not be asked, which the app shows as `can't start over · could not check: …`, never as a yes.
- `recover_interrupted` (fn) — close every entry left `Pending` by a previous run as `interrupted`, recording the repository as it stands now and sealing it behind that entry's backup ref; run at launch. Returns `Recovered`. An unreadable repository closes the entry with no after-state, which widens the inverse to the whole tree and makes `drift` say so (m3/03, review fix M1/C1).
- `Recovered` (struct) — `live: Vec<EntryId>` (m5/07: entries left `Pending` whose operation git's state says is **still under way** — recovery leaves those alone, the conflict banner takes them over) and `closed: Vec<EntryId>` and `unreadable: Vec<(EntryId, FactsError)>`: what recovery closed, and which entries it could not read a state for, with the reason (m3/03 review fix, M1); `plans_left: Vec<(EntryId, io::Error)>`: closed entries whose rewrite plan dir could not be removed (m7/02b); `set_aside: Vec<(EntryId, EditsAt)>` (30c): for each closed entry with a set-aside `S` still listed, where its edits are — `Stash { n }` when every tracked file equals `HEAD`, `Back { copy: Some(n) }` when the tree changed (the put-back's own judge); not listed → no row; a read failing → no row (the notice falls back to its older words).
- `left_at` (fn, crate-private, 30c) — `(ctx, stash, stashes, tracked_changed) -> Option<EditsAt>`: the rule above, pure over what recovery read.

## restore
`restore.rs` is the error type and `execute*`; `restore/outcome.rs` is the plan loop (`run_plan`, `outcome_of`) since 30h; `restore/rollback.rs` is the cancel half (`Before`, `Settled`, `roll_back_after_stop`, `roll_back`, `reverse_of`, `settled`, `uncancellable`); `restore/steps.rs` is the one `git` per `Step` and the reads that scope it. No public surface moved (m5/06 review fix M5).
- `RestoreError` (enum) — `RefMoved { name }` (a compare-and-swap refused, before any file was touched; matched on git's `but expected`/`reference already exists`, not on a lock message another process shares), `StashGone { commit }` (only when git ran and refused), `Run`, `Facts`, `Snapshot`, `Journal { error, after }`, `AfterState { applied, unread }`, `Cancelled { rolled_back }` (stopped and fully put back: `undo cancelled · nothing changed`), `CancelledPartway { applied, rollback }` (stopped, roll-back refused; `applied` names what is still in force, newest first: `undo cancelled part-way · <what> · U restores the backup` — **`U`, not `u`**: the entry is an in-force `Undo` entry, which `next_undo` steps over and `next_redo` reaches (m5/06 review fix M2)), `FailedPartway { failure, applied, rollback }` (a step failed and the roll-back of what had run could not finish: `<failure> · rolled back part-way · <applied> still changed: <why> · U restores the backup`; m7/01a, gap :496), `BadRefName { name, reason }` (a plan's `UpdateRef`/`SetHead` name fails `RefName::new` or is not under `refs/`; checked before `begin`, so no entry, no backup, nothing written; m7/01a, gap :497), `NoBefore { field }` (the entry's own before-state does not record the field the roll-back needed; **no longer reachable for an unmerged index**, which now has a state of its own — it stays for refs, m6-conflicts/08); `explain`, unsanitised like `ApplyError::explain` (m3/03, review fix Minor 1/6/7; the three cancel variants m5/06). **A stop leaves restore and undo in one shape** (m7/01b, gap :495, planner ruling): `Cancelled { rolled_back }` — `rolled_back: 0` for a stop before any step (before or inside `begin`, or in `undo`'s rails; an entry only if `begin` wrote one) — or `CancelledPartway`. The `Stopped` variant is gone. Inside, every stop folds into crate-private `STOPPED` (`Run(RunError::Stopped)`; `from_facts`, `From<PrepareError>`), never seen outside.
- `RestoreError::MergeState(MergeStateError)` (m6-conflicts/20) — `SetMergeState` failed; a stop inside it folds into the crate-private stop, then `Cancelled`. Its roll-back is `SetMergeState(<the entry's merge_before>)`.
- `restore_stages` (fn) — one path's recorded stages put back, and nothing else: no plan, no entry, no backup, error set exactly `SnapshotError`'s. The only caller is `d` after `⏎` (`apply::run_restart_prep`), which is inside an operation of its own and has already taken both. It exists because `Operation::plan` returns `Vec<Invocation>` — a pure description of what git will be asked to do, with nowhere to put a recorded tree or the stdin it needs — and growing `Invocation` to carry stdin would let every later operation smuggle state through its plan (m6-conflicts/08 scope 5(c); the design call is the conductor's).
- `execute` (fn) — run an `InversePlan`, journaled as its own entry with its own fresh backup (§6.4). Its `Applied.refresh` is `Everything` whenever a ref moved **or `HEAD` did** (a `SetHead` step, a recorded `head_before` ≠ `head_after`, or an unread `head_after`) — a checkout's undo touches no ref (m6-conflicts/79). `UpdateRef` compare-and-swaps (an absent expected side is git's empty old value, not an all-zero id of a guessed hash length); `SetHead` is `symbolic-ref` or `update-ref --no-deref`; `RestoreIndex` is one `update-index -z --index-info`, never `read-tree` on the real index and never `checkout --merge` (the stages come out of the recorded tree, so nothing replays a merge) — per path a **mode-0 removal record first**, then one `<mode> <oid> <stage>` record per entry the recorded state holds, which is the documented rule for placing higher-stage entries and without which stale stages survive; `RestoreWorktree` splits the paths four ways (tracked → `restore --source`, untracked-and-in-the-tree → a temporary index plus `checkout-index`, untracked-and-absent → `clean -f`); `StashStore` scans the reflog first (git's own `stash store` duplicates a commit already at `stash@{1}`) and uses the commit's subject, which is byte-identical to git's reflog message; `StashDrop` is a no-op when the reflog lacks the commit, which is what makes an aborted pop undo correctly (m3/03).
- `execute_over_drift` (pub(crate) fn, m6-conflicts/77) — `execute` for a run forced past drift: the replaced-read's command lines head the entry's Command Log, and `replaced` rides on the `Applied` (the `AfterState` one too). `execute` is it with nothing read and nothing replaced.
- `execute`, the stop (m5/06) — `ctx.stop` is checked **before every step**, not only the first, and a stop **rolls back what already ran** (ADR-0037 §6): a half-applied undo is worse than none. The roll-back reverses the applied steps newest first from the entry's **own** before-fields and backup ref, both taken by `begin` before step one — `UpdateRef` compare-and-swapped against what the step itself wrote (a refusal means something outside Graft moved it: reported, never clobbered), `SetHead` from `head_before`, `RestoreIndex`/`RestoreWorktree` from `index_before`/`worktree_before` over the *same* paths the forward step had, `StashStore`/`StashDrop` each other. It runs against `&()`: a cancel of the cancel is not offered. Outcome `Aborted("cancelled")` with the after-state read fresh (so it equals before, `in_force` is false and `next_undo` is unchanged), or `Aborted("cancelled — rollback failed: …")` with the real half-way after-state, which `in_force` and `drift` then report and the backup ref covers.
- `execute`, a step that **fails** (m7/01a, gap :496) — rolled back like a cancel (`rollback::roll_back_after_failure`, uncancellable): every step that ran is reversed newest first, plus the failed step itself unless it is an `UpdateRef` (atomic in git; its compare-and-swap reversal would misreport drift). Clean → the step's own error, entry `Aborted` and not in force; refused → `FailedPartway`, entry reason `<failure> — rollback failed: <why>`.
- `execute`, a step git was killed inside (m5/06) — whether it landed is not knowable from the error, so the repository is read: only `UpdateRef` needs asking (its reversal is itself a compare-and-swap, so a wrong guess would report drift that is not there), and the ref reading as neither the step's target nor the restore's own before-value is `RefMoved` — reported, with **nothing written on a guess**. A ref the entry's before-state does not record at all reads as `NoBefore`, the same as in `reverse_of`, rather than as "it did not exist" (m5/06 review fix Minor 1). Every other reversal is idempotent by construction, so a step that may not have run is simply reversed.

## undo (execution half)
- `UndoError` (enum) — `Nothing(NotInvertible)`, `Drift { drift: Box<Drift>, direction: Direction }` (`Direction { Undo, Redo }`, m7/01b gap :494: `explain` ends `u again` or `U again` to match; boxed since m6-conflicts/77: `Drift::replaced` pushed it past `result_large_err`), `Restore`, `Facts`; `explain` (m3/03).
- `revert_to` (fn) — `(ctx, target, force)`: run `plan_revert_to`'s steps newest first, **one journaled `Undo` entry per step** with its own backup, so `U` walks the revert back one operation at a time. The stop is checked between steps; what already ran stays (it is journaled and undoable) rather than being rolled back by a second unasked-for write (m5/07).
- `UndoError::PartWay { done, error }` (m5/07) — a revert that stopped part way: what had already run, and why the next step did not.
- The undo gate (m6-conflicts/57, private `refuse_while_live`, in `run_plan` between `read_state_now` and `drift`, so `undo`, `redo` and every step of `revert_to` pass it) — while git has an operation in progress, the entry is reversed only when its `merge_after` names the merge standing now (same `MERGE_HEAD` and other heads); otherwise `Nothing(NotInvertible::OperationLive { kind })`, nothing written, no drift box, `force` does not pass it. A bisect is let through (not an operation Graft ends). `MergeDrift::Begun` is no longer reached from this path.
- `undo` / `redo` (fn) — plan the inverse, read the repository now, compare (§6.7), and run it. An unmerged index — what a stash pop that conflicted leaves — is recorded as its stage tree and compares equal to itself, so undoing one needs **no `force`** and the stages and markers come back exactly (m3/03; m6-conflicts/08, which retired the old "reads as index drift; forcing past it still works").
- `run_plan`'s replaced-read (m6-conflicts/77) — right after `drift`, and only when it is not clean: `Drift::replaced` is filled before the refusal (so the box can name it) and again on the forced run (the tree may have changed between); a clean undo spawns no `diff-tree` (`a_clean_undo_spawns_no_diff_tree`).

## preview
Ghost Preview's planner: what an operation *would* do, drawn before it runs. One `Operation` serves both — the same value is previewed and applied, and `check`'s `Moved` refusal is what keeps the picture and the act the same act (design note hard choice 3).
- `PreviewPlan` (struct) — `description` (the operation's own), `commands` (`plan`'s lines, never a second rendering), `ghosts`, `ref_moves`, `head: Option<HeadMove>`, `worktree`, `conflicts`, `undo`, `against: Vec<Tip>` (what to re-check before confirming) (m5/07), `set_aside: Option<SetAside>` (`op.sets_aside(facts)`, m6-conflicts/73; for a put-in or absorb `files` counts only the unstaged files, the part put back, 0 when none — review m7-09..21c Minor 6), `files: Option<FilesEffect>` (a put-back only, m7/23: `preview::recover`; `None` otherwise), `put_back: Option<ConflictForecast>` (edits aside only: would putting them back clash — `preview::put_back::forecast`: `stash create` on a scratch copy of the index, the landed tree (a checkout's target; a rebase's replay by `merge-tree` + `commit-tree`; a cherry-pick's commits each replayed from its own parent, m7-power-tools/11a), then the m5 forecast; `NotChecked` on git < 2.40, when the rebase may stop first, or on a read failure; writes no ref, index or file; m6-conflicts/84).
- stash apply / pop (m6-conflicts/86, `preview::stash`) — `worktree`: `Updated` with the stash's changed paths plus its untracked ones (`stash^3`), capped; `conflicts`: `merge-tree --merge-base=stash^1 <ours> <stash>`, ours = the **index** tree (`write-tree` on a scratch copy of the index, then a scratch commit), `Clean`/`Likely{paths}`; `NotChecked` on git < 2.40 or an unmerged index. `IndexOnly { paths, more }` (`stash^1`→`stash^2`) when the stash changes only the index (87). A file the index doesn't track, on disk where the stash writes (ignored files included), is refused `StashInTheWay { untracked, ignored }` by `plan` and at `y` by `apply`, both from `in_the_way::blocking` (m7/28a; an ignored one tagged `(ignored)` with `move it aside first` since 28c). **git's `--index` rule first** (87): when `stash^2`'s tree differs from both `stash^1`'s and the index-now tree, `diff-tree --binary stash^1 stash^2 | apply --cached --check` on the same scratch index copy; failure refuses `StashIndexNoLongerApplies`, never `Clean`/`Likely`. Writes no ref, index or file.
- `EditsAt` (enum, m6-conflicts/84) — where a failed set-aside left the edits: `Stash { n }` (not in the tree; listed at `n`), `Back { copy: Option<usize> }` (in the tree; a copy stays listed, or was not found), `Backup { copy: Option<usize> }` (stored, then the reset failed or stopped: the entry's backup has them). `words()` is `graft-ops`' own clause, no keys. `ApplyError::edits_at()` reads it. Derives `Clone, Copy, Debug, PartialEq, Eq`; not serialised (also `Recovered::set_aside`, 30c).
- `PreviewPlan` m7/05 fields — `already_in: Option<DropSuggestion>` (a rebase whose bottom branch is already on `onto`), `published: Vec<RefName>` (branches whose upstream holds a commit this rewrites: one `for-each-ref`, then `rev-list --ignore-missing <upstream> ^<onto>` per branch with one), `messages: Vec<(Target, String)>` (a rewrite's written messages, squash groups joined by git's default).
- `ConflictForecast::StopsAt { step, of, commit, paths }` (m7/05) — the chained forecast's first conflict: `step` counts every todo row as `rewrite::progress` does; nothing past it checked. Rebase and `Operation::Rewrite` plans chain (`preview::chain`: `merge_tree_step`, each clean tree a `snapshot::scratch_commit`, no ref); a step whose parent is the result so far fast-forwards without a spawn.
- `suggest_drops` (fn, m7/05) — `(repo, git, &BranchLine, onto, stop) -> Result<Option<DropSuggestion>, FactsError>`: the bottom branch's `diff split tip` patch-id against each of `split..onto`'s (`patch-id --stable`, no renames/colour/ext-diff). `DropSuggestion` = `Drop(AlreadyIn { branch, commits, matches, subject })` or `NotChecked(why)` (past `DROP_CHECK_CAP` = 200 commits). Wired into no `Operation` yet: the engine side is blocked (ticket 05 NOTES).
- `Target` (enum) — `Real(Oid)` (a commit that exists) or `Ghost(usize)` (an index into `ghosts`): how a row points at a commit that is not written yet (m5/07).
- `GhostCommit` (struct) — `oid` (synthetic, see `ghost_oid`), `parents: Vec<Target>`, `subject`, `author: Identity`, `replays: Option<Oid>` (the real commit a rebase or pick row is a copy of) (m5/07).
- `RefMove` (struct) — `name`, `from: Option<Oid>`, `to: Option<Target>`; `to: None` is a ref that goes away (m5/07).
- `HeadMove` (enum) — `ToBranch(String)` or `Detached(Target)` (m5/07).
- `WorktreeEffect` (enum) — `Untouched`, `Updated { paths, more }` (rewritten on disk; `more` when past `PATHS_CAP`), `IndexOnly { paths, more }` (only the index changes — a stash whose one change is staged; m6-conflicts/87), `Lost { paths }` (a `--hard` reset over changed tracked files — recoverable from the entry's backup, which is why its `undo` note still says `Undoable`), `RestoredFromBackup` (the time machine), `EditsStay` (a switching branch-create at `HEAD`'s commit over edits: nothing is set aside and index and files stay byte-equal; the app draws `your edits stay as they are`, m7-power-tools/10b), `NotShown { why }` (files **will** change and which ones could not be worked out — deliberately neither `Untouched` nor an empty `Updated`, both of which read as "nothing happens to your files"; it names the hole the way `ConflictForecast::NotChecked` does, m5/07 review fix M3) (m5/07). **One rule decides which pair is diffed** (`preview::Landing`, m5/32): the effect names the files that differ between the tree `HEAD` has now and the tree it will have once the operation lands — `At` when the landed tree already exists (fast-forward, checkout, hard reset, branch, branch-from-stash), `Joining` for a merge or rebase (the fork point against the incoming side, never the two tips), `Replaying` for a cherry-pick or revert (each commit against its own first parent).
- `ConflictForecast` (enum) — `Clean`, `Likely { paths }` (**may** conflict, never *will*: `merge-tree` forecasts one merge, and a rebase or pick replays commit by commit, so a later one can still stop), `NotChecked(String)` with the reason (git too old, or past `FORECAST_CAP`). A hole beats both of the others when forecasts are folded: absence of evidence is not a clean bill (m5/07, design note hard choice 5).
- `UndoNote` (enum) — `Undoable` or `NotUndoable(String)` saying why in the user's terms; a re-push's says plainly that it rewrites the remote for everyone who has already pulled it (m5/07, ADR-0038 §4).
- `FORECAST_CAP` (const) — 50: more commits than that and the forecast is `NotChecked` rather than 50 spawns (m5/07).
- `ghost_oid` (fn) — `sha1("graft-ghost\0<subject>\0<n>")` (the subject git would give the commit, not the operation's description — m5/07 review Minor 2 corrected the doc, not the code): stable for one plan, distinct per row, and **never written to the object database**. It exists so the renderer can key a row like any other commit (m5/07).
- `plan` (fn) — `(repo, git, op, facts, stop)`: the picture for one operation. **Runs `op.check(facts)` first**, as `apply` does: `Err(Refused(r))` exactly when `check` is `Err(r)` (m6-conflicts/67: no `[ Confirm ]` for a write `apply` refuses). One exception to "exactly": a stash apply or pop whose `TouchesChangedFiles` covers an unsaved or untracked path is refused as `StashInTheWay { unsaved, staged, untracked }` instead — the staged-only rest of check's list named beside them (m6-conflicts/86, 87). **Then, before any forecast, `in_the_way::blocking`** (m7/28a, ADR-0049): files git doesn't keep where the write puts its own refuse `InTheWay` (stash kinds: `StashInTheWay`) — the same read `apply` repeats at `y`, so a preview refusal and an `apply` refusal agree. Reads only; the ghosts come from `commits_between` (`replayed_commits` for a rebase, so the ghost count is git's commit count — m5/43) and `merge-tree`, the author of a commit git would write from `git var GIT_AUTHOR_IDENT`. Refuses with `PreviewError::Refused(Refusal)` for the things only a read can find — a re-push whose commit is not on its branch, an `--ff-only` merge of diverged branches (m5/07).
- `plan_as_run` (fn, m7/05b) — `(repo, git, op, facts, stop) -> Result<(Operation, PreviewPlan), PreviewError>`: the op as `y` will run it, and its picture — the preview job's entry for every `Operation` subject. A `Rebase`: `check`, `line_of` (fork / elsewhere / git-too-old → `Refused`), `suggest_drops`, `line` and `drops` written (drops kept only where `rebase_rows` has a row: a commit git already leaves out has none), then `plan` over the completed op (facts gain the dependents' tips) with `already_in` set. Every other kind: `op` back unchanged, plus `plan`. A rebase's put-back forecast reads the chain's landed commit (drops skipped) when the chain is clean.
- `plan_revert_to` (fn) — `(entries, target)`: the time machine's picture, drawn from the very `InversePlan`s `undo::revert_to` will run, so the picture and the act cannot disagree (m5/07).
- `PreviewError` (enum) — `Facts`, `Read(RunError)`, `Refused(Refusal)`, `Stopped`; `explain` (m5/07).

## rewrite (m7/02, ADR-0047)
- Every rewrite and every `r` runs git's `rebase -i` on a todo Graft writes; branches built on his follow on one line. Planned here; run by `apply::engine` (rewrite-engine-b), proven against hand-run `git rebase -i` by `tests/it/rewrite_oracle.rs`.
- `TodoAction` (enum) — `Pick Reword Edit Squash Fixup Drop`; `word()`, `melds()` (squash/fixup), `keeps()` (pick/reword/edit), `from_word()` (long and one-letter).
- `TodoLine` (struct) — `action`, `commit: Oid`, `subject`.
- `BranchLine` (struct) — `branches: Vec<Tip>`, his first, bottom up; `top()`, `dependents()`.
- `RewriteParams` (struct) — `head: Tip`, `onto`, `todo` (his rows, oldest first), `line`, `messages: BTreeMap<usize, String>` (row → whole message), `made: Vec<Oid>` (commit objects written from the index), `index_base: Option<Oid>` (absorb only, 06b: `HEAD` + every placed hunk as a commit with no ref; pinned; saved in the rewrite's `plan.json`; when the rewrite went through and `HEAD`'s tree is its tree, the set-aside puts the edits back with `stash apply --index` of `S` rebuilt on it — stays stay staged, index-only and mode-only ones included, and an edit made on past a placed hunk merges clean; otherwise ADR-0045's plain put-back).
- `RewriteRequest` (enum) — `Open { from }` (`R`), `AmendInto { target }` (`a` on an older commit), `Absorb` (m7/06), `FromRebase(RebaseParams)` (`R` in a rebase preview, rebase-preview-keeps-drops: the as-run params `plan_as_run` filled).
- `RewriteError` (enum) — `Refused(Refusal)` (Display = `explain()`), `Facts(FactsError)`, `Stopped`.
- `plan` (fn) — `(repo, git, req, facts, default_branch: Option<&RefName>, stop)`; `default_branch` is the app's `graph.default_branch` override, `None` to resolve it (m7/02b). Open: `HEAD` down to the merge-base with the upstream's tracking tip (else the default branch), deeper to `from` if it is; the repository's first commit is never a row (it becomes `onto`). Autosquash rows come back marked and moved; a squash group gets `default_message`. AmendInto: `write-tree` + `commit-tree -p HEAD` (`fixup! <subject>`), a `Fixup` row after the target, `onto = target^`; a target other than `HEAD` must be in `your_commits` (every base, 06e ruling), else the walk's stop refuses: `Pushed` → `AlreadyPushed`, `Base`/`NotItsOwn` → `NotOnYourBranch`, `Merge(m)` → `MergeInRange { m }`, `Root` → `RootCommit`, `Cap` → `BeyondReach`; `HEAD` skips the range check (amend, whatever a remote holds, 06e ruling 5). Refusal order: `NotOnABranch`, `NothingStagedFor`, `NotOnYourBranch`, (the walk's stop, 06c/06e), `RootCommit`, `MergeInRange`, `ForkedDependents`, `DependentElsewhere`, `GitTooOld` (only with dependents), `PlainAmend`. Absorb (m7/06): the range is `your_commits` (06e), refused when it is empty: `AllPushed` (`HEAD` pushed), `NoCommitsOfItsOwn` (the base is `HEAD`, not the default or only branch, 06f), or `MergeInRange`/`RootCommit` when `HEAD` is a merge or the first commit; `absorb` places the hunks; each target's hunks → one `commit_pieces` commit (`fixup! <subject>`, parent `HEAD`) as a `Fixup` row right after it; rows start at the oldest target, `onto` = its parent; none placed → `NothingToAbsorb`; then `MergeInRange`, `ForkedDependents`, `DependentElsewhere`, `GitTooOld`.
- `plan`, `FromRebase(params)` (rebase-preview-keeps-drops): `head_of` (detached → `NotOnABranch`); `HEAD` ≠ `params.branch` (name or oid) → `Moved { name: branch }`; `todo` = `rebase_rows(onto_tip, branch)` oldest first, `Pick` but `params.drops` → `Drop` (a drop with no row → `Moved`, as the engine refuses it); `onto = onto_tip`, `line = params.line` as-is; no autosquash, no range walk, `messages`/`made` empty, `index_base` `None`. Unedited = the rebase's own todo (`rewrite::plan::tests::from_rebase_unedited_matches_the_rebase_todo`).
- `dependents` (fn) — local branches containing the tip whose first-parent chain reaches it with no merge; not his, not the default branch (`Branches::resolve(repo, default_branch)`: signature `(repo, git, branch, default_branch: Option<&RefName>, stop)`, m7/02b), not at the same commit (a backup). Sorted by chain length; each must contain the one below, else `Dependents::Fork { a, b }`. Checked-out-elsewhere branches stay in (plan refuses them).
- `Dependents` (enum) — `Line(BranchLine)` | `Fork { a, b }`.
- `squash_groups` (fn) / `SquashGroup` (struct) — `kept` + `melded` (newest first); a meld passes over dropped rows.
- `default_message` (fn) — kept row's message, blank line, each melded `Squash` row's message newest first; fixups add nothing.
- `validate` (fn) / `TodoProblem` (enum) — `MeldsIntoNothing { row }` (`nothing below to meld into`), `EverythingDropped`; `explain()`.
- `progress` (fn) / `RewriteProgress` (struct) — from `rebase-merge/{done,git-rebase-todo,head-name}` + the saved plans: `step` counts pick-like rows only (git's `msgnum`/`end` count `update-ref` lines too: measured 4/6 vs 3/4, git 2.54), `current`, `pending` (oldest first), `branch: Some((name, i, n))` only for a line of 2+ (i = 1 + `update-ref` lines done), `begun_in_graft` = a saved plan whose top is `head-name`. Short ids resolve via `rev-parse`. `followers: Vec<Follower>` (m7-power-tools/07d): the line's branches above the current one, bottom up, each's pick-like todo rows counted between `update-ref` boundaries and its tip author from `plan.json`'s tip (one `git log --no-walk` spawn); empty when `branch` is `None`. A read failure is `Err`, never partial followers.
- `RewriteProgress::pending_here` (fn) — `pending` minus the followers' rows: this branch's rows still to apply, oldest first (07d).
- `Follower` (struct) — `branch` (no `refs/heads/`), `tip_author`, `commits` (07d).
- `edit_stop` (fn) / `EditStop` (struct, m7-power-tools/07a) — `(repo, stop) -> Result<Option<EditStop>, FactsError>`: `Some` iff `rebase-merge/amend` exists (git writes it at an `edit` stop only; verified against git 2.54.0 by `git_writes_rebase_merge_amend_at_an_edit_stop`) **and** the last commit row of `rebase-merge/done` is `edit`. `EditStop { stopped: Oid` (amend's id), `head_on_it: bool` (HEAD's first parent == stopped's: HEAD is it or an amend of it; one `rev-list --no-walk=unsorted --parents` spawn) `}`.
- The plan dir (crate-private `rewrite::saved`) — `<git dir>/graft/rewrite/<entry-id>/`: `plan.json` (`home`, `line: [[name, tip]]`, `onto`; a format contract — a relaunch reads what an older Graft left), `todo`, `messages/<full id>`, `editor` (the `GIT_EDITOR` helper keyed by the last line of `rebase-merge/done`). `CLEANUP` = `commit.cleanup=whitespace` via `GIT_CONFIG_*` env. Saved before the `Pending` line; removed when the entry closes — by `apply`, `resume`, or `recover_interrupted` (m7/02b).
- `absorb_plan_map` (fn, 06c) — `(repo, facts, default_branch, stop) -> Result<AbsorbMap, RewriteError>`: the map over the very range `plan`'s absorb uses (lines below it stay by the walk's stop: `Pushed` → `AlreadyPushed`, `Base` → `BeforeYourBranch`, else `OutsideYourCommits`, 06e); what the absorb preview lists.
- `ABSORB_FALLBACK_DEPTH` (const, 06c) — 10: git-absorb's reach, on the default or only branch, or a branch with no base (06f).
- crate-private `rewrite/unpushed.rs` (06c, rewritten 06e): `your_commits(repo, head, default_branch, stop) -> YourCommits { base (parent of the oldest taken; `HEAD` if none), commits (first-parent, newest first), stop: RangeStop }` — walks down from `HEAD`, stopping at each commit in order: reached by `refs/remotes/*` → `Pushed`; the base (`base_of`, when below `HEAD`) → `Base`; a merge → `Merge(oid)`; the root → `Root`; only with no base below `HEAD`, 10 taken → `Cap`. Entry (06f), in order: 1. a base below `HEAD` → the walk with `Base`; 2. else the default branch (override included) or the only local branch → the fallback; 3. else a base that is `HEAD` → `NotItsOwn` (unless `HEAD` is pushed → `Pushed`); 4. else no base (orphan branch, no shared history) → the fallback. One `rev-list <chain> --not --remotes` read. Absorb and AmendInto both call it; `R`, `base_of` and `default_branch_of` are unchanged.
- Files (review 02 Major 3): `rewrite/plan.rs` (requests → params, refusals; `head_of`), `rewrite/absorb.rs` (absorb's base, plan and rows, 06c), `rewrite/dependents.rs` (`dependents`, `line_of`, worktree check, `UPDATE_REF_GIT`), `rewrite/reads.rs` (raw history reads: ranges, picks, messages, base, `commit_index`); `apply/resume/rewrite.rs` (the resume's rewrite helpers: `started_on_its_line`, `resume_invocation`, `stopped_on_edit`).
- `RewriteKey` (enum, review 02 Major 2) — `Open` (`R`), `AmendInto` (`a`); `what_it_does()` → `R rewrites your branch` / `a puts staged changes into a commit on your branch` (note R1/R2); `key()` → `R` / `a` (06c).
- `Refusal` additions (m7/02) — `NotOnYourBranch { commit, by: RewriteKey }` (`<by.what_it_does()> · <short> isn't on it`), `MergeInRange { merge }`, `ForkedDependents { a, b }`, `DependentElsewhere { branch, worktree }`, `NothingStagedFor { target }` (the unit `NothingStaged` is the commit's), `NotOnABranch`, `GitTooOld { need }`, `PlainAmend`, `RootCommit { commit }`, `BadTodo(TodoProblem)`, `NothingToAbsorb` (m7/06: `none of your staged lines belong to a commit on your branch · c commits them`), 06c: `AllPushed { branch }` (`every commit on <branch> is already pushed · absorb only changes unpushed commits · c commits them`), `AlreadyPushed { commit }` (`a` only; `by` dropped, 06e: `<short> is already pushed · a only changes older commits you haven't pushed`), `BeyondReach { commit, branch }` (06e: `<short> is more than 10 commits back · on <branch> a reaches the last 10 unpushed commits`), `NoCommitsOfItsOwn { branch }` (06e, absorb: `<branch> has no commits of its own yet · c commits them`); words in `explain()` (R1's where the note has them).

## absorb (m7/06)
- Each staged hunk goes to the commit in `base..HEAD` that last changed its lines; one that fits none stays staged. Reads only; `tests/it/absorb.rs` (placing rows), `absorb_oracle.rs` (the tree oracle), `absorb_printed.rs` (its independent reads: porcelain diff, and each target by `git log -L`, not the code's blame, 06c), `absorb_config.rs` (his config, submodules), `absorb_unpushed.rs` (the fallback range), `absorb_pushed.rs` (the pushed stop on every base, 06e), `absorb_orphan.rs` (a branch with no base falls back, 06f). Files (06c): `absorb/mod.rs` (types, `mapped`), `absorb/read.rs` (diff, blame, file reads), `absorb/judge.rs` (`verdict`, `commutes`), `absorb/build.rs` (patches, trees, commit objects); crate-private `objects.rs` (06d: `resolve` = `rev-parse --verify`, `commit_tree`, `printed_oid`; the set-aside rebuild uses all three, absorb only `resolve` — it writes commits with `-F -`).
- `StagedHunk` (struct) — `path`, `old`, `new`: `Range<u32>` as git's `-U0` header says them (`start..start+count`; an empty side sits at the line it follows).
- `StaysWhy` (enum) — `NoCommitChangedIt` (binary/mode-only, insertion at the top or bottom of a file), `TwoCommitsChangedIt` (2+ commits, or the commutation check failed), `NewFile`, `BeforeYourBranch` (every line blamed below the range), `Renamed` (both sides of a staged rename; `-M` detects no copies, 06b/06d), `Submodule` (a gitlink on either side, found by a `diff-index --cached --raw -z` read, 06c), `OutsideYourCommits` (below a merge or the fallback's cap, 06c), `AlreadyPushed` (06e: the range stopped at a pushed commit; words, 09 renders: `stays staged · the commit that changed these lines is already pushed`).
- `AbsorbMap` (struct) — `placed: Vec<(StagedHunk, Oid)>`, `stays: Vec<(StagedHunk, StaysWhy)>`. Every stay is still staged after the absorb (06b, `RewriteParams::index_base`); `stays_unstaged` removed.
- `absorb_map` (fn) — `(repo, git, head: &Tip, base, stop)`. `diff-index --cached -p -U0 -M` (renames read as renames, both sides stay; plumbing: porcelain `diff` refreshes the index); per file one `cat-file blob` and one `blame --porcelain --no-ignore-revs-file -L… <base>..<head>` (his `blame.ignoreRevsFile` dropped, 06c); old lines (an insertion: the lines above and below) all one commit in the range → it. Commutation: the hunk, with one line of `HEAD` context either side, must `apply --cached --check --whitespace=nowarn` on the target's tree (temporary index, `snapshot::TempIndex`), else `TwoCommitsChangedIt`; any exit but 1 is an error, never a stay. Every `apply` pins `--whitespace=nowarn`: his `apply.whitespace` never changes what goes in (06c).
- crate-private: `mapped` (the map with each hunk's patch; `below`: the reason for lines older than the range), `commit_pieces` (`HEAD` tree + pieces, bottom of each file first, on a temporary index → `commit-tree -p HEAD`), `empties` (target + its pieces = its parent's tree: the plan drops the target instead of a fixup git would stop on, 06b; when every row would be a drop, the commit below joins as a pick); `snapshot::TempIndex` and `snapshot::path_of` are now `pub(crate)` for it.

## mistake_radar::probes
- `EvilVerdict` (enum) — `Clean`, `Resolved { files }` (the remerge diff differs only in files both sides changed: a hand-resolved conflict, never a finding), `Evil { files }` (files only one side, or neither, touched since the merge base), `NotCheckable(String)`.

## journal_list (m7/22, ADR-0046)
The journal and git's reflog as one list: `●` Graft, `$` the shell, `✗` lost. Three stages so `J` never waits.
- `RECORDS_CAP` (2000), `LOST_CAP` (500), `PAIR_WINDOW_SECS` (2: a `HEAD` record and a branch record with the same old/new this close are one step), `BACK_LIMIT` (100: "N commits back" counted this far) (consts).
- `OutsideRecord` (struct) — `record: ReflogRecord`, `back: Option<usize>` (reset: new's distance back from old; fast-forward: old's back from new).
- `OutsideStep` (struct) — `record` (the branch's record when paired; the finish when a rebase folded), `words`, `folded`.
- `HeldBy` (enum) — `Branch { name, gone }`, `Head`. `LostCommit` (struct) — `run: LostRun`, `subject: Option<String>` (`None`: the tip could not be read; drawn by its sha alone, m7/30o), `held_by`. `LostEdit` (struct) — `entry`, `backup_tree`, `paths`.
- `ListRow` (enum) — `Graft(EntryId)`, `Outside(OutsideStep)`, `Lost { event, commit }`, `LostEdit { event, edit }` (`event` indexes `rows`). `LostScan` (enum) — `Running`, `Done`, `Capped { checked }`, `Failed(String)`. `JournalList` (struct) — `rows` (newest first, lost rows right after their event), `scan`.
- `read_outside(repo, cap, stop) -> Result<Vec<OutsideRecord>, FactsError>` (fn) — stage 2's read, through gix.
- `find_lost(repo, entries, outside, cap, stop) -> Result<Unreached, FactsError>` (fn) — stage 3: candidates are records' olds and entries' `HEAD`/`refs/heads/*` befores, newest first, once each, through `history_reads::unreached`.
- `build(entries, outside, lost, subject_of, branch_exists, edits, scan) -> JournalList` (fn, pure) — folds a shell rebase's records into one row, drops records that moved nothing (not a `checkout:`), pairs `HEAD`/branch twins, claims a Graft entry's records for its `●` row, places each lost run under the newest event whose old values held its tip.
- `words(record, back) -> String` (fn) — the J1 table (`committed "X" on main`, also from `commit (initial): X` since m7/24-a, `reset main 1 commit back`, `switch from a to b`, …); an unknown subject is git's own.
- `lost_edits(repo, entries, stop) -> Result<Vec<LostEdit>, FactsError>` (fn, m7/23) and `LOST_EDITS_CAP` (50) — the newest 50 in-force undo/redo entries with a backup: a path is lost when the backup differs there from the reversed entry's after-state (his drift) **and** from the entry's own after-state (it wrote there) **and** the file on disk differs from the backup (one `worktree_tree` read, then `diff-tree`s). Newest first. Undo/redo only, by design (m7/30p R3): the copy a put-back replaces is never a lost edit — he chose it in the box; `u` or the put-back's own `●` row reaches it (pinned by `recover::a_put_back_leaves_no_lost_edit_row_and_u_brings_it_back`).
- `Recover` (enum) — `Run(RecoverParams)`, `OfferBranch { at, name, why }`. `recover_for(list, row, entries, facts) -> Result<Recover, Refusal>` (fn) — what `⏎` on a row puts back, or why not. `recover_scope(list, row) -> FactsScope` (fn) — the refs `recover_for` reads (the branch, `refs/remotes/<b>` and `refs/tags/<b>`, `<b>-restored`, `-2`…`-9`). A gone branch whose name a remote-tracking branch or tag has is never made again: `OfferBranch` `restored` instead (review m7-22 M1).

## submodule (m7/13a)
- `SubmoduleLog` (struct) — `pulled_in`, `rewound`: `Vec<(Oid, String)>` (id, subject), newest first, git's order; every commit (the 50 cap is the diff pane's).
- `submodule_log(repo, path, from, to, stop) -> Result<SubmoduleLog, FactsError>` (fn) — `git diff --submodule=log`'s walk (`from...to`, left-right, first parent), run as `git --git-dir=<path>/.git log`, so the ids are taken directly and a submodule not set up is never read as the superproject. Not set up and a commit not held are both `History(Exited { status: 128, .. })`, measured.

## switch_list (m7/10c)
- `SwitchKind` (enum) — `Local`, `RemoteOnly { remote, local }`. `Relation` (enum) — `Tracks(ref)` (upstream under `refs/remotes/`), `BuiltOn(ref)` (under `refs/heads/`), `None`.
- `SwitchRow` (struct) — `name, kind, tip, subject, author, when, relation, current`. `SwitchList` (struct) — `previous: Option<SwitchRow>` (`↩ before`, not repeated in `rows`), `rows`.
- `switch_list(repo, stop) -> Result<SwitchList, FactsError>` (fn) — `graft_git::switch_refs` + `head` + `remote::list`. Rows: previous (`@{-1}`, when not HEAD's branch) apart; then local newest tip first; then remote-only newest first; HEAD's branch (`current`) last. A remote ref is left out when a local branch's upstream is it, when a local branch has its local name, or **when no listed remote prefixes it**. Local name = ref less `refs/remotes/<remote>/`, `<remote>` the **longest** listed remote name prefixing it. Stopped → `FactsError::Stopped`.
- `filter_switch_rows(list, query) -> Vec<&SwitchRow>` (fn, pure) — empty query: previous then `rows`. Else case-insensitive over the short name; a match at the start or after `/`/`-` ranks above another substring; ties newest tip first; previous ranks like any row.
