- `context_menu` (mod) — the `.`/right-click popup: `ContextAction` (`Explain`, `CopySha`, `CompareWithThis`, `OpenDetails`, and — m5-03 review Major 1 — `Fetch`, `Pull`, `Push`, `Undo`, the keys the hint bar's width rule drops first, so `. more` leads somewhere; plus `History(usize)`, m5-history-and-ghost-preview/08 piece 6), `MenuItem` (`label` is `graft_term::SanitizedText`: a history verb names refs out of the repository, so every label goes through `sanitize_line`), `with_key(label, ActionId, &Keymap) -> String` (m8/10: `label (key)` from his keymap, `label` alone when unbound), `ContextMenu` (`for_row(marked, history, leading, dim_first, keys)` — `history` is `(label, Option<reason>)` pairs since m7-power-tools/11, as `for_drop` takes; a `Some(reason)` item is drawn and acts as `dim_first` does (`label — reason`, `DIM`, `ContextAction::Unavailable`, keeps its place; slot 2 `Cherry-pick (o) — already on main`); `dim_first` drawn disabled as `ContextAction::Unavailable` (never dispatched), then `history[..leading]`, then `Explain` if marked, then the row's own actions, then the rest of `history`, each a `History(i)` item carrying that label's index in the caller's own list, then `always_items(keys)` (m6-conflicts/71); No theme carried, so its `Widget` impl draws only labels and the reversed cursor row, the background painted by the caller (m2-details-and-diffs/12). Since m5-history-and-ghost-preview/10 it also carries a **drop menu**: `ContextMenu::title` (`Option<SanitizedText>` — `feature → main`, drawn bold on its own row above the items, so a menu opened by a gesture says what went where), `MenuItem::disabled` (`Option<SanitizedText>`, the reason a verb cannot run — the row draws `DIM` and reads `Merge feature into main — check out main first`, `REASON_SEPARATOR` being that ` — `), `ContextMenu::for_drop(title, verbs)`, `rows()` (items plus the title row, when there is one), `item_at(offset)` (which item a click at that offset in the menu's rect means — the title row belongs to nothing), `selected_refusal()` (the reason under the cursor, `None` when the verb can run). The **drop verbs themselves stay indices**: `for_drop` takes `(label, disabled)` pairs and the caller keeps the operations, the same `History(usize)` boundary `for_row` uses, because `ui` never imports `ops`.
- `confirm` (mod) — the confirm box, N choices now (m5-history-and-ghost-preview/04, ADR-0038 §1): `ConfirmView` (`title`, `message: Vec<SanitizedText>`, `command`, `choices: Vec<SanitizedText>`, `cursor: usize`) — `new(title, message, command)` opens two choices, `["Cancel", "Confirm"]`, cursor 0 (the safe default, never varies by danger level); `with_choices(labels)` replaces the choice list and resets the cursor to 0, for boxes with a real third answer (`u` after a push's `[ Cancel ] [ Undo locally ] [ Re-push old tip ]`, ADR-0038 §4); `with_labels(safe, confirm)` is a two-choice shim over `with_choices`; `left`/`right` move the cursor clamped at the ends (no wrap); `toggle` wraps `(cursor + 1) % len`, kept for the two-choice callers; `selected() -> usize`. `Choice` (the old two-variant enum) is **removed** — callers read `view.selected()` and compare against `view.choices`' index instead. `Confirm<'a>` widget now carries `theme: &'a Theme` (was theme-less) and draws its own cleared, rounded-border frame (`KNOWN_GAPS` row 484: it used to draw no frame at all, text straight onto whatever the caller left underneath — m4-07 Minor 2), title in the top border via `frame_box::border_row`, message/command/choices as `frame_box::content_row`s. `confirm_area`/`confirm_rows(view, width)` sizing helpers (`confirm_rows` now `wrapped.len() + 6`, +1 for the added border pair), `message` wrapped on spaces to `width` and capped at 4 lines (`…` on the rest) — `with_max_lines(rows)` raises one box's cap (the force-with-lease box, m7-power-tools/16b); a frame too short for the rows cuts message rows only, never the command or the buttons, the box never reaching the frame's own last (footer) row when it has more than one row (m3-working-tree-undo-and-stash/04; wrapping and footer clearance added m4-remotes/03, M3 review 06 Minor 11). `confirm_area_at(frame, view, x, width) -> Rect` (m5-history-and-ghost-preview/28, ADR-0040) — the same box at an x and a width the caller chose, for a layout site that has snapped it onto whole row columns; it re-takes the height at that width, because a wider box wraps the message into fewer lines. `confirm_area` is now this called with the centred x and natural width. The widget is unchanged and still knows nothing about where it was put.

## theme
- `LANE_COUNT` (const) — number of lane hues; lanes beyond reuse them.
- `TOKEN_COUNT` (const) — 18: PROMPT.md §5's twelve plus the six conflict roles.
- `TINT_ALPHA` (const) — 0.30, the one α every conflict tint is mixed at (ADR-0044 §1). Lives in `theme/conflict.rs` (m6-conflicts/64, a pure move) with `mix`, `Token::is_tint`, `Theme::tint` and the private pin table (`pinned`, `tints_dropped`, `reduce_conflict`); re-exported from `theme`, paths unchanged.
- `mix` (fn) — `fg` over `bg` at `alpha`, per channel, rounded; ties the tint literals to the rule.
- `contrast` (fn) — WCAG 2.x ratio of two `Rgb`s, `(L1+0.05)/(L2+0.05)`, symmetric (`theme/contrast.rs`).
- `ContrastRule` (struct) — one floor: `fg` token on `bg` token at `min`:1.
- `ContrastMiss` (struct, m8-16) — a floor missed: `rule` and the `ratio` reached. `words()` → `selection on bg 1.0:1 — under 3.0`, ratio floored to 0.1 (never rounds up to its floor).
- `contrast_misses` (fn, m8-16) — `(ThemeKind, &[(Token, Rgb)]) -> Vec<ContrastMiss>`: pure, on the pre-reduction table (built-ins with overrides written over), `CONTRAST_RULES` order; empty for every built-in (`theme/overrides.rs`).
- `CONTRAST_RULES` (const) — the four floors every theme passes: text/bg 4.5, text/selection 4.5, selection/bg 3.0, text-muted/bg 4.5.
- `Theme::legible_on` (fn) — `fg` unchanged if ≥ 4.5:1 on `bg`, else mixed toward white (dark bg) / black (light bg) in 5% steps until it is; target after 20 steps.
- `Theme::on_selection` (fn) — a `TokenColor` as drawn on this theme's `selection` (read from the theme's pre-reduction table, so an overridden `selection` drives the lift): truecolor `legible_on`; 256 lifts and judges each step after reduction to the palette; 16 colours / `NO_COLOR` / `Default` → `token(Text)`. What every cursor-row painter calls.
- `Token` (enum) — a chrome colour role; ends with the conflict roles `Ours`, `Theirs`, `Open`, `OursTint`, `TheirsTint`, `OpenTint` (named by pane position, ADR-0044 §1).
- `Token::ALL` (const) — every token, in PROMPT.md §5's order.
- `Token::name` (fn) — the token's name as PROMPT.md §5 and config spell it.
- `Token::from_name` (fn, m8-16) — inverse of `Token::name` over `Token::ALL`; `lane-N` and typos → `None`.
- `Token::is_tint` (fn) — true for the three conflict tints (backgrounds).
- `ThemeKind` (enum) — dark, light, or high contrast (override only).
- `ThemeKind::select` (fn) — resolve theme from an override and a terminal hint; unknown → dark.
- `ThemeKind::name` (fn) — the theme's name as the config file spells it.
- `TokenColor` (enum) — a resolved colour, `NO_COLOR`-aware.
- `Theme` (struct) — a resolved theme; no path hands a widget a colour the terminal can't show.
- `Theme::new` (fn) — resolve a theme for a kind and terminal capabilities; `with_overrides(kind, caps, &[])`.
- `Theme::with_overrides` (fn, m8-16) — the constructor: `kind`'s built-in table with `[theme.<kind>]` colours written over it (kept privately as `rgb`), each token reduced from that table. Overridden conflict token skips its pin → `nearest_256_cube`; no token re-derives another; lanes untouchable; `NO_COLOR` → all `Default` (`theme/overrides.rs`).
- `Theme::kind` (fn) — which theme this is (diagnostics, config round-trips).
- `Theme::color_depth` (fn) — how much colour this terminal has, `NO_COLOR`-reduced like every token; widgets use it to reach for a non-colour separator at `Palette16`.
- `Theme::token` (fn) — the colour for one chrome token. Conflict tokens use private `pinned` (fixed 256/16 entries, dark and high contrast) then `depth::nearest_256_cube` (16–231, never the grey ramp); a dropped tint is `TokenColor::Default`.
- `Theme::tint` (fn) — a tint token's background, `None` at 16 colours, under `NO_COLOR` and in high contrast; widgets ask this, never the depth.
- `Theme::lane` (fn) — the colour for one graph lane; shape/dash separate same-hue lanes.
- `Theme::lane_muted` (fn) — m8/17: a lane's hue mixed 45% toward `bg` for off-thread cells at truecolor/256; the lane's own colour at 16/none (caller keeps DIM).
- `Theme::branch_muted` (fn) — `lane_muted` by `BranchIdentity`.
- `Theme::fades_by_hue` (fn) — truecolor or 256: off-thread lanes fade by hue, not DIM.
- `Theme::raster_lanes` (fn) — truecolor lane hues for the pixel tier at any depth; one muted hue when colour is off.
- `Theme::raster_muted` (fn) — the unreduced `text-muted` hue (his override if any, from the `rgb` table), for a pixel `+N` marker.
- `Theme::branch` (fn) — the colour a branch identity draws in, independent of column.
- `Theme::syntax` (fn) — the colour for a `syntax::SyntaxRole`, from the chrome tokens; collapses to `Token::Text` at `Palette16` and under `NO_COLOR`.

## text_input
Text entry (m3-working-tree-undo-and-stash/05). The state halves are pure —
no width, no theme — and the cursor is a **character** index, so a wide
character or a combining mark is never cut in half. Horizontal and vertical
scrolling are worked out at draw time from the cursor rather than stored, so
no offset can go stale behind a resize.
- `GUIDE` (const) — `┊`, the length-guide glyph (column 50 for a subject, 72 for a body).
- `LABEL_WIDTH` (const) — cells the `Subject`/`Body` label column takes, so both text regions start in the same column.
- `TextField` (struct) — one editable line. `new`, `text`, `cursor`, `len`, `is_empty`, `insert`, `insert_str` (a bracketed paste; control characters, newlines included, are refused at the door so the cursor index can never disagree with the sanitiser), `backspace`, `delete`, `left`, `right`, `home`, `end`, `word_left`, `word_right`.
- `TextArea` (struct) — several editable lines, always at least one. `new`, `text` (joins with `\n`; round-trips `new`), `lines`, `cursor`, `is_empty`, `insert`, `insert_str` (`\n` and `\r\n` break the line), `newline`, `backspace` (joins upwards at a line start), `delete` (pulls the next line up at a line end), `up`, `down`, `left`, `right`, `home`, `end`, `word_left`, `word_right`, `append_line` (a line of its own at the end, cursor after it; on an empty area it becomes the first line, never a blank one followed by it).
- `FieldView` (struct) — `label`, `text`, `cursor` (character index), `guide_at`, `counter` (`(typed, limit)`; drawn in `Warning` past the limit), `focused`.
- `FieldWidget` (struct) — `view`, `theme`; `Widget` over one row: label, text, guide, right-aligned counter.
- `AreaView` (struct) — `label`, `lines`, `cursor` (`(line, character)`), `guide_at`, `focused`.
- `AreaWidget` (struct) — `view`, `theme`; `Widget` over the rows it is given: the label row, then as many lines as fit, scrolled so the cursor's line is always one of them.

## commit_editor
The commit/amend editor's screen (m3-working-tree-undo-and-stash/05). Draws
