- `context_menu` (mod) — the `.`/right-click popup: `ContextAction` (`Explain`, `CopySha`, `CompareWithThis`, `OpenDetails`, and — m5-03 review Major 1 — `Fetch`, `Pull`, `Push`, `Undo`, the keys the hint bar's width rule drops first, so `. more` leads somewhere; plus `History(usize)`, m5-history-and-ghost-preview/08 piece 6), `MenuItem` (`label` is `graft_term::SanitizedText`: a history verb names refs out of the repository, so every label goes through `sanitize_line`), `ContextMenu` (`for_row(marked, history)` — the row's own actions, then one `History(i)` item per label in `history` carrying that label's index in the caller's own list, then `always_items()`; `for_working_tree` 5; `move_cursor` clamped, `selected`, `width`); every label but `Explain`'s names its key when it has one (`Push (P)`, `Merge … (m)`, `Rebase … (r)`), so a trailing `(key)` anywhere in the menu means "next time you can skip the menu"; the history verbs that own no letter carry none, which is why they live behind `.` at all (`docs/design/02-keymap.md` §2.1). **A pane narrower than the longest label cuts from the right, so the key hint is the first thing lost** — pinned by `context_menu::tests::a_pane_too_narrow_for_the_label_cuts_the_key_hint_off_the_end`, not fixed here (ADR-0039's problem). **`History(i)` is an index and nothing else**: `ui` never imports `ops`, so which git operation row `i` means is `graft`'s (`update::context_menu::verbs`). No theme carried, so its `Widget` impl draws only labels and the reversed cursor row, the background painted by the caller (m2-details-and-diffs/12). Since m5-history-and-ghost-preview/10 it also carries a **drop menu**: `ContextMenu::title` (`Option<SanitizedText>` — `feature → main`, drawn bold on its own row above the items, so a menu opened by a gesture says what went where), `MenuItem::disabled` (`Option<SanitizedText>`, the reason a verb cannot run — the row draws `DIM` and reads `Merge feature into main — check out main first`, `REASON_SEPARATOR` being that ` — `), `ContextMenu::for_drop(title, verbs)`, `rows()` (items plus the title row, when there is one), `item_at(offset)` (which item a click at that offset in the menu's rect means — the title row belongs to nothing), `selected_refusal()` (the reason under the cursor, `None` when the verb can run). The **drop verbs themselves stay indices**: `for_drop` takes `(label, disabled)` pairs and the caller keeps the operations, the same `History(usize)` boundary `for_row` uses, because `ui` never imports `ops`.
- `confirm` (mod) — the confirm box, N choices now (m5-history-and-ghost-preview/04, ADR-0038 §1): `ConfirmView` (`title`, `message: Vec<SanitizedText>`, `command`, `choices: Vec<SanitizedText>`, `cursor: usize`) — `new(title, message, command)` opens two choices, `["Cancel", "Confirm"]`, cursor 0 (the safe default, never varies by danger level); wrapping and footer clearance added m4-remotes/03, M3 review 06 Minor 11). `confirm_area_at(frame, view, x, width) -> Rect` (m5-history-and-ghost-preview/28, ADR-0040) — the same box at an x and a width the caller chose, for a layout site that has snapped it onto whole row columns; The widget is unchanged and still knows nothing about where it was put.

Out of scope here (later groups): key handling, scrolling state, hit-testing beyond `row_at`, colour beyond reused tokens — **colour ships unverified** (CLAUDE.md rule 5).

- `graph_screen::hints` (mod) — the footer's key hints by context (`hint-bar-redesign`). `HintState` (`Live`/`Planned`), `Rung` (`Key` < `Short` < `Full` — how much of a hint the bar had room for), `Hint { key, verb, state, rung }` with `Hint::text() -> String` (the key plus as much of the verb as `rung` allows; `verb` always names the *whole* verb whatever the rung, which is what `graft`'s `every_key_the_bar_draws_is_answered` compares), `Divider` (`Shown`/`Hidden`); `HintContext` (`WorkingTreeRow`, `BranchRow { current }`, `PlainRow`, `Marked(Box<HintContext>)`, `Banner { skippable, conflicted }`, `Preview`, `ChangesPane { unmerged }`, `Journal`, `Stash`, `Map` (the third overlay, keymap §2.3a: `⏎ seek`, `j/k move`, `esc close` — m5/42), `PaneOverOverlay { opens }` (m5/42: the detail pane has the keyboard with an **overlay**, not the graph, behind it — the row's list is not borrowed at all, because the overlay swallows every key the graph would have answered; what is left is `⏎ open` (unless the diff already has focus), `j/k move`, and the two verbs dispatched above the panes, `u undo` and `/ search`), `Dragging` (a ref badge is in the air: `release drop on a row`, `esc cancel`, and nothing else — m5-history-and-ghost-preview/10), `PaneFocused { row: Box<HintContext>, opens }` (m5/31: the row's own context with the keys a focused pane leaves dead filtered out — `S`, `J`, `M`, `O`, which need the graph to have the keyboard, and `⏎` unless `opens`, i.e. unless the files list rather than the diff has focus; it keeps the row's doorway, so what is hidden is still one `.` away) — `ChangesPane`'s `detail_shown` is gone, the divider is now a frame-level `Divider` every context gets); `hints_for(context, divider, columns) -> Vec<Hint>` — the design note's priority table with `Planned` entries dropped first (a key no group has bound is never drawn, m5-03 review Critical 2), `<> resize` inserted fourth when `Divider::Shown` (so the six-hint tier reaches it), then, for the graph's own row contexts, the keys the whole screen answers (`TAIL`, the old fixed list's leftovers, deduped by key — Major 3); then width, by the **shrink ladder** (ADR-0039's third amendment, m5/24): the bar fills from the most relevant end — the three most relevant at their `Full` rung first, then every remaining hint at its bare `Key`, then those raised one at a time from the left, short rung then full. A hint that will not fit even at its bare key is dropped, `. more` is never dropped, and the floor is three hints at their **floor rung** — their `Short` rung where `short_form` names one, their `Full` verb where it does not (m5/27, m5/31's wording pass). **Where `. more` sits** (m5-history-and-ghost-preview/28, ADR-0039 §"The decision"): at the head of the bare keys — which is the end of the row when there are none. One rule, two layouts: with a `TAIL` of bare keys it reads `… ⏎ open  c commit  . more  P  p  f  u …`, the doorway ending the part you can read and introducing the part you cannot; with nothing abbreviated it is simply last. It is no longer always last, so `ends_with(". more")` is not the promise — being reliably present is. **Below the floor** the ladder continues rather than stopping: floor → `. more` alone (its `Full` rung, then `Short`, then bare `.`) → nothing. The bar never draws a fragment of itself. Measured (`the_floor_fits_at_forty_eight_cells_of_bar`): the tightest context's floor is 38 cells and the narrowest bar the app can reach is 48, so nothing below the floor is reachable today — completeness, not a live defect (`Short` == `Full` for a verb the user's table gives no short form). Built as a fixed sequence of steps with the longest prefix that fits, which is what makes the bar monotone in its own width in both dimensions — more room adds a hint or raises one, never the reverse. Short forms live in `short_form(verb)`: the user's own table, restated 2026-09-21 (m5/27) to **prefixes only** — nine rows, each a clean prefix of its verb (`cont` for `continue`, `rev` for `revert`, …); squeezes (`cmt`) and substitutions (`find`, `tool`, `stop`) were deleted, thirteen rows. `stash`, `merge`, `rebase` and the planned verbs are absent from it on purpose and keep their whole word; a verb the table does not name simply has no short rung. **No width tiers** — they capped 160-column screens at three hints whenever the pane beside left the bar ~92 cells, while a 120-column screen with the pane below drew six (ADR-0039 amendment, m5/20 item 7). `Marked` leads with `. explain`, omits `. more`; `Preview` is the only context an empty list is allowed for. `Banner` is the exception to all of it: no width tier (its whole list draws, `⇥ graph` — the way out — included), no `<> resize` and no `. more`, because a focused banner is modal and swallows both (m5/16); `conflicted: false` drops `M`/`e`, which refuse in words with nothing unmerged. `m merge` and `r rebase` are **`Live`** since m5/24 — ticket 25 bound them to the Ghost Preview (`graft::update::preview::is_history_key`) while the table still called them planned, so two working keys were advertised nowhere. `every_hint() -> Vec<Hint>` — every table's entries, `Planned` included, deduped by (key, verb): what `graft`'s walk tests iterate. `every_context() -> Vec<HintContext>` (m5/31) — one value per variant and per field combination, each wrapped again as `Marked` and as `PaneFocused`: the single enumeration every sweep reads, so a context added to the enum is added to the sweeps in one place. The plain list is hand-written and **cannot** come from the type (Rust cannot enumerate a type's values, and `Marked`/`PaneFocused` are recursive so the set is not finite without a hand-chosen depth). What is forced instead is that a new shape cannot pass unnoticed: `marked_form`, `pane_focused_form` and `tests::coverage_slot` all match exhaustively — the last of them on every boolean field combination too — and `tests::every_context_reaches_every_shape` fails until the list actually produces one (m5-history-and-ghost-preview/33, review M3, correcting an earlier claim that the compiler forced the list itself). `Journal`, `Stash`, `Map` and `PaneOverOverlay` draw no `. more` and no `<> resize`: `.` opens nothing over an overlay, and the bar behind one is only ever drawn in the tab layout, which has no divider. `Resolver { base, restart }` (m6-conflicts/02) — the conflict resolver's whole-bar modal table (`o ours`, `t theirs`, `b both`, `B base` when `base`, `e edit`, `n next`, `N prev`, `⏎ resolved`, `M mergetool`, `d start over` when `restart`, `esc close`), no doorway or divider like the other modal contexts. **Every entry ships `HintState::Planned`**, not `Live`: no `graft`-side state or dispatcher for the resolver exists yet (that's this milestone's G4, at the seam this ticket's crate set stops short of), and drawing a key `Live` with nothing behind it is the exact defect `every_key_the_bar_draws_is_answered` and m5-03 review Critical 2 exist to catch. `ChangesPane{unmerged}` and `Banner{conflicted}` each gained a leading `planned("⏎","resolve")` hint pointing at it. `hints_text(hints) -> String` — ` key verb  key verb`. `fit_status_line(reason, keys, columns) -> String` — a `reason · keys` status line; cuts the reason with `…` first, keeps ` · keys` whole; drops the separator rather than leave it dangling when not even the keys fit.

- `text_input` (mod) — the commit editor's (and later the stash prompt's, and the credential prompt's) text entry: `TextField`, `TextArea`, `FieldView`/`FieldWidget`, `AreaView`/`AreaWidget` (m3-working-tree-undo-and-stash/05). `SecretField` (m5-history-and-ghost-preview/01, ADR-0038 §2) — the typed-password buffer: backed by `Zeroizing<String>` with 256 bytes reserved once at construction, so the inner `String` never reallocates on its own; growth past that builds a fresh `Zeroizing` and drops the old one (whose whole capacity zeroes), shrinking edits wipe the bytes past the new end, and `clear` zeroes the capacity in place and keeps the allocation (m5-01 review Critical 1 — the old version grew 0→8→16→32, freeing an unwiped prefix each time). `insert`/`insert_str`/`backspace`/`delete`/`left`/`right`/`home`/`end`/`clear` mirror `TextField`; `len`/`is_empty`/`cursor`/`pulse`; `new(pulse_seed: bool)` is the only constructor (no `Default`) — `pulse` is a bit that flips on **every** edit, so each keystroke visibly registers, started from `pulse_seed`, which `graft::jobs::askpass::pulse_seed` draws at random per prompt. Both halves of ADR-0038 §2 hold because of the seed: the row moves on every keystroke, and the row *at rest* is `seed XOR (edits mod 2)`, so it is uniform and independent of what was typed (a fixed start rested at the parity of the length — m5-01 review Major 2 — and `!is_empty()`, its first fix, cost the per-keystroke feedback). Not hidden: an observer watching one prompt from the moment it opened can count the flips (m5-history-and-ghost-preview/04); `into_bytes(self) -> Zeroizing<Vec<u8>>` moves the buffer out via `mem::take` (no clone) for handoff to `graft::update::credential::Answer`; hand-written `Clone` (its own zeroizing copy, capacity carried over), `Debug` (the constant `SecretField(..)` — not the text and not the length), `PartialEq`/`Eq` (by length only, which is never printed) — never `Display`, `text()` or `as_str()`. Zero-after-drop rests on zeroize's contract; safe Rust cannot observe it. `FieldView.secret: Option<bool>` (replaces `masked: bool`, m5-history-and-ghost-preview/01) — `Some(pulse)` draws a **fixed** `SECRET_GLYPHS = 8` glyphs (`•`/`*` at the ASCII tier) regardless of the real secret's length, the first swapped for `◦`/`+` while anything is typed, so two secrets of different lengths draw byte-identical rows; cursor/guide/counter suppressed (a counter would leak the length). `display_text(view, ascii)` is the one gate the shown string passes through, and `Debug for FieldView` redacts `text`/`cursor` while `secret.is_some()`, so the real text never reaches a draw call or a log line by any other path. `pub(crate) fn draw_line` reused by `credential_prompt`.

## detail
View-model types for the detail pane (m2-details-and-diffs/06); no widget. Every string is `SanitizedText`.
- `Subject` (enum) — `None`, `Commit { sha }`, `Compare { base, head }`, `WorkingTree { staged, unstaged, untracked }`.
- `DetailHeader` (struct) — subject, summary, author, dates, committer, co-authors, parents, against, contained, radar lines.
- `ContainedIn` (enum) — `NotAsked`, `Checking`, `Known { branches, tags, more }`, `Failed`.
- `RadarLine` (enum) — a finding (`Severity`, title) or the evil-merge / force-push states, including `EvilResolved { files }` ("evil merge: clean (N files hand-resolved)").
- `FileStatusView` (enum, no longer `Copy` — `Unmerged` carries a `SanitizedText`) — `Added`, `Deleted`, `Modified`, `Renamed`, `Copied`, `TypeChanged`, `Unmerged { how: SanitizedText }` (the porcelain pair as words, `"both modified"` etc. — no single "the diff" while both sides are still in the index, so `detail_pane::files::file_row_text` draws `how` in place of a letter and add/remove counts, m5-history-and-ghost-preview/04), `Untracked`.
- `WorkingTreeSection` (enum) — gained `Unmerged` as its first variant (drawn first in the changes pane by caller row order); `title()` returns `"CONFLICTS"` for it (m5-history-and-ghost-preview/04).
- `FileRowKind` (enum, no longer `Copy`, cascades from `FileStatusView`) — `Message { lines }`, `Dir { collapsed }`, `File { status, added, removed }`.
- `FileRow` (struct) — depth, name, kind, `entry` (index into the git list; `None` for message/dir).
- `FileListView` (struct) — rows, cursor, top, totals, `message` (the `✉` row's body lines).
- `FileListView::visible` (fn) — rows not under a collapsed dir, with their indices.
- `FileListView::toggle_dir` (fn) — collapse or expand a dir row.
- `FileListView::move_cursor` (fn) — move among visible rows, clamped.
- `FileListView::selected_entry` (fn) — the cursor row's git entry, if a file.
- `LineKindView` (enum) — `Context`, `Added`, `Removed`, `HunkHeading`.
- `LineView` (struct) — kind, old/new numbers, text, word ranges, `SyntaxSpan`s, `pair` (index of its partner line).
- `HunkView` (struct) — heading and lines.
- `DiffMode` (enum) — `Unified`, `SideBySide`.
- `DiffOptionsView` (struct) — context, ignore_whitespace, word_tint; `Default`.
- `DiffView` (struct) — path, old path, status, hunks, `binary`, `truncated`, `untracked`.

## text_input
Text entry (m3-working-tree-undo-and-stash/05). The state halves are pure —
no width, no theme — and the cursor is a **character** index, so a wide
character or a combining mark is never cut in half. Horizontal and vertical
scrolling are worked out at draw time from the cursor rather than stored, so
no offset can go stale behind a resize.
- `GUIDE` (const) — `┊`, the length-guide glyph (column 50 for a subject, 72 for a body).
- `LABEL_WIDTH` (const) — cells the `Subject`/`Body` label column takes, so both text regions start in the same column.
- `TextField` (struct) — one editable line. `new`, `text`, `cursor`, `len`, `is_empty`, `insert`, `insert_str` (a bracketed paste; control characters, newlines included, are refused at the door so the cursor index can never disagree with the sanitiser), `backspace`, `delete`, `left`, `right`, `home`, `end`, `word_left`, `word_right`.
- `TextArea` (struct) — several editable lines, always at least one. `new`, `text` (joins with `\n`; round-trips `new`), `lines`, `cursor`, `is_empty`, `insert`, `insert_str` (`\n` and `\r\n` break the line), `newline`, `backspace` (joins upwards at a line start), `delete` (pulls the next line up at a line end), `up`, `down`, `left`, `right`, `home`, `end`, `word_left`, `word_right`, `append_line` (a line of its own at the end, cursor after it; on an empty area it becomes the first line, never a blank one followed by it).
- `FieldView` (struct) — `label`, `text`, `cursor` (character index), `guide_at`, `counter` (`(typed, limit)`; drawn in `Warning` past the limit), `focused`.
- `FieldWidget` (struct) — `view`, `theme`; `Widget` over one row: label, text, guide, right-aligned counter.
- `AreaView` (struct) — `label`, `lines`, `cursor` (`(line, character)`), `guide_at`, `focused`.
- `AreaWidget` (struct) — `view`, `theme`; `Widget` over the rows it is given: the label row, then as many lines as fit, scrolled so the cursor's line is always one of them.

## commit_editor
The commit/amend editor's screen (m3-working-tree-undo-and-stash/05). Draws
into whatever rect it is given and carries no state of its own: the caller
owns the `TextField`/`TextArea` halves and passes a view.
- `SUBJECT_LIMIT` (const) — 50, where the subject's guide stands and past which its counter turns `Warning`.
- `BODY_LIMIT` (const) — 72, the body's guide column.
- `Field` (enum) — what has focus: `Subject`, `Body`, `Amend`, `SignOff`, `NoVerify`, `AllowEmpty`, `CommitButton`. `OPTIONS` (const) lists the four checkboxes in row order. `is_option`, `label`, `next`/`previous` (the `Tab` order, wrapping), `sibling_option(forward)` (`←`/`→` along the options row, `None` at either end).
- `CommitEditorView` (struct) — `title`, `subject`/`body` (the `FieldView`/`AreaView` halves), `focus`, `amend`/`sign_off`/`no_verify`/`allow_empty`, `refusal` (the reason drawn dimmed beside a dimmed `[ Commit ]`, `None` when the commit may go ahead), `status` (why the last write failed — a hook's refusal above all; takes the footer row from the key hints, in `Token::Warning`, until `Esc` dismisses it; m3/05 review M1), `busy`.
- `CommitEditorScreen` (struct) — `view`, `theme`; `Widget`: title row, subject row, body block, the options row pinned above the footer, then the key footer. Nothing scrolls off: below `fits` it is not drawn at all.
- `fits` (fn) — whether an area has the rows (`CHROME_ROWS` = 6, plus a body line) and columns the screen needs. The caller shows a "too small" message instead.
