# m5-ui-credential-over-graph-80x24.txt: 80x24, drawn by
# `view::view` from a real AppState — the same repository and the
# same running push as m5-ui-confirm-over-graph-80x24.txt, with
# git's password question opened on the job the confirm started
# (`update::credential::credential_needed`, the entry point
# `Progress::CredentialNeeded` uses) and a seven-character password
# typed into it
# (crates/mergewright/tests/it/two_boxes_over_content.rs,
# capture_two_boxes_over_real_content_for_docs_shots, asserted).
# The host in the question is pinned to `127.0.0.1:8443`: a real HTTP
# fixture is served on a port the OS picks, and a capture whose title
# changed every run could not be diffed. Not a pty capture — no
# colour attributes, CLAUDE.md rule 5.
#
# **What right looks like here** (ADR-0040): the opposite outcome,
# from the same rule. The prompt **clears the band it stands on**,
# full width, at every width. Two reasons, either sufficient: at 80
# its right border landed inside the short-SHA column and left four-
# character tails standing against it, reading as identifiers that
# are not; and nothing behind a modal password question serves the
# task — the prompt's own border says which push is waiting
# (`esc cancel the push`); the bottom row is its keys (m6-conflicts/69).
#
# It clears **the band**, not the screen: the graph above it and the
# footer below it stay. So there is nothing beside the prompt in the
# rows it occupies, and that is the picture, not an omission — the
# writer asserts it before writing this file, and a change of heart
# fails there rather than going stale here.
#
# The border's rule no longer runs into the title or the key hints:
# `Credentials — 127.0.0.1:8443───` read as part of the host. The
# prompt's private copy of `frame_box::border_row` is gone and the
# four bordered surfaces share one implementation (ADR-0040).
#
# ADR-0038 §2 is unchanged and holds here: the field draws a fixed
# 8 mask glyphs whatever was typed, never the typed length, and the
# plaintext is in no row of this file (the writer asserts both).
