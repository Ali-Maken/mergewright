# m5-ui-banner-conflict-80x24.txt: 80x24, drawn by `view::view`
# from a real AppState — a real repository whose `main` and `feature`
# both rewrote the same 16 files, opened over the real job pool, the
# merge launched with `m` through the preview and the confirm box, and
# git really stopped on the conflict (crates/graft/tests/it/
# conflict_interim.rs, capture_banner_for_docs_shots, asserted). The
# app was resized to 80x24 before the frame was drawn, so the
# layout it chose is the layout for this screen and not for another
# one. Not a pty capture: the terminal is ratatui's TestBackend, so
# this is a character grid with no colour attributes in it —
# CLAUDE.md rule 5, colour ships unverified. The scratch repository's
# temporary path is set to `/code/api` **before** the frame is drawn,
# so the header is laid out against the width a real checkout takes;
# nothing else is touched.
#
# What right looks like:
#  - A banner above the panes reading `MERGING` — the state the
#    repository is in, said once, at the top, and **nothing else**. No
#    filename: the changes pane lists every conflicted file, and
#    saying it twice on a 24-row screen spends a row on nothing.
#    Worded the
#    same at all three widths.
#  - No `⚠`. A stopped merge is a state to finish, not a failure;
#    the glyph keeps its force for the Mistake Radar's real findings.
#  - **What it costs.** Under 100 columns only one side of the tab
#    strip is on screen and this frame stands on the graph, with 30
#    commits of ordinary work behind it: history runs from the first
#    row to the last with nothing blank. The banner shares the header
#    row with the repository path, and its keys take over the hint bar
#    that was already there — so on this tab a stopped merge costs
#    **no** rows of history at all. The row of its own is the `Detail`
#    tab's case, where the `Graph  [Detail]` strip needs a line of its
#    own anyway; that tab at 24 rows is a six-row file list over one
#    file's conflict, which shows a screen rather than a cost.
#  - The footer teaches the banner's own keys — `c continue`,
#    `a abort`, `M mergetool`, `e edit`, `⇥ graph` — and nothing else.
#    No `<> resize` and no `? keys`: the banner is modal and swallows
#    both.
#  - The banner is drawn focused (colour, so unverified here), and the
#    footer says nothing false about the merge: no `an operation was
#    interrupted` line.
#  - **The working-tree row counts the conflict**: it reads
#    `Uncommitted changes (16 unmerged)`, not the `()` it read on
#    the last pass. An unmerged path is in none of staged,
#    unstaged and untracked, so the row drew and then counted
#    nothing (m5/21). Unmerged leads the count when other
#    buckets are there too.
#  - Nothing on the screen reads as an error.
#
# Re-captured for m5/23, which pinned this fixture's clock: every
# commit is stamped a fixed minute after 2021-01-01 and the frame is
# drawn against a fixed instant, so the object ids, the ages and the
# lane order of `main` and `feature` are the same on every run. They
# all differ from the last pass, once, as a consequence.
#
# Captured before that for m5/21, which made the working-tree row
# count unmerged paths and gave the changes pane a body for a
# conflicted file (it is read against `HEAD` now; against the
# index git answers with a combined diff and the body drew
# nothing).
#
# Captured first for m5/20, which dropped the `⚠` and the filename from
# the banner, settled the pane before the shutter, put 30 commits of
# ordinary work and 16 conflicted files behind the frame so the
# banner's row cost lands on content rather than on blank space, and
# made the hint bar count from its own row rather than from width
# tiers (so the bars here are longer than on the last pass). What is
# **not** proven here: colour (rule 5), and that the banner row reads
# well by eye —
# that is yours to judge (rule 6).
#
