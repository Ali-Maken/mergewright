# m5-ui-context-menu-verbs-160x48.txt: 160x48, drawn by `view::view`
# from a real AppState — a real repository (`main` three commits, `feature`
# forked off the first with two of its own, `feature` checked out), opened
# over the real job pool, cursor moved to `main`'s row and `.` pressed
# through `update`
# (crates/mergewright/tests/it/context_menu.rs, capture_context_menu_for_docs_shots).
# This file is a golden snapshot: that test asserts the frame still
# matches it, so drift fails the suite. Regenerate on purpose with
# MWR_UPDATE_SHOTS=1. Not a pty capture: the terminal is ratatui's
# TestBackend, so this is a character grid with no colour attributes in
# it — CLAUDE.md rule 5, colour ships unverified. The fixture's commits
# carry fixed dates and the ages are drawn against a fixed clock, so the
# frame is the same on every run and does not age. The repository is
# moved to `/code/api` **before** the frame is drawn, so the header is
# fitted to the path shown here rather than to a temporary one, and the
# walk's sort and the radar have landed — a settled screen, not a transient.
#
# What right looks like:
#  - The menu is anchored under `main`'s row and is wide enough for its
#    longest label, with the cursor on the first item.
#  - `Checkout main` then `Cherry-pick <sha7> (o)` come first (m6-conflicts/71),
#    then `Explain` if the row is marked, then the row's own actions
#    (`Copy SHA (y)`, `Compare with this (x)`, `Open details (⏎)`),
#    then the rest of the history verbs, then the ambient
#    ones (`Fetch (f)` … `Undo (u)`). The menu lists every verb valid for
#    this row at every width — it does not filter against the hint bar,
#    because a verb you can only discover at 160 columns is the failure
#    ADR-0039 exists to prevent.
#  - The menu is opaque. On each of its rows, everything right of the
#    label is blank out to the edge of the pane: no date or sha from the
#    commit row underneath survives beside a verb, where it would read as
#    if the verb were bound to that sha.
#  - The history verbs name the real branches, not placeholders: `Checkout
#    main`, `Merge main into feature (m)`, `Rebase feature onto main (r)`,
#    `Cherry-pick <sha7> (o)`, `Revert <sha7>`, `Reset feature to here,
#    mixed`/`, hard`, `Delete branch main`. `feature` is the branch
#    checked out, `main` is the row under the cursor.
#  - No verb names the branch you are standing on where git would refuse
#    it: there is no `Checkout feature` and no `Delete branch feature`.
#  - A trailing `(key)` means one thing everywhere in the menu: that
#    letter is live right now, so next time you can skip the menu. Only
#    `Merge`, `Rebase` and `Cherry-pick` carry one, because only `m`, `r`
#    and `o` (M7) exist. A
#    qualifier that is not a key never wears that shape — hence `Reset
#    …, mixed`, not `(mixed)` (`docs/design/02-keymap.md` §2.1).
#  - Choosing any of them opens a picture, not a write (PROMPT.md §1.7).
#  - The marker column has settled: `feature`'s tip carries the radar's
#    muted `ⓘ`. Earlier captures were taken before the radar
#    answered and the column was blank — that was the transient, not
#    this. What the finding says is not part of this picture.
#  - At 160 columns the graph's date and sha columns sit far to the
#    right of the menu, and they stop dead at the menu's own rows: the
#    popup clears the whole band it stands on, so no verb has a stray
#    sha beside it.
#
