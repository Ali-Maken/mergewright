# m5-ui-undo-after-push-80x24.txt: 80x24, drawn by `view::view` from a
# real AppState — a scratch repository pushed to a `file://` bare,
# then `u` (crates/graft/tests/it/remote_by_key.rs,
# capture_undo_after_push_for_docs_shots, asserted). Not a pty
# capture: the terminal is ratatui's TestBackend, so this is a
# character grid with no colour attributes in it — CLAUDE.md rule 5,
# colour ships unverified.
#
# Why: `u` undoes your local branch. A push has already sent that work
# somewhere others can pull. Undoing silently would leave the two
# disagreeing with no word about it (ADR-0038 §4).
#
# What right looks like:
#  - **The first box names the remote side** and says in words that
#    undo is local only, and that re-pushing the old tip rewrites a
#    branch others may have pulled. Three answers, `Cancel` first.
#  - **Re-push asks a second time.** Choosing `[ Re-push old tip ]`
#    does not push: it opens the ordinary push confirm, showing the
#    exact command. Two deliberate answers before a remote branch is
#    rewritten.
#  - **The command line says `--force-with-lease`**, never a bare
#    `--force`. At 80 columns the box is narrower than the full
#    command, so the tail is clipped — the same clipping the M4 lease
#    box already takes (noted in the ticket; the fix is in graft-ops).
#  - Your local branch keeps every commit it has: re-push moves the
#    remote back, not you.
#
# The `to push` commit is made by this test moments before the frame is
# drawn, so its id is new on every run. It is zeroed to `0000000` in
# this file, at the width it was drawn at, so the capture can be
# compared to the code. Nothing else here is normalised.
