# Why: the lane cap was read off the **screen's** width while the
# detail pane stood beside the graph. At 160 columns the graph gets 92
# of them and folded to twelve lanes anyway — the breakpoint for a
# width it does not have. ADR-0039's 2026-09-21 amendment, third
# instance: ask how much room this thing has, not how big the screen
# is (m5/21 item 4).
#
# What right looks like:
#  - **The two frames differ.** With the pane open the graph folds
#    more: the header says `+8 lanes` and a `⋮` marker column
#    stands where the folded lanes were. With the pane closed the same
#    repository on the same terminal says `+4 lanes`: more lanes
#    drawn. The two used to be identical, because both asked the
#    screen.
#  - The topic tips sit above the window, so their lanes pass through
#    rows with no node on them: those are what the cap folds. A column
#    with a node on screen is never folded (m7-power-tools/36; the
#    fixture reshaped again for the fold by ease-pass 06f).
#  - With the pane open the subject column starts two cells earlier
#    and every subject is still readable.
#  - Nothing reads as an error on either frame.
#
# What is **not** proven here: colour (rule 5), and whether the graph
# beside the pane reads well by eye — that is yours to judge (rule 6).
# The counts themselves are pinned by
# `lane_cap::the_pane_narrows_the_graph_so_the_graph_folds_more` and
