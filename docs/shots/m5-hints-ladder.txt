# docs/shots/m5-hints-ladder.txt — the hint bar's shrink ladder
# (ADR-0039, m5/24 and m5/28)
#
# What right looks like: the bar fills from the most relevant end. The
# three most relevant hints keep their whole verbs; every hint after them
# is drawn at its bare key until the whole context is on the bar, and only
# then do the tail's keys start gaining verbs, left to right. A hint that
# will not fit even at its bare key is dropped, and `. more` — the doorway
# — is never dropped and **sits at the head of the bare keys**, which is
# the end of the row when there are none.
#
# The question these rows were captured to answer is answered: a tail of
# naked letters after three labelled hints read as *leftover*, and the
# user chose variant B, which is what is built here. Every labelled item
# is now contiguous and the last of them announces the menu, so everything
# after `. more` reads as keys the menu will spell out — which is what
# they are. That resolves `space` and `j/k` in the tail too: the region is
# labelled even though its members are not. It cost no cells and no glyph.
# The A/B comparison that used to sit at the bottom of this file is gone
# with the question.
#
# The bottom of the ladder, which these widths are all far above:
# floor → `. more` → `.` → nothing. The bar never draws a fragment of
# itself at any width. The narrowest bar anything reachable actually has
# is 48 cells and the tightest context's floor fits in 38, so nothing
# below is near it (ADR-0039).
#
# How this was made: `hints_for(context, divider, columns)` rendered by
# `hints_text`, which is exactly the two calls `graph_screen::footer` makes
# (`footer.rs`, the `(None, None, None, None)` arm). It is the bar's own
# row and nothing around it — the whole screen at these widths is in
# `m5-hints-<context>-<size>.txt` beside this file. `columns` is the room
# the *bar* has, not the screen's width: with a detail pane beside the
# graph a 160-column terminal hands the bar about 92 cells (ADR-0039's
# second amendment). No colour here — TestBackend records a character
# grid, so the muted grey the footer draws in is unverified
# (CLAUDE.md rule 5).
#
# The short rung is visible where the room runs out mid-hint: `F3 rend`
# below. Every short form is a prefix of the full verb, the user's own
# word, restated 2026-09-21 (m5/27) — a verb it does not name (`stash`,
# `merge`, `rebase`, `compare`, `commit` among them) has no short rung at
# all and keeps its whole word at every width.

=== `rev` — revert's only home, the undo journal browser ===
#
# `revert` keeps its short form under the m5/27 rule — `rev` is a clean
# prefix, not a squeeze or a substitution. But `rev` is also a git word
# meaning *revision* (`rev-parse`, `rev-list`), and that clash is the
# user's to judge, not the builder's — this section exists only to put it
# in front of him.
#
# It cannot be shown at 80, 120 or 160 cells: the journal browser's whole
# list is `⏎ revert  esc close`, two hints, and that fits whole (plus
# `. more`) from about 28 cells of bar — every width in the three-width
# matrix above is past that, so the journal row there always reads
# `⏎ revert  esc close  . more` in full, never `rev`. Below is the
# narrowest room `rev` actually appears in, computed the same way as
# every row above: `hints_for`, nothing hand-set.
