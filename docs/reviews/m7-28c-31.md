## Minor

### m1 — On a case-insensitive disk, an untracked file under another spelling is named by the target's spelling and tagged `(ignored)`
**Where:**
- `crates/graft-ops/src/in_the_way/disk.rs:43-48`: `stored` is computed but `found.insert(path.clone())` records
  the target's spelling.
- `:171-172`: `sort_out` matches status's untracked list with a case-sensitive `Path::starts_with`.

**Observed** with a reviewer probe (a throwaway test in the review worktree, not committed; APFS):
1. `other` adds `README.md`.
2. On `main`, an untracked `readme.md` holds his bytes. `git status`: `?? readme.md`.
3. Switching to `other` gives, in the preview and in apply: `README.md (ignored) is in the way of switching to other ·
   move it aside first`.

**Why it matters:**
- The refusal is on the safe side, so nothing is lost.
- But it names a file that `ls` shows under another name.
- It calls an untracked file ignored, so it hides the real next step (`S` would stash it).
- This predates 28c. 28c now computes the right name one line above and drops it.

**Fix:** record `stored`, not `path`, in `found` when it is not tracked. Then `sort_out` compares status's own
spelling. Add the probe as a test next to `a_case_only_rename_is_not_in_the_way`.

### m2 — Mixed stash refusal: `move it aside first` after a list that includes his unsaved edits
**Where:** `crates/graft-ops/src/operation.rs:1094`, pinned at `operation/tests.rs:1637`: `your unsaved edits to a.txt
and c.txt (ignored) are in the way · move it aside first`.

**Why it matters:** after a plural `are`, the reader cannot tell what "it" refers to. The unsaved edits get no step
at all. ux-principles: visibility of the next step.

**Fix:** name the file in the step, as in `move c.txt aside first`. Or give each clause its own step (the unsaved one
already has none, per 86's ruling). This is a wording call for the conductor.

### m3 — The perf record is missing its per-case 100k line, and the script hides cargo's errors
**Where:**
- `docs/perf/m7-28.txt:5-6` has the 20 000-file line and the summary, but not the `m7-28 100k commits, switch to
  HEAD~50000` line that `in_the_way/perf.rs:73-76` prints. It most likely landed on the harness's `test … ` line, which
  the `grep '^m7-28'` drops. That is inferred from the file, not observed.
- `scripts/m7-28-perf.sh:36-38` sends cargo's stderr to `/dev/null`. A build failure exits 1 through `pipefail` with no
  message.

**Why it matters:**
- The record should show what it measured.
- The script is the only way this number gets made (CLAUDE.md: measurement runs from a script), and a silent failure
  there is rule 3's shape.

**Fix:** print a newline before the first `println!` (or `eprintln!` a header). Write stderr to a log next to the output
instead of `/dev/null`.
