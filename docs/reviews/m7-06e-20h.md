## Major

**1. An orphan branch, or one sharing no history with its base, is told it "has no commits of its own"
(`rewrite/unpushed.rs:95-108`; ruling decision 2).**
- **What's wrong.** `base_of` returns `None` "when there is neither [base], or they share no history"
  (`reads.rs:41-42`). A branch with a `None` base that is neither the default branch nor the only one gets the
  `NotItsOwn` candidate (`unpushed.rs:99-105`).
- **Probe.** `main` c1 c2, then `switch --orphan docs` with d1 d2 d3, then d2's line staged. Absorb →
  `docs has no commits of its own yet · c commits them`. `a` into d2 → `a puts staged changes into a commit on your
  branch · 1b3fc93 isn't on it`.
  - Both are **false**: all three commits are docs' own, and d2 is on it.
  - Before 06e this path fell back to the capped walk.
- **Why it matters.** Ruling decision 4 is "words stay true where they fire" (CLAUDE.md status rule, H9). Examples of
  such branches: gh-pages, docs, a vendored import, a subtree split.
- **Suggested fix.** This is the ruling's gap, not the builder's. Decision 2 tests for "no base below `HEAD`", but it
  means "a branch at `main`'s tip".
  - Split the `None` arm. A base of `None` because no history is shared (the default branch exists but has no
    merge-base with `HEAD`) should fall back like the only branch.
  - Keep `NotItsOwn` for `base == HEAD` only.
  - Add a test `an_orphan_branch_falls_back`. → planner.
