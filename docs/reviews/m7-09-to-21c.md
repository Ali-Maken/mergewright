## Major

### 1. An amend at an edit stop in a rebase begun in the shell gets no journal entry, so `u` cannot take it back (07a)

- **The admission:** `crates/graft-ops/src/operation.rs:1537` exempts an Amend at an edit stop from P14 (`amends_at_edit_stop`, :366).
- **Why it is not recorded:** in `crates/graft-ops/src/apply/fold.rs:54-58`, `live_entry` finds no Graft entry for a rebase begun in the shell, so `span` is `None`. Amend's `touches` has `worktree == false`, so the guard at :55 does not send it to its own entry. It goes to `inside_live_operation` with no span.
  - :111-120: the backup is `None`.
  - :190: `fold_commands` returns early.
  - :153-155: the `JournalEntry` built is "a record of what ran, not a journal entry".
- **Contradiction:** the doc comment at :96-100 promises "What does arrive with `span` `None` writes the index alone". An amend writes a commit and moves `HEAD`.
- **Why it matters:** before 07a every amend in a rebase was refused. Now a new commit write goes unrecorded, against "every operation is undoable". The old commit is kept only by git's reflog, so no bytes are lost, but Graft cannot take the amend back, and the Command Log does not show it.
- **Scope of the conductor's note:** the note to 07b covers only the fold inside a rebase Graft began, not this path.
- **Fix:**
  - Route a `span`-less operation that writes a commit or ref (`touches.head` or a ref) to its own entry. Widen the :55 guard to `touches.worktree || touches.head`, or better, to "anything but index-only", which is what the comment claims.
  - Pin it with a test: an edit-stop amend in a `git rebase -i` begun in the shell, then `u`.
  - Correct 07a's Touches line.

### 2. `binary_words` re-matches the enum its caller has already matched (21c, readability)

- **Where:** `crates/graft-ui/src/history.rs:479-482` matches `FilePane::Binary { header, .. }`, then calls `binary_words(&view.file)`. At :521 that function matches the same pane again, with a fallback arm returning empty words "for any other pane", which can never be hit from its only caller.
- **Why it matters:** a reader has to prove the second match is total, and the unreachable arm reads as a live case. PROMPT 6.2 counts this as a readability finding, so it is Major, though the fix is small.
- **Fix:** bind the fields in the outer arm (`FilePane::Binary { header, sizes_failed, .. }`) and pass them, or pass the `Binary` payload struct, to a function that takes only that.

## Minor

1. **A put-in whose staging does not come back gets no put-in words or tags, and leaves `amend_into.asked` behind.**
   - `crates/graft/src/update/operate.rs:1081-1088`: the `StagingNotKept` arm calls only `landed(...)`.
