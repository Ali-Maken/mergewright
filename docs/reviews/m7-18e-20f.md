## Verified, with how

- **`BLAME_PORCELAIN_MARKS = 2.50.0` is right.** I fetched `builtin/blame.c` from raw.githubusercontent.com at v2.38.5,
  v2.49.0, v2.49.1, v2.50.0 and v2.54.0.
  - `puts("unblamable")` / `puts("ignored")` appear first at v2.50.0:362-364, in `emit_porcelain_per_line_details`.
  - They are absent at v2.49.1 and earlier.
  - git's `RelNotes/2.50.0.adoc:51-52` says: "`git blame --porcelain` mode now talks about unblamable lines…".
  - The const's doc (`version.rs:74-86`) cites this correctly.
- **The pinned configs are enough.** In 2.38.5 `emit_other`, colour is written before the `^` (`fputs(color…)`), then
  `^`, `*`, `?` are each written with `length--`, then the hex. `blankBoundary=true` would blank the hex, and
  `parse_marks` would then refuse the line. Pinning it `false` is needed and is done.
- **Both marks on one line mapping to `Unblamable` is right.** In 2.38.5 `blame.c:1753-1763`, an ignored split either
  passes to the parent (`ignored = 1`) or stays on the target (`unblamable = 1`). A line with both flags stays on an
  ignored commit.
- **The marks oracle's independence.** `the_human_format_marks_match_the_porcelain_marks` (`src/blame/tests.rs:428-456`)
  checks git's two separate writers against each other, on 2.54.
  - It is independent for Skipped/Plain.
  - It is **not** independent for the both-marks mapping, which both readers share (`marks.rs:48-54`,
    `porcelain.rs:127-134`). The session fixture has no unblamable line anyway.
  - The independent checks are the hand-set expectations: `tests/it/blame.rs` `an_unblamable_line_is_marked_unblamable`
    (`[Plain, Unblamable, Plain]`) and `a_skipped_line_is_marked_skipped` (assertion unchanged).
  - On git < 2.50 the oracle becomes a count check against `SKIPPED`, which is hand-set.
  - Acceptable, with the gap in Major 1.
- **The cost is within ADR-0050's number.** 2.38.5 with a list: p95 2224.2 ms, against 3 000 ms
  (`docs/perf/18e.txt`, 10 runs, nearest-rank, so p95 is the slowest run).
  - I did not re-measure (conductor).
  - The 2.38.5 binary is self-built, with unknown flags, so the gap from 2.54 (1511.5) is not only the second pass.
  - There is 776 ms of headroom on an M5.
  - See Minor 8 for the budget's wording.
- **The catch-all at graft `jobs/detail.rs:157-159` does not break rule 3.** `other => BlameFailure::Failed(other.to_string())`
  sends the words to `update/place.rs:569`, and graft-ui `blame.rs:242` draws
  `git blame stopped: <words> · esc back`:
  - `TooLarge` reads `git blame stopped: this file's blame is over 64 MiB, too large to show · esc back`.

## Major

### 1. On the standard gate, nothing tests the git 2.38 path, which is the whole reason for 18e

**Where:**
- `crates/graft-git/src/blame.rs:372-425` (`marks_pass_wanted`, `configured_list`)
- `src/blame/tests.rs:460-510`

**What's wrong:** these tests assert the Auto path, but on git ≥ 2.50 the porcelain carries marks, so condition 2
short-circuits before `configured_list` or the version gate run. I ran two mutations:
- `Some(0) => Ok(false)` at `blame.rs:414`: **all 40 blame tests green on 2.54**. Only
  `a_configured_list_alone_is_a_list_in_effect` went red, and only on 2.38.5.
- `if wanted && false` at `:324`: on 2.54 only the forced `HumanFormat` oracle catches it. The Auto-path tests stay
  green.

No documented tier runs the floor git (`grep 2.38 TESTING.md`: no hits). Its binary lives only under one machine's
`$TMPDIR`. KNOWN_GAPS `:230` records the same pattern for M3.

**Why it matters:** the marks fix exists only for git < 2.50. A later change can break it, and every gate stays green.

**Fix:**
- (a) Let a test choose the version and the porcelain's answer: `Knobs { git: Option<GitVersion>, .. }`, or test
  `marks_pass_wanted` directly with `porcelain_has_marks = false`.
- (b) Unit-test `configured_list` on its own: set, unset, and a bad config file (exit 3).
- (c) Add a floor-git line to TESTING.md's milestone-review tier, with the 18b build recipe and the filtered command.

**Erratum (2026-09-27, per `docs/reviews/m7-18f-32b-06f-33.md` Minor 6):** the `if wanted && false` line above (`:128`) is wrong. On 2.54 the forced `HumanFormat` oracle stays **green** under that mutation (observed at `559492f2`): `wanted` skips the pass for that source too, so the oracle compares porcelain marks with themselves. 18f's `as_old_git_*` tests now catch the mutation on every run. Text above left as recorded.

### 2. `blame.rs` is past the file-size rule, and the predicate is called with stand-in values

**Where:** `crates/graft-git/src/blame.rs`

**What's wrong:**

  3 and 4, so that the call tests only 1 and 2. A reader has to work out that `true, None` makes 3 and 4 hold.

- Replace `:379` with a plain `if !opts.ignore_revs || porcelain_has_marks { return Ok(false); }`.

## Minor

1. **Marks are merged by position, with the line count as the only check.**
   - `blame.rs:355-368`. If the working-tree file is edited between the two passes and keeps its line count, the lines
     get marks from the other version, silently.
   - `parse_marks` throws away the id that `-l` prints (`marks.rs:37-55`). git shortens that hex by one character per
     mark (2.38.5 `emit_other`, `length--`), so the id is a prefix of the full one.
   - Fix: return the id prefix too, and treat a mismatch with the porcelain line's commit as `Changed`. That catches
     the edit whether or not the line count changes. Only `Rev::WorkingTree` is exposed.
2. **The version read can't be stopped, and it runs even on new git.**
   - `blame.rs:386` calls `system_git()`, which uses its own `Deadline` (`version.rs:155`), not the caller's `stop`.
     Leaving blame doesn't cancel it.
   - On 2.54 it also runs for any file with a list in effect where no line was skipped (condition 2 doesn't hold), so
     it is a spawn on every such blame.
   - The cost is unmeasured.
   - Fix: pass the version the app already read (`state.system_git`) through `BlameOptions`, or cache it in a
     `OnceLock`.
3. **The docs say "no list, no spawn"; the code spawns.** `MAP.md:36` says "no list … costs no extra spawn", and
   `blame.rs:371` says "A repository with no list pays neither". With no root file, conditions 1-2 always hold (there
   are no marks), so `configured_list` spawns `git config` on **every** blame without a list, on every git. Fix the
   wording: "one `git config` spawn".
4. **The human pass's cap refusal has no test.** `blame.rs:330-332`: the cap test hits the porcelain's cap first
   (`:316`), and the human output is smaller. Either say in a comment why it's kept, or cover it with a test knob that
   caps only the second pass.
5. **The wildcard at graft `jobs/detail.rs:159` hides new variants.** It is not a swallow (Verified above), but a
   wildcard lets the next `BlameError` variant compile into `Failed` with no one deciding. 18e found this site by grep.
   Fix: name the arms. Separately, no test shows `TooLarge` or `Changed` words in the blame place.
6. **The walk counts are hand-written labels, not the keys sent.** `m7_walk/blame.rs:235-242`, `:290`, `:329`, `:362`:
   `route` is filled by `push`es next to `app.key` calls, so a key sent without a push is never counted.
   `m5_walk/steps.rs` drives the keys from the route instead. Today's counts hold (checked above). Fix: a
   `press(&app, state, key, &mut route)` helper.
7. **Caption text drift in `crates/graft/tests/it/blame_place.rs`:**
   - `:115` "the 150-character line": the fixture's line is **137** characters (`graft-fixtures/src/shapes/trace.rs:51`).
   - `:80-81` "The spec's 'the trailer whole' assumed the mock-up's shorter line": the mock-up's line 22 is the same text
     (m7 note `:129`). The spec's arithmetic was wrong.
   - These captions become the contact sheet's "Right" lines.
8. **The list metric has no budget line.** ADR-0050:12 budgets only `blame-longfile p95` from
   `m7-perf-blame-longfile.sh` (no list, 2.54). The 2.38.5-with-list metric (`scripts/m7-perf-blame-list.sh`) is
   judged against 3 000 ms only by analogy, and no review tier runs it. Fold this into gap row M7/18bcd-m7:
   TESTING.md's release perf run should run both scripts, the list one on the floor git too.
