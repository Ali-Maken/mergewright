## Questions (no line proves wrong behaviour; filed as questions per rule 7)

- **Q1. Does the confirm box still cover the SHA column whole with the Right
  layout's pane open?** `snap_to_columns` waives the gutter only at
  `bounds.right()` (`graph_screen/layout.rs:520-524`); every other boundary,
  including the graph pane's own right edge when a pane sits beside it, is
  stepped back one cell. Whether the cell it steps back onto is m5/19's
  unpainted gutter or the SHA's last character depends on `Columns::compute`
  against the pane rect, which no test draws: `view/tests.rs::confirm_over_graph`
  sets `detail.shown = false` (`:2673`), and `pane_boundaries.rs` sweeps a
  full-frame graph. One drawn case at 160 with the pane open (`j` a few rows,
  `P`) would answer it.
- **Q2. Are every one of the keys the Detail-tab bar draws live while the
  pane has focus?** Ticket 29's decision says the bar "draws the pane's own
  `HintContext` — `ChangesPane`, `Journal`, `Stash` and so on — not the
  graph's". For a commit's detail, `render_graph_with_detail` passes
  `screen.hint_context` (`view/frame.rs:295`), which is the cursor row's
  context, so at 80 columns the Detail tab draws
  `⏎ open  c commit  P push  . more  p  f  u  S  J  /  q  F2  F3  x  +  j/k  space`
  (`every_tab_context_draws_a_bar` asserts this bar exists, not what it
  says). `02-keymap.md` §2.1: a displayed key must work when pressed. Are
  `⏎ open`, `.`, `x`, `+`, `space` live with focus on the Diff pane, or does
  the pane swallow them? If the pane answers them all, the tick holds; if
  not, the bar advertises dead keys on the one layout it was added to fix.

  **Answered by the conductor, 2026-09-21: the pane does not answer them all.**
  `crates/graft/src/update/detail/keys.rs:74-77` — with the pane shown and
  `DetailFocus::Diff`, `Enter` returns `true` (consumed) and does nothing; its
  own comment says so: *"Diff already has focus: Enter has nothing further to
  open."* `crates/graft/src/view/rows.rs:302-303` confirms the context is the
  cursor row's (`hint_context(state, &[])`). So the bar draws `⏎ open` on the
  Detail tab and pressing it does nothing — a §2.1 violation, and the converse
  of the defect ticket 24 fixed. **Q2 is upheld as a defect**, filed as ticket
  31 (`31-every-key-the-bar-draws-is-answered.md`), whose deliverable is the
  invariant rather than the one key. The gap is in ticket 29's decision text,
  which named a `HintContext` variant that does not exist for a commit's
  detail — the conductor's, not its builder's.
