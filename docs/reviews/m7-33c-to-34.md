### m3. 14b's stop sweep catches an unchecked spawn only on a fast machine (14b)
- **Judgement: the deviation is right.** The count of stop checks really does vary from run to run:
  - `wait` checks at the top of every turn (`graft-git/src/run.rs:489`).
  - Turns come from the 50 ms `recv_timeout` (`:508`) and from the 1 ms `try_wait` sleep (`:504`).
  - So the spec's "every k < N is `Err`" would be flaky.
  - The builder's invariant is the true contract, and every `k` checks it: `Err(Stopped)` exactly when some check
    answered true, and any `Ok` equals the full answer.
- **The weak part:** a second spawn given `&()` is caught only by the floor `n > 2 * CHECKS_PER_RUN`
  (`compare_and_stash.rs`, `CHECKS_PER_RUN = 4`).
  - The first spawn alone can make more than 8 checks when git is slow to start, from the 1 ms sleeps and the timer.
  - If it does, the mutant passes.
  - It is not flaky the other way: correct code always passes.
- **Fix (optional):** say this in the `CHECKS_PER_RUN` doc. Or, for a deterministic guard, add a `Stop` that records
  the check count at each spawn boundary. That needs a test hook in `run.rs`, so it is not worth doing for this alone.
