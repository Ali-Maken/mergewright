# housekeeping/02: where the heap slope's bytes per commit went, and where they go now
#
# Cause, not symptom. `jobs::radar::RadarContext.default_chain` held the
# default branch's whole first-parent chain as a `HashSet<Oid>`. An `Oid` is
# 33 bytes; a hash set of them costs ~44 B per member once the table is
# over-allocated, and the chain is as long as history. That is a direct
# breach of ADR-0026's rule that every history-sized structure holds a u32
# handle, never an `Oid` — M2's radar was written against the pre-ADR shape.
# It is now a `HandleSet` (one bit per commit) over the repository's own
# `CommitTable`, which the context holds so it can still answer about an
# `Oid`.
#
# Measured, release, by the counting allocator in prototypes/heap-slope-hk02,
# 10k cg vs 100k cg (the guard's own two fixtures):
#
#   footprint peak slope   69.9 -> 31.5 B/commit
#   live heap slope        48.4 ->  5.2 B/commit
#   the chain itself       43.3 ->  0.14 B/commit   (4,456,611 B -> 14,307 B at 100k)
#
#   4,456,448 B = 131,072 slots x 34 B (33-byte Oid + 1 control byte) for
#   78,526 chain members: the accounting matches the structure exactly.
#
# What is left of the live slope: RefBadges 2.19, CommitTable 1.93,
# RadarState::ref_findings 0.93 B/commit. The footprint peak is 26 B/commit
# above the live total: transient walk arrays and allocator-retained pages,
# the same residual ADR-0026 names.
#
# The gate: `cargo test --features heavy-tests` exits 0 (was 101 at 76
# B/commit against the 50 B bar). The bar did not move and no test was
# touched.
#
# Frame budgets: the release perf run's p50/p99 are unchanged (see the gates
# section). One run of `frames::fifty_thousand_refs_..._unicode_tier` failed
# on a single 16.3 ms frame out of 420; six interleaved A/B runs of that test
# (target/hk02-gates/ab-*.log) put the tail in both builds — before 5.4/9.8/
# 6.5 ms, after 6.5/5.8/5.3 ms — so the outlier is the max-based gate's own
# variance under load, not this change. Not a claim that the tail is
# harmless: it is a claim that this change did not cause it.
