## 2. cargo-dist (axodotdev `dist`): maintained?

- Yes. v0.33.0 released 2026-09-10/11; v0.32.0 2026-05-21; 0.33 adds Windows signing via Azure ([releases](https://github.com/axodotdev/cargo-dist/releases)). Still 0.x.
- Homebrew: set `tap = "<owner>/homebrew-tap"` and `publish-jobs = ["homebrew"]`; needs a `HOMEBREW_TAP_TOKEN` secret (PAT, `repo` scope); dist writes the formula, which installs the prebuilt archive ([dist book: homebrew](https://github.com/axodotdev/cargo-dist/blob/main/book/src/installers/homebrew.md)).
- macOS: dist **codesigns but does not notarise**. With `macos-sign` set in `workspace.metadata` (`cargo-dist/src/config/v0.rs`), it reads secrets `CODESIGN_IDENTITY`, `CODESIGN_CERTIFICATE`, `CODESIGN_CERTIFICATE_PASSWORD` (`cargo-dist/src/sign/macos.rs:174-177`). Its module doc says "In the future, this module will also support notarization" (`sign/macos.rs:21`) ([source](https://github.com/axodotdev/cargo-dist/blob/main/cargo-dist/src/sign/macos.rs)). The book's `supplychain-security/signing/` has only `windows.md`. Both were read via `gh api` on main, 2026-10-02.

## 3. Homebrew: tap vs core

- **Tap**: a Git repo, recommended name `homebrew-<x>`; formulae in `Formula/`. Users run `brew install user/repo/formula` (taps automatically). `brew update`/`upgrade` pick up new versions ([How to Create and Maintain a Tap](https://docs.brew.sh/How-to-Create-and-Maintain-a-Tap)).
- **Core**: needs a stable, immutable tagged release, SHA-256 sources, **builds from source** on Homebrew CI for macOS and Linux, a DFSG-compatible open-source licence, no bundled deps where a formula exists; self-updating software discouraged. The page names no stars/forks threshold ([Acceptable Formulae](https://docs.brew.sh/Acceptable-Formulae)). **Question**: other Homebrew docs may still set a notability bar; not checked.
- So: a tap ships prebuilt binaries the day we tag; core rebuilds from source and is a later step that needs the public final name.

## 4. macOS Gatekeeper

- Unsigned or ad-hoc-signed binaries downloaded **in a browser** get `com.apple.quarantine` and are killed or blocked on first run; `curl` does not set quarantine, so install scripts slip past. Workaround users get told: `xattr -d com.apple.quarantine <bin>`. The proper fix needs an Apple Developer ID and `notarytool` in CI. Sources (user complaints in other projects): [crgx#12](https://github.com/yfedoseev/crgx/issues/12), [vaultspec-core#336](https://github.com/nevenincs/vaultspec-core/issues/336), [lookout#1](https://github.com/millimoose/lookout/issues/1), [koan PR#548](https://github.com/radiosilence/koan/pull/548).
- **Guess**: Homebrew formula installs and `cargo install` are not quarantined (not confirmed from an Apple or Homebrew primary source).
- **Question**: whether any of the ten tools notarises. None of the configs read shows it.

## 5. Install helpers

- cargo-binstall order: `[package.metadata.binstall]` → GitHub release assets of the crate's `repository` → quickinstall → `cargo install` compile ([README](https://github.com/cargo-bins/cargo-binstall/blob/main/README.md)).
- clap_mangen renders roff from a `clap::Command`, usable in `build.rs` or a generator; subcommand man pages possible ([docs.rs](https://docs.rs/clap_mangen/latest/clap_mangen/), [discussion #3603](https://github.com/clap-rs/clap/discussions/3603)). Graft does **not** use clap: no `clap` in any `Cargo.toml` (grep, 2026-10-02). It has a hand-written parser over `env::args_os()` (`crates/graft/src/cli.rs:65`, `parse` at `:94`). So clap_mangen would mean adopting clap. The alternative is a hand-written roff page or one generated from our own `cli.rs`. Adding a dependency → check crate rules (ARCHITECTURE.md "Dependency rule").

### What users praise and complain about

- **Unsigned macOS binaries.** In helix, a studied tool: "MacOS Ventura 'cannot be opened because the developer cannot be verified'" ([helix discussion #6759](https://github.com/helix-editor/helix/discussions/6759)). The suggested fix was clearing xattrs and codesigning the grammar `.so` files (from the search summary; thread not read in full). The same complaint in other terminal tools: [alacritty#4932](https://github.com/alacritty/alacritty/issues/4932), [helm#6615](https://github.com/helm/helm/issues/6615). More in section 4.
- **`cargo install` compile time / failure.** zellij users asked for binstall support ([zellij discussion #1067](https://github.com/zellij-org/zellij/discussions/1067)). `cargo install --locked zellij` broke on a dependency compile error ([#3096](https://github.com/zellij-org/zellij/issues/3096), [#3107](https://github.com/zellij-org/zellij/issues/3107)), on "too many open files" on Debian ([#4091](https://github.com/zellij-org/zellij/issues/4091)), and built the wrong arch on M1 ([#3601](https://github.com/zellij-org/zellij/issues/3601)). Titles only, from search; bodies not read. **Question**: are compile *times* measured anywhere? Not found.
- **Tap vs core.** Users ask which to use ([getantibody/homebrew-tap#8](https://github.com/getantibody/homebrew-tap/issues/8), [Homebrew discussion #268](https://github.com/orgs/Homebrew/discussions/268)). Moving a formula from a tap into core confuses existing installs and needs `tap_migrations.json` ([Homebrew discussion #3712](https://github.com/orgs/Homebrew/discussions/3712)). A tap pinned formula is silently reinstalled from core ([brew#5796](https://github.com/Homebrew/brew/issues/5796)). Titles from search; bodies not read.
- **Missing man pages.** **Question**: no request issue found in helix, lazygit, zellij or gitui by web search. Not searched per repo with `gh`.
- **Praise.** **Question**: no primary praise source collected. The zellij "try without installing" one-liner is the only one-step path seen.

## 7. Take / reject / invent candidates for the planner

- **Take**: `brew install owner/tap/<name>` as the main Mac path, generated by dist (2 steps, matches core's count).
- **Take**: dist for tarballs + tap formula + shell installer; it is maintained (v0.33, 2026-09). Custom CI (ripgrep style) is the fallback if dist falls short.
- **Take**: man page and completions generated from the CLI definition (ripgrep `--generate`, jj `util completion`, clap_mangen), shipped in the tarball and installed by the formula.
- **Take**: `cargo install --locked` documented; `[package.metadata.binstall]` so binstall finds the release assets.
- **Reject (for now)**: homebrew-core: needs the public final name and a build-from-source formula; later.
- **Reject**: in-app update notifier. No studied tool's docs show one, and Homebrew discourages self-updating.
- **Decide**: man page source. clap_mangen means adopting clap (Graft's parser is hand-written, `crates/graft/src/cli.rs:94`). The other options are hand-written roff or generating it from `cli.rs`.
- **Question → user/conductor**: notarisation is not done by dist, which only codesigns (`sign/macos.rs:21`); it would be custom CI. Apple Developer ID notarisation (costs a paid account) vs documenting "use brew or the curl installer; browser downloads are blocked". Hard to reverse → ADR.
- **Question**: which crate in the workspace is the published binary crate, and the crates.io name. The name is open until M8 picks it. Nothing gets registered under "Graft".
- **Invent**: none needed so far.
