Twenty branches can't each get a colour, so only three do

Your screenshot has about ten lines in ten colours, and nothing tells you which one matters. In this version a line's colour says how it relates to the row you're on, not which branch it is. Click the terminal and move with j / k. Watch the colours move with you. space on a merge row shows the commits folded into it, # turns colour off.

From Sublime Merge and others

Taken: merges folded by default

Sublime Merge shows only the main line and opens a merge on click (build 1070). Fork does the same and pitches it as its fix for clutter (Fork blog). Here: space on a merge row.

Changed: label colour matches its line

Sublime Merge colours lanes from a rotating palette and labels by kind, and users read the two as not matching (forum). Here the branch name is always the colour of its own line.

Changed: your route lights up

Sublime Merge can hide branches, but it doesn't highlight the selected commit's history. Users have asked for that (#2009). GitKraken and GitLens dim the unrelated branches. Here that happens on every cursor move, with no click and nothing hidden.

Changed: names on one line

Sublime Merge puts the full author name on a second line, and users say it wastes height (#18, #692). lazygit's initials cut three-part names to two letters (#5670). Here: the first name in its own column, and your own rows in bold, as JetBrains does (docs).

Ours: only lanes with something on screen

A branch gets a lane only while it has a commit in view. The header says how many lanes are drawn out of how many exist, so the count stays small while you scroll.

How the screen reads

Colour means a role

┃ the branch you're on, │ what it was built on, ║ development. Every other branch is a ┊ grey dotted line. Move the cursor onto a teammate's branch and it becomes the green one. Three colours are enough for any number of branches.

Finished branches fold away

A branch that's already merged is one row: ◉ Merged PR 16021 · +4 from sara/fix-toc. That removes most of the lines in your screenshot. space opens it when you want to look inside.

Every row says its branch

A branch column names the branch for each row, written once where it changes. You don't have to trace a line back up to a label.

Your branch and its remote are one thing

Your screenshot shows both wallet-release and origin/wallet-release as separate labels. Here it's one name with ↑1 to push.

This is a mock with a made-up repo shaped like yours: a development trunk, an integration branch, your branch on top, teammates' branches beside it. A real terminal may draw the colours differently from this page; the line shapes (┃ │ ║ ┊) carry the same roles without colour.
