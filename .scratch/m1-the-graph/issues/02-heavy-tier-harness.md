# m1-the-graph/02 — Heavy tier, the 100k fixture, `git/git`, and TESTING.md

Status: ready
Build with: Opus
Blocked by: 01

Why: M1 is the first milestone with anything worth measuring, and KNOWN_GAPS.md says plainly that "gates green" currently means the fast tier only — no performance or memory budget in the spec has ever been measured. Ticket 16 cannot exist without this harness, and the M1 checkpoint needs `git/git` on disk.

## Read first
- PROMPT.md §7.1 (tier table, the `heavy-tests` feature, the 300 MB peak-memory gate) and §7.2 (the corpus table, the manual checklist in item 7)
- KNOWN_GAPS.md, "Only the fast test tier exists"
- Ticket 01's generator — this extends it, it does not fork it

## Goal
`cargo test --features heavy-tests -- --ignored --test-threads=2` is a real, documented tier with real fixtures behind it, and `TESTING.md` exists with the manual checklist M1 will fill in.

## Scope
In:
- The `heavy-tests` feature and the `#[ignore]` convention, wired so the fast tier never picks a heavy test up by accident (prove it: fast-tier run shows 0 ignored-and-run).
- The 100k-commit synthetic repo, generated by `fast-import` with a **size parameter**, cached in `target/fixtures/`. Generation itself is heavy-tier only.
- A `getrusage`-based peak-memory helper the budget tests will use, tested on its own.
- A script (not a test) that clones `git/git` with `--filter=tree:0` into a cache dir, run by hand, never by a test, never automatically. Document the disk cost and how to delete it.
- `TESTING.md`: the three tiers and their commands, how to build fixtures, how to get `git/git`, and the skeleton of PROMPT.md §7.2 item 7's manual terminal checklist (pixel terminals, Unicode terminals, tmux, SSH) with the pass conditions written out. Tickets 08/11/14 fill in their rows.
- `proptest` cases: 64 fast, 1000 heavy, via `PROPTEST_CASES`.
- README/CHANGELOG note that the heavy tier exists and what it costs.

Out:
- The budget assertions themselves (ticket 16) — this ticket builds the harness, not the gates.
- CI (PROMPT.md §7 item 6 is conditional on a GitHub repo; there is none).
- `cargo-fuzz` targets — M2 parsers, not M1.

## Acceptance
- [ ] `cargo test --features heavy-tests --no-run` compiles; the fast tier is unchanged in count and runtime.
- [ ] The generator is verified end to end at a **reduced** size (a few thousand commits) inside this session, and the 100k run is left to the milestone review — say exactly which size you ran and what it cost in time and disk. Never claim the 100k run you did not do.
- [ ] The peak-memory helper is asserted against a known allocation in a unit test.
- [ ] The `git/git` clone script is run once by hand (or explicitly not run, with the reason); record commit count and disk size if run.
- [ ] `TESTING.md` exists and a human can follow it without reading any other file.
