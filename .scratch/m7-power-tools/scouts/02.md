# Scout 02 — rewrite-engine (HEAD 942c0a5a)

## 1. Rebase plan, recording, touches/tips
- `plan_rebase` `crates/graft-ops/src/operation/history.rs:620-628`: `rebase [--no-update-refs --no-autostash] <onto>`. The flags are added only when `git >= GitVersion::MINIMUM` (2.38). There is no `-i` and no `-c`. The doc comment at :613 says M7 "opts back in" to updateRefs. ADR-0047 does the opposite (`-c rebase.updateRefs=false`, own `update-ref` lines).
- `RebaseParams { branch: Tip, onto: Source, onto_tip: Oid }` `history.rs:86-93`. No `line` and no `drops` yet.
- `touches` for Rebase: `operation.rs:1254-1258`. Refs are `head_ref_name(HEAD)` plus `refs/stash` if set aside; index and worktree are `true`. `tips` returns `[params.branch]` (`operation.rs:935`). `facts_scope` returns `refs_of_rebase`, i.e. branch + onto ref (`history.rs:345-349`).
- `refs_before` = `read_refs(touches.refs)` at open (`apply/record.rs:82`). `refs_after` is filled at close (`record.rs:215`). Only HEAD's branch is recorded today.

## 2. resume

- `ContinueWith` builds `commit -F -` (merge only, `resume.rs:204-212`).

## Mismatches
- `OperationKind` is defined in **graft-core** (`crates/graft-core/src/journal.rs:32`, serde snake_case), not graft-ops. `OperationKind::Rewrite` needs a graft-core edit, and the ticket's crate set is "graft-ops only".
- The `history.rs:613` comment says M7 re-enables updateRefs. ADR-0047 disables it.
- `history_ops.rs:567-600` asserts the old one-ref recording. It must be inverted, not merely kept green.
- Resume passes no `-c rebase.updateRefs=false` (`resume.rs:220-222`). Could not confirm whether git rereads that setting on `--continue`.
