## The two disk checks
- `preview/stash.rs:345 occupied(repo, paths) -> Result<Vec<PathBuf>, PreviewError>`: pure disk test of given paths.
- `preview/recover.rs:90 in_the_way(repo, &RecoverParams, facts, stop) -> Result<Vec<PathBuf>, FactsError>`: computes
  paths (`tree_diff(expected,to)` + status-untracked held in `to`), drops `tracked_paths_now`, then the same
  `symlink_metadata` loop as `occupied` (NotFound skip, NotADirectory counts). Its doc (`:83-84`) says "The stash
  preview's `occupied` is the same rule." The disk loop is duplicated; the path-set and error types differ
  (`PreviewError` vs `FactsError`). Recover-only via `let … else` at `:96`.
- Note: `in_the_way`'s untracked half reads `facts.status` untracked (`:109-115`), so an ignored file only enters via `tree_diff`.

## Backup
`snapshot::worktree_tree` `snapshot.rs:198-206`: copies index, `add_all` (`git --literal-pathspecs add -A`,
`snapshot/plumbing.rs:204-217`), `write-tree`. `add -A` honours ignore rules, so **ignored files are not in the backup**
(standard git behaviour; not separately probed here). Set-aside `stash create` (`apply/set_aside.rs:68-72`) takes
tracked changes only, no `-u`.

- Ticket's list says "pull ff": pull is `merge --ff-only` (`remote.rs:281-286`); covered above as exposed.
- Ticket: "refusal the operation already gives for an untracked file in the way": only Recover and Stash apply have one.
  Checkout, Merge, Pull, Rebase, Rewrite, CherryPick, Revert, Reset-hard, BranchCreate have **none** → per ticket, `blocked: needs wording` for those.
- Stash apply is safe by git (probe), but its `y` guard is status-only; `occupied` is preview-only.
