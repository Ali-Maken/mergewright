## What the loop does today with queued input
- `frames` (`crates/graft/src/event_loop/running.rs:91-174`): draw first (`:108`); per turn: `prefetch` asks `waiting()` (`:115`), `next_wake` (`:116`), `graphics.drain` (`:123`), `Terminal`/`Shutdown`/failures handled before `update` (`:126-144`), `update` (`:148`), `carry_out` (`:152`), quit check returns **before drawing** (`:155-161`).
- Batch rule `:163-169`: only when the wake *just handled* was a job (`from_a_job`, `said_by_a_job` `:146`), `began.elapsed() < BATCH_BUDGET` (8 ms, `:88`) and `job_event_waiting()` → `continue` without drawing. A key always draws (`:170`). A queued key behind a key = one frame each.
- `undrawn_since` (`:111`, `:147`) is the existing budget clock; reset at `:140`, `:171`.
- `carry_out` (`:184-230`): handovers are the six commands at `:212-217` (incl. `EditCommitMessage`, `OpenExternalEditor`, `OpenConflictEditor` — spec lists four kinds). It returns only `AppState`; **nothing tells `frames` a handover happened** — the build must add that signal.
