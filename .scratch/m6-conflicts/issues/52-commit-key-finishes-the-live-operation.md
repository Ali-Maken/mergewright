## Scope
**In:**
- **`c` in the graph or the changes pane, while `live_operation(state)` is `Some`:** call the banner's `c` handler.
  Same function, same refusals, same landings: one path, so the two cannot drift.
  - A merge (begun in Graft or in the shell) → the finish summary. `Esc` from it → the banner, focused
    (`ReturnTo::Banner`).
  - A rebase, cherry-pick or revert begun in Graft → continue, as the banner does.
  - Files still unmerged → the banner's refusal words.
  - A shell-begun non-merge, or a bisect → M3a's pane words (the banner's `c` refuses these too).
- **`a` is unchanged:** it refuses in words (M3a) and never aborts.
- **The graph and changes-pane bars, while an operation is live,** label `c` by what it does: `c finish` for a merge,
  `c continue` for the others. A kind where `c` refuses shows no `c` label.

**Out:**
- The summary's confirm key (`finish-summary-is-a-preview`).
- The banner's own keys.
- A `ReturnTo::Pane` variant. `Esc` goes to the banner, the operation's home. If the builder finds `ReturnTo::Banner`
  wrong from a pane (for example, the banner is not drawn), stop and report it.
