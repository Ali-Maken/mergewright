## Scope

In, in order (a commit per piece):

1. **State and jobs** — `AppState::resolver: Option<ResolverState>`; `GraphOverlay::Resolver` (drawn over graph and pane; header kept; `text_field_open()`/`graph_has_focus()` answer as for `Map`). `Command::OpenConflict(JobId, PathBuf)` → job calls `open_conflict` against the latest `WorkingTreeStatus` → `Product::ConflictOpened(Result<Arc<Opened>, String>)`. `Command::TakeSide(JobId, TakeRequest)` → `apply_take` → `Product::Taken(Result<Arc<ConflictFile>, String>)`. Errors carry `graft_ops`' words (`OpenError`/`TakeError` `Display`), never `{:?}`.
2. **Opening** — `open_resolver(state, commands, path, from, next_id)`: refuses in words when `state.resolver` is `Some` (never two), when a confirm box or the commit editor is open (`finish the box first`), when a job is busy on that path; else sets `ResolverState { path, opened_from, doc: Loading, .. }` and pushes `OpenConflict`. Bound to `⏎`: in `detail/keys.rs` on a `CONFLICTS` row (`from: Pane`); in `banner_key` on the focused banner (`from: Banner`, path = `first_conflicted(state)`), both **only after the keymap names them**. `ConflictOpened(Ok)`: `file = opened.file`, `cursor_block` = first open block (or `None`), `top = 0`; the notice for the empty states (`no conflict markers · ⏎ marks it resolved`; `too large to show (9 MB) · e edit  M mergetool`; binary/whole-file → G5 — here they show the file card **without** `o`/`t` acting: `Status::Sticky("deleted by them · o/t come with the next build")` is **not** acceptable; instead this group's `open_resolver` refuses `binary and whole-file conflicts: M mergetool  e edit` for `file: None` until G5 lands — in words, no dead screen). `ConflictOpened(Err)` → `resolver = None`, `Status::Sticky { reason: <words>, keys: Some("e edit  M mergetool") }`.
3. **`resolver_key`** — chain position: right after `preview_key`, before `banner_key`; modal: claims every key but `Ctrl+C` while `state.resolver.is_some()`. `o`/`t`/`b` → `TakeSide { path, expected: file.fingerprint, block: cursor_block, take }` (refused in words when `cursor_block` is `None`: `no conflict under the cursor · n next`); `Taken(Ok(file))` → replace `file`, keep `cursor_block`, **scroll so the block's header is in view** (`layout.block_row[block]` vs `top`/height), `Status::Done("took ours in <path> · 2 of 3 open")`; `Taken(Err)` → notice `(words, true)`; a `Changed` error → also re-push `OpenConflict` (re-read; the notice reads `<file> changed on disk · re-read`). `n`/`N` → next/previous **open** block; past the last open block of this file → the next conflicted file in `unmerged_paths(state)` order (closes and reopens with `from` kept), at the very end `Status::Sticky("no more conflicts · ⏎ marks <file> resolved")`. `⏎` → `mark_resolved_refusal` first (`2 conflicts still open in <path> · n next`, no job), else `Operation::Stage(Target::Paths([path]))` via the existing `operate` path; on the `Operated::Done` for it: advance to the next conflicted file, or — none left — close to `opened_from` with `Status::Done("all conflicts resolved · c continue")` when a banner shows, `("all conflicts resolved")` otherwise (row 229's stash pop). `e` → `OpenExternalEditor { path, line: blocks()[cursor].first_line }`; `M` → `OpenMergetool { path }` (its `None`-mergetool refusal reused); after `Product::HandedOver` the resolver pushes `OpenConflict` for its path again (the file may be resolved or gone from unmerged: `NotUnmerged` → close to `opened_from` with `Status::Done("<path> resolved outside · ⏎ …")`). `j k ↑ ↓ PgUp PgDn g G` scroll `top` within `layout.rows.len() − height`; `Esc` → `resolver = None`, focus back to `opened_from` (banner focus restored when `Banner`). `Tab` → swallowed (modal). Every other key swallowed.

## NOTES

**Scout.** Used, and all three facts held. (1) `cursor_conflict` is in `banner.rs`, not `detail/keys.rs` — `detail/keys.rs`'s new `⏎` arm calls it there. (2) `⏎` on the banner was unbound (the catch-all swallowed it), so nothing was displaced; on detail rows all three existing meanings survive because the new arm falls through on a non-conflicted row — `enter_elsewhere_unchanged`. (3) The `e`/`M` asymmetry was real and is **closed for the resolver's path**: `Product::HandedOver` and the mergetool's answer both call `resolver::handed_back`, which pushes `OpenConflict` *and* `ReadWorkingTree`. Outside the resolver the asymmetry is untouched.

**Where `⏎` is bound.** Three places: `update::detail::keys::open_the_resolver` (a `CONFLICTS` row, `from: Pane`), `update::banner::banner_key` (the focused banner, `from: Banner`), and inside the resolver itself (`update::resolver::act` → mark resolved). `resolver_key` sits in the chain between `boxes_key` and `banner_key`.

**The two decisions the dispatch asked for.**

1. **The banner stays.** `GraphOverlay::Resolver` does *not* suppress the operation banner: `view::frame::draw_resolver` draws it on row 0 and gives the resolver everything below. Mid-rebase, `REBASING step 3 of 7` is the one line on screen that says which side `ours` is — losing it exactly where the user is choosing between the two sides would be the worst possible moment. `update::resolver::banner_rows` is the single answer, used by the geometry and the drawing alike.
2. **The resolver swallows the mouse.** `resolver_mouse` runs first in `mouse_event` and always answers `true`. **For the conductor to file:** the other three overlays do *not* do this — `update::mouse::left_click` calls `geometry::graph_row_at` with no `graph_overlay()` check at all, so a click over the Map, the journal or the stash list selects a row of the graph behind them (`docs/reviews/m5-10-30-31.md:291-296`). Untouched here, by instruction; the comment in `update::mouse` names it.

**Deviations from the ticket's signatures**, each deliberate:

- `ResolverState` has no `doc: Loading<…>` and no `layout` cache. `file: Option<Arc<ConflictFile>>` is the whole document state (`job: Option<JobId>` says a read is in flight), and the layout is recomputed per frame by `view::resolver::resolver_layout`. A cache on `ResolverState` would sit inside a struct that derives `PartialEq`/`Eq` and is compared whole by the hint sweeps. **Risk:** one `layout()` per frame over a very large conflicted file. Not measured — if a perf run finds it, the cache belongs in `view`, keyed by `(fingerprint, columns, base_shown)`.
- `Product::ConflictOpened`/`Taken` carry no `JobId` of their own (the event already carries one, like every other product), and their errors are **typed** (`jobs::conflict::{OpenFailure, TakeFailure}`) rather than `String`: `not_unmerged` and `reread` decide control flow, and deciding it by matching on a sentence is how wording changes become behaviour changes.

**M2 — `⏎` and a block take in flight together on one file. Reproduced, fixed at the cause.**

- **Reproduced** (update level, red before the fix): `t` over a taken block then `⏎` queued `TakeSide` + `Operate(Stage)`; `⏎` then `t` queued `Operate(Stage)` + `TakeSide`. The pool shares one queue across several workers (`jobs/runner.rs:128-138`), so the two run concurrently. The on-disk interleaving itself was not observed — only that both writes were queued at once.
- **Cause:** two write channels (fs take via `open.job`; git write via `state.operating`) with each key checking only one. **Fix:** one gate, `write_refusal` (`update/resolver.rs`), asked by every writing key — block take (`take.rs`), `⏎` (`mark_resolved`), whole-file `o`/`t` (`whole_file.rs`), `d` (`restart.rs`). Refuses with the busy words of a take/read, else `a write is already running`.
- **Tests:** `update::resolver::tests::enter_waits_for_a_take_in_flight`, `update::resolver::tests::a_take_waits_for_the_stage_in_flight` — both seen red, now green.
- **Cost to the user:** a key pressed during a write is refused in words (sticky line) and must be pressed again once the write lands. Side effects of the single gate: a whole-file `o`/`t` during a re-read now says `still reading the file` (before: launched); `d` on a card while a write runs now says `a write is already running` rather than the not-a-marker-shape refusal.
